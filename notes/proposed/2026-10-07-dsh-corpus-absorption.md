# DSH 开发语料吸收：动态闭环三环补齐 + 驾驭者成本面瘦身

日期：2026-10-07 · 状态：**proposed**

> 承接自[调研卡](../../_backlog/_done/_closed_plans/261007-dsh-corpus-absorption-audit.md)（2026-10-07 用户点名审计，当日收卷）。
> 完整证据与逐机制对照表 = [收卷台账](../archived/research/2026-10-07-dsh-corpus-absorption-audit.md)（三卷 230+ 条机制 × 本仓六态对照、四症状 × 八根因归因、一处子代理误读的亲验纠正）；本卡只携带问题、方案与验收。

## 问题（可观察行为）

用户（驾驭者）2026-10-07 原话症状：**「每次驱动一下能干点，但质量成问题，没感觉质量有很好的保障，流程上也有问题，测试资产也不知道在哪儿……驾驭感觉很糟糕。」**

审计结论（台账 §五）：本仓对 DSH 流程的**静态结构与机械层吸收极深**——语料自检三问全 PASS、五条优先迁移原则次序不倒挂、230+ 条对照机制中整条漏吸仅 2 条小项。「没吃透」的真身是**动态闭环三环断裂 + 驾驭者视角缺位**：

| 断裂环 | 可观察行为 | 语料对应 |
|---|---|---|
| 意图定义环 | proposed/ 空、~90 张 implemented 两周直落——开工不写「触发/用户看到什么/完成条件」，完成判断无可对齐物，用户沦为点火器而非方向盘 | 闭环第 1 步「外部结果先行」 |
| 行为证据环 | 模型可见面（=产品核心面）的回归固定靠 spec + 手动 probe；eval 无路由强制（10 月 note 16/34 提及）；session 回放触发未到——「质量没保障」的行为层实体 | recorded-session 义务的适配声明缺口 |
| 交付签收环 | 机械绿 ≠ 交付批准，但每切片的「行为 vs 意图对齐签收」无稳定动作（语义评审是事件型：阶段收尾） | 闭环第 7 步「语义评审完成交付判断」 |
| 驾驭者可见性 | 证据阶梯知识散在 testing.md + pre-push-evidence + snapshots 三载体，agent 3–4 跳、用户不可见——「测试资产不知道在哪」 | 五缺口框架第 5 问的入口成本 |
| 流程自重 | 仓在自身上的战役占比高；外置知识维护成本无「驾驭者认知成本」判据（语料四成本形态之外的本仓第五形态） | 07 页成本意识 |

## 提案

分两批交付，批内逐片；**A 批补漏（五件）、B 批瘦身（一件审计）、C 随手登记不借项**。每片独立提交锚点。

### A 批：动态闭环三环 + 地图（补漏）

1. **A1 外部结果先行成轮内纪律**（意图定义环）：根 AGENTS.md「新会话开工」节加一条 standing order——非机械的轮内任务，开工先落**外部结果三要素**（触发条件 / 用户看到或得到什么 / 完成条件），载体 = plan 呈批或切片卡首节；实现不先于意图定义。机械/局部编辑豁免（与 note 义务豁免同口径）。
2. **A2 模型可见面证据路由硬化**（行为证据环）：`pre-push-evidence` 技能「model-visible surface」行追加 `pnpm eval --only` 为最小路径必项；`docs/testing.md` 已定姿态节补一句适配声明（语料 B11/B12 的义务）：「模型可见面的回归 = agent 面合同 spec + eval 判决；repo-live-probe 是**取证动作不是回归资产**；session 回放维持触发条件制（触发未到，不预建）」。
3. **A3 证据地图单页化**（可见性）：`docs/testing.md` 增「一页证据地图」节：改动面 → 最小证据命令 → 回归资产的家 → 能证明/不能证明（内容合并自现分层表与 skill 逐面表，**testing.md 拥有表，skill 与 README「按问题找」改为链接**——一个事实一个家，消灭三载体分散）；验收含新上下文走查「改什么→跑什么→资产在哪」≤2 跳（复用 P5 验收法）。
4. **A4 交付签收轻量行**（签收环）：`notes/README.md` §二之二 proposed/implemented 卡骨架补一行「**行为对齐**：外部结果 = …；签收 = 用户真机走查 / eval 判决 / 新上下文评审（记其一）+ 未跑项」——把语料 B17「未执行的检查」栏与 B16 语义评审显性化；**不设机械门禁**（格式门只证结构不证决定正确——sdlc 01 §4；阶段收尾语义审计轮抽查）。
5. **A5 小补三件**：① 环境特异性三件记录（exact command + failing test + 平台差异后才可声称环境特异）→ `pre-push-evidence` 规则节一条；② 负例接线断言（语料 verify.test.mjs 形态：verify-gates.spec 增「`pnpm verify` 顶层实际调用 verify-checks 每个导出」+ 诊断文本断言，prove-it-red 夹具同 diff）；③ TODO 政策偏离登记（DSH 三档 TODO vs 本仓「不立项只在代码内」→ `docs/discipline.md`「已声明的适配」加一行：约束→适配→证据）。

### B 批：流程总预算审计（瘦身，一件）

**B1**：把 2026-10-06 的门禁预算制扩展到 standing instructions / docs / skills 三面，新增语料没有的第四判据「**驾驭者认知成本**」。预列审计对象（台账 §4.3）：根 AGENTS 155 行的常设指令密度、pre-push-evidence「每切片全地板」与窄证据的张力（语料条 35「不重复未失效的检查」）、5 技能五要素齐度（停止条件/验证报告）、入口链总跳数。产出 = 处置表（删>并>修>记，每行指向具体摩擦或误导），走 SDLC closeout 同款程序（退役四件套同构：原防护风险/曾坏证据/消费者核对/替代防护）。

### C：不借项登记（负知识）

随 A 批同 diff 在 `docs/discipline.md` 或其 ⏸/不借表登记：CI 矩阵/stacked PR/加权批准/Issue-PR policy（主仓治理，语料明示不自动适用）；双语 pairing（本仓语言分工非对称）；archived hash manifest（本地单人仓无对抗面）；registry 三态幂等（触发 = export-dist 同版本内容变的实证）。

## 输掉的方案

1. **全盘照搬语料形态**（含 CI、pairing、hash manifest）——输给语料自己的适用边界声明（native A2/C6、repo-harness #49）与本仓无协作面/无对抗面的现实；静态层三问全 PASS 证明不需要结构级补课。
2. **把行为签收做成机械门禁**——输给语料「格式 gate 只证结构不证决定正确」（sdlc 01 §4）；硬门禁会逼出凑节仪式，签收本质是语义判断。
3. **立即建 session 回放**——输给触发条件制（既有裁决：不过度为想象的未来预建）；语料 B12 允许适配但要求声明替代证据——A2 的补句就是声明。
4. **一次性大瘦身（直接删文档/并技能）**——输给本仓处置纪律（每处改动指向具体误导或漏检）；瘦身走审计程序（B1），不是斧头。
5. **把 eval 全量化**——输给窄证据原则（语料条 35）；A2 只把 eval --only 聚焦跑加进模型可见面的最小路径，全量仍留给阶段收尾。
