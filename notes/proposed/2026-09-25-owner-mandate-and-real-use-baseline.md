## 一、定位（用户 2026-09-25 确认）

**我是这个产品对着 [`notes/intents.md`](../intents.md) 的长期责任人，不是一个回合的交付者。**

| 维度 | 被否定的形态（我前四轮） | 确认的形态 |
|---|---|---|
| 目标 | 交付物（有终点） | 职责（有方向、有度量） |

## 二、圈纪律（每圈四步，缺一不算交圈）

1. **测差距**：举一个 intent 级差距（不是"某门禁没绿"）。
2. **切片**：一个垂直切片（代码 + 测试 + docs/README + note 同 diff）。
3. **更新队列**：完成的离队；新暴露的进 ROADMAP（带触发条件或 ▶）；延后必须有归宿（门禁 `deferral homes` 管）。
4. **摆下一圈**：把下一圈候选写到本卡或 ROADMAP，不留"以后有空再说"。

## 四、第一圈：真实使用代理基线（用户已授权）

**任务集**（五个，覆盖"用自己"与"通用性"两端；每个用 preset-runner 真跑，不设合成约束）：

1. **连续性**：跨会话问它自家决定（"我们为什么用 working folder 这个词，谁拍的板"）——应走记忆/知识，不重读仓库。
2. **领域活**：本仓研发域的真实小活（如"给 curate 加一条 finding 该怎么下手"）——测它能否用自己房间的知识页开工。
3. **判断**：一个需要取舍的问题（如 Obsidian 里点名字链接打不开该怎么办）——测 research 线索与知识页的使用。
4. **养护**：让它自己判断"家里现在该收拾什么"——测 curate 的主动性与处置质量。
5. **通用性（反面测试）**：一个非开发类任务（如把一段会议记录整理成"决定/待办/待确认"）——预期暴露"它目前只是研发域助手"。

**每会话记录**：任务、工具调用序列、是否引用自家房间、答案是否可用、摩擦点、失败点。
**产出**：本圈结束时写入一份可用性基线报告（notes/research/archive/，含失败案例原文）+
新暴露的差距进 ROADMAP + 第一圈切片（把基线里最容易的 1–2 个真痛点修掉）。

## 五、输掉的方案（防重新开讼）

- **继续按交付物开会话**（"把这批做完就结束"）：正是被否定的形态；每轮都绿、产品不前进。
- **只做合成探针（我出题我打分）**：探针能抓机制 bug（digest 冷启动就是这么抓到的），
  但抓不到"用户真正会遇到的摩擦"——所以第一圈用**真实任务**跑，探针退居回归工具。
- **先加更多机制再谈使用**（继续 owner 文件/门禁/目录）：最近四轮已经证明这条路会让我把
  "工具的整洁"当成"产品更聪明"；机制只在被真实摩擦驱动时才加。
- **把 goal 标 complete**：职责式目标没有 complete；只有交圈、用户 steer、或连续三圈同一阻断。

## 九、第四圈：desktop 分级降级（永不静默）（2026-09-25）

- **测的差距**：第三圈 live 探针带回的真信号——digest 4056/4096（内存段 2343B 占 58%，知识树 1419B）。
  量化后发现真正的结构缺口不是"预算小"，而是**爆掉时的降级方式**：渲染器只是停止 push，
  **尾部整页静默消失**（desktop 会悄悄藏东西，违反"知道自己有什么"）。
- **切片**：`src/home/digest.ts` 改为分级降级——①先去知识树的描述提示（**每页仍在树上有名有 id**）
  ②仍不够就停止列条目并追加显式省略标记（`+N more … omitted — digest budget`）
  ③**状态栏（地图）永不被驱逐**：空间连标记都放不下时丢标记、不丢地图（既有测试 `keeps the map …`
  当场抓住了我第一版把地图挤掉的实现）。新增 4 个夹具（压缩树/标记/地图优先/确定性），196 tests 全绿。
- **live 证据（真会话 + 临时降预算补丁）**：会话日志的 system prompt 原文里，
  知识段是压缩形态（5 页名+id、无描述），其后是两行省略标记——读者能明确知道还有 5 条记录与 5 页没显示。
- **合同**：`docs/home.md` 写下降级顺序与"desktop 可以变短，但不许谎报完整"。
- **方法学副产物**（已进开发技能 `repo-live-probe`）：会话事件的字段路径不一致（`system/message`
  是 `data.message.content`、`user/message` 是 `data.content`）——**先列事件类型再取字段**；
  探针 patch 必须镜像被替换的 patch（漏掉 `headless-runner: disabled` 会在答对之后于退出阶段报错）。
- **本圈不改的**：内存段 2343B 的内容级瘦身（合并/下沉记忆）——降级已经优雅，它从"到期必须做"降为
  "想做再做"，触发条件=真实使用中确实感到摘要偏薄（条目在 ROADMAP）。

## 十一、第六圈：技能使用面——账本覆盖窗口（2026-09-25）

- **测的差距**：意图里"从不被加载的技能是每次请求都在付的目录税"。用仪表能力（日志解析）做交叉核对，
  结果先**推翻了我的假设**：6 件策展技能里 **5 件真被加载过**（self-reflection 7、memory-hygiene 7、
  home-curation 6、research-backlog 5、knowledge-craft 3），只有 `session-recall` 是 0。
- **差点犯的错**：日志显示 `research-backlog` 5 次而账本 0 次，我一度判定"账本系统性少记 → 会误荐退役"。
  按**账本纪元**（09-24T17:03Z）分桶后真相是：那 5 次全发生在账本存在之前，纪元后每一笔都对得上
  （1/1、3/3、2/2、1/1、4/4）。**账本没错，是我的读法错了**——这是本圈真正的产出。
- **真问题与切片**：账本的**覆盖窗口对读者不可见**——`0 次`会被读成"从未使用"，足以诱发退役一个在用的技能
  （`campaign-evidence-recording` 账本 0、日志 2，都在纪元前）。修：①账本文件记 `since`；
  ②旧账本无该字段时按**最早一次加载**推导下界（推导而非编造）；③`curate` 的 skill usage 行带窗口
  （`since YYYY-MM-DD` / `ledger window unknown`）；④`docs/home.md` 写进合同。
- **live 证据**：真实会话里模型读到 `- skill usage (since 2026-09-24): campaign-evidence-recording not loaded,
  repo-to-knowledge×1 (0d ago).`——并且**它自己就用对了**：明确说"尚无退化判定，因为窗口未知，未到报废线，我没动手"。
  （第一次 live 跑出的是 `ledger window unknown`，因为 `index.ts` 那处接线我的替换没匹配上、静默成了空操作——
  已加断言修正；这正是"live 验证抓替换空转"的价值。）
- **下一圈候选**：①`session-recall` 的触发面（两个窗口都 0；判招牌还是描述没接上）②自用率分母的会话归属
  ③真实使用开跑（等你本人）。
