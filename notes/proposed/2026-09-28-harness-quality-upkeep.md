# harness 质量维持：合同面自生成最小扩面 + 审计轮制度化 + 产品面证据刷新

日期：2026-09-28 · 状态：**proposed**（用户 2026-09-28 指示立卡；轨 A 为解冻请求，轨 B 建议随 A 同判，轨 C 不涉冻结）

> 证据链：[十维自评（借 DSH 借鉴 FAQ 尺子，含第四轮漂移审计）](../research/2026-09-28-harness-ten-dim-self-assessment.md)。
> 本卡只装**接下来**的决定与验收；已完成的事实（19 处漂移明细、十维打分）在证据链，不在此复制。

## 问题（可观察行为）

1. **散文合同面跟不上交付**——四轮语义漂移审计累计 19 处，本轮 6 处中 3 处同根：client 座位面
   长了一圈，`docs/architecture.md` / `docs/identity.md` 的散文清单没跟上（「不做 client」已死、
   浏览器面行变短、已退役 slot 残留）。机器门禁 32/32 绿的同时散文烂了：**这类事实没有机械钉定面**。
2. **唯一抓得住这类漂移的探针靠「记得」**——审计轮三轮间隔（09-23 / 09-27 / 09-28）全是人为时机，
   无常设触发；漏跑一轮，漂移就活在入口链里喂给下一个会话。
3. **产品面待裁决项缺新鲜数据**——摘要触顶（4,011/4,096）是 2026-09-27 读数；2026-09-28 估算：
   活跃记忆 5 条、记忆段渲染 ≈2.4KB（仍占预算 ~60%）、全摘要 ≈3.6–3.9KB **仍贴顶**
   （口径：memory/*.md 去 frontmatter 字节数 + 稳定知识页与开放线索行数）——压力未解，但精确
   读数缺一次真机刷新。
4. **usage 报告出现 error×7 结束轮**，尚无按 desk-loop 口径的归因分解（产品缺陷 / 传输瞬时 / 评测人造）。

## 提案（三轨，分轨验收）

### 轨 A · 合同面自生成最小扩面（**解冻请求**，需拍板）

把 **client 座位面**（品牌 slot、三室 tab 定义 + guide 条目、每室 keyed 座位
`sidebar.right.pane.tab` / `tab.title`、会话面三座位、房间命令）从散文改为 `gen-catalog`
生成节，进 `docs/package-catalog.md`，吃既有 freshness 门禁；`architecture.md` §二/§三与
`identity.md` §一第 8 行的对应清单改为指针。

- **为什么值得解冻**：复查环处置优先序「删 > 并 > 修 > 记」——生成即「删散文、并进生成物」，
  方向与冻结要防的门禁膨胀相反（净减一处散文源，增一个生成节）；本轮 3/6 漂移同根，
  四轮曲线预测该类继续发生。
- **成本**：生成器扩面一个切片（client 源码的 slot 注册可静态扫出）+ 红绿夹具
  （新门禁必带反例：改 client 注册不重跑生成 → 红）+ 两文档改指针。

### 轨 B · 审计轮制度化（不新增机器件，建议随 A 同判）

`ROADMAP.md` 维护规则加一行：**战役/阶段收尾必跑 `semantic-drift-audit` 一轮，发现即切片**。
零机器成本，把四轮实证（0/6/7/6）变成常设触发。诚实呈现张力：用户拍板过「不加 pre-push hook，
不让流程再长一层」——本轨加的是**一行工作规则**不是机器件，是否越线由用户判。

### 轨 C · 产品面证据刷新（不涉冻结，可独立执行）

1. **摘要压力精确化**：真机桌面刷新取 digest 精确字节 → 回写 ROADMAP ⏳ 条目备判（估算与口径见
   问题 3）；**裁决权不变**，选项仍是退役/压缩一条、授权自选、调大 `digestMaxBytes`。
2. **error×7 归因**：按 desk-loop 的日志结构口径扫 error 结束轮，产出分类计数；有产品侧成分
   才立摩擦卡，否则记录并关闭。
3. **vendor pin 新鲜度**：对照上游 tag 复查是否 `pnpm sync-dsh`（既有工作流，非新机制）；
   升或不升各记一行理由。

## 输掉的方案

- **维持现状（纯审计轮兜底，A/B 都不做）**：本轮证明探针抓得住，但同类漂移四轮三现，成本在
  每次靠人记得；若用户否决 A+B，本卡转 `rejected/` 并以此为一行原因。
- **新增独立 verify 检查**（校验「docs 提及的 slot 名都在代码里」）：同为新增门禁、冻结成本与
  轨 A 相同，但保留散文介质（少删一处）——按「删 > 并」输给生成方案。
- **只做轨 C**：产品面数据会更新，但 dev 面最高发漂移类的根因（散文介质无常设时机）不动，
  漂移曲线预测不变。

## 验收

- **A**：`pnpm gen-catalog` 产出 client 座位节；`architecture.md` / `identity.md` 对应行成指针；
  freshness 红绿夹具各一（造红：改 client 注册不重跑生成 → verify 红）；该面的「行清单变短」类
  从根因上不可能复发。
- **B**：`ROADMAP.md` 维护规则多一行；下一次战役收尾的 note 里出现审计轮记录（跑没跑、发现几处）。
- **C**：ROADMAP 摘要条目有精确读数；error×7 有归因分类；pin 复查有结论行。
