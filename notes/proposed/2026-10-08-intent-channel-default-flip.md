# 意图通道默认翻转：重大新工作默认呈批

日期：2026-10-08 · 状态：**proposed**

## 问题（可观察行为）

双通道设计（proposed 呈批 / 轮内直落）**实践失衡**：proposed 池长期为空，两周约 90 张 implemented
全部以轮内直落形态交付（[语料吸收审计 R4](../archived/research/2026-10-07-dsh-corpus-absorption-audit.md)）。
可观察后果：每件大事以「已交付」形态第一次见面——用户在事前看不到什么要进来，方向纠偏只能事后进行；
用户对工作面失去「什么进来了」的控制感（审计原话：用户是点火器不是方向盘）。

外部结果三要素：**触发** = 跨切片的新工作 / 流程面改动 / 模型可见面新能力被提出；**用户看到** =
开工前有一张三要素齐的 proposed 卡等点头或点名；**完成条件** = 下一次重大新工作真实走了卡
（proposed 池不再闲置）。

## 提案

根 AGENTS.md「新会话开工」意图通道节**默认翻转**（机制零新建——proposed 卡四件套与毕业门都在）：

- **默认**：重大新工作（跨切片 / 流程面 / 模型可见面新能力）先立 proposed 卡呈批，**点头或点名即开工**；
- **豁免清单（轮内直落保留）**：机械与局部编辑（与 note 义务豁免同口径）、已授权切片的轮内延续、
  用户本轮明确点名的具体任务、bug 修复卡毕业（巡检流自带呈批点）；
- [proposed-card-positioning](../implemented/2026-10-04-proposed-card-positioning.md) 的「点名或点头
  即开工」门槛不动——翻的只是「何时必须有卡」（本卡与其构成部分取代关系：毕业时同 diff 双向互链、
  更新其仍有效事实）。

## 输掉的方案

1. **维持直落默认 + 事后审计**——velocity 最高，但审计 R4 实证（proposed 空 / ~90 直落）说明
   事后审计拦不住方向偏差；「驾驭无力」体感不解。
2. **按规模阈值机械切（如 >N 文件必须卡）**——把意图判断降成行数统计：小而方向重的事（改一条
   standing order）会漏网，大而机械的重构会被误拦。
3. **废除直落通道**——过度翻转：机械修复与延续工作走卡是纯仪式（R5 流程自重）。

**代价（如实陈述）**：velocity 降——大事多一跳呈批。判断：值得；R4 是四症状根因里唯一原样开着的，
且 ~90 直落的「快」换来的正是失控感。

## 验收

- **机械面**：实施 diff 后 `pnpm verify` 全绿（entry-files 门确认常设指令形态）；根 AGENTS.md
  意图通道节含默认翻转句与豁免清单（grep 可断言）。
- **行为面**：下一次重大新工作以 proposed 卡开工（观察项——无法预跑；签收 = 用户在第一次真实
  呈批场景确认，或 `pnpm eval` 若立对应行为任务）。
- **红的形态**：文档语义不门禁化（A4 口径）——机械面红 = entry-files 门对常设指令形态的既有红；
  行为面无机械红，靠交付收口行与阶段收尾语义审计抽查。
