# 真用第一：冻结机制，本人过评测题定 G2，摩擦驱动下一轮 UX

日期：2026-10-01 · 状态：**proposed（主轴已拍板：A 真用驱动；第一件真活 = 本人过 30 题评测并打分——材料已就绪，等本人；基座搬运由 agent 并行自主做。2026-10-02 更新：G2 机器预判完成——当前组合重跑 30/30 零失败 + 判例乙逐题回填 + 三判据全绿，见 [评测卡](../../_backlog/plans/260928-domain-eval-v0.md) 与导览 `dev/eval/domain/calibration-2026-10-02.md`；验收 §1 只剩本人抽检真人门；同批首条真实摩擦证据 = 记忆摘要触顶（多题自报写不进记忆），下一切片候选）**

## 问题（可观察行为）

用户 2026-10-01 原话大意：弄来弄去有点不知所措；这个助手 UX 上不太好用、"怎么看都好像不知道怎么用"；
"CEO 或 VP 很容易抓到"没做到；要么停下来好好思考。同日核实三件事（证据均为当日实跑）：

1. **记忆基础已埋好（双层）**：房间事实记忆（26 个 memory/digest 测试当日全绿；245 会话中
   `assistant_memory` 真实调用 349 次；跨进程 recall 命中有日志实证）＋ OpenViking 情景记忆
   层 1（[推敲卡](../../_backlog/plans/260929-openviking-formal-integration.md)实弹验证版剖面已定稿，
   卡两道真人门）。诚实面：内容仍以研发域自指为主——"记得住"已解决，"记得都是用户的事"未开始。
2. **能力面机制大件已齐**：`--dump-config` 实证 goal / plan-mode / 委派 subagent / jobs /
   session-query / time-context / web 搜索抓取全部在场（[采纳卡](../implemented/2026-09-30-stock-plugin-adoption.md)）。
   按[《总体思路》](../archived/research/2026-09-25-grand-plan-enterprise-expert-assistant.md) §2.4 八个支撑物对照，
   缺口只剩：领域基座内容（0）、真实使用（0）、治理与触达的阶段 2 项。
3. **真实使用 ≈ 0**：245 会话真人消息共 152 条（0.6 条/会话）；工具混合 bash×2328/read×601
   表明绝大多数是开发代理会话。2026-09-26 [第一公里](../implemented/2026-09-26-first-mile-landing.md)修的是**发现性**
   （hero/命令/引导条），修完用户仍报同一感受 → 根因不在按钮位置，在"它是谁、替我干什么活"没立起来：
   领域内容为 0（打开像通用 LLM）、从未被真人用过（UX 无真实摩擦输入）、治理词汇（四房间/promote/park/drop）
   泄漏到用户面。**在没有真实使用输入前盲改 UX，只会重复第一公里的结局。**

## 提案（用户 2026-10-01 拍板：主轴 A 真用驱动）

1. **冻结**：机制与门禁扩张停止（宏观计划阶段 0 既有决定重申生效）；**无真实摩擦证据不动 UI**。
2. **G2+G3 一举两得的真用探针（2026-10-01 当日更新为零作业形态）**：本人在**干净试用 home**
   （`dev/trial-home`：expert-setup 装配管理岗身份 + 3 页管理知识种子；首开工作区之问已修，
   记录见[首开 UX 卡](../../_backlog/plans/261001-first-open-ux.md)）**随手真用**，不布置作业。首版
   「本人过 30 题评测并打分」被本人当日否决："本来想让你帮我解决问题，结果你给我抛过来这么多
   问题"——这正是产品自身的 UX 反模式现场重演，UX 思考已立 [首开 UX 卡](../../_backlog/plans/261001-first-open-ux.md)
   为 ongoing goal。G2 打分改为**机器按判例乙（已拍板：占位合规）逐题预判回填 + 本人随时抽检**
   （材料仍在：[打分表](../../dev/eval/domain/sheet-2026-09-28-19-23.md) +
   [校准导览](../../dev/eval/domain/calibration-2026-09-29.md)；对应
   [评测卡](../../_backlog/plans/260928-domain-eval-v0.md)）。每下 👎/每次卡壳
   自动进 desk-loop 摩擦报告 §7（[C2](../implemented/2026-09-30-c2-feedback-desk-loop.md)）不变。
3. **并行（agent 自主）**：搬管理岗基座内容——`ai_dsh_company` 的角色技能（CEO/VP-Sales/CFO/COO）
   搬成本仓 preset 技能（模型用、英文），知识种子按治理写入路径落 `draft` 人审（ intents §〇
   既定：基座内容的来源=那边）。目标：打开它第一眼像懂管理的专家，不是白纸。
   切片一已落地（2026-10-01）：[管理岗基座搬运](../implemented/2026-10-01-management-base-port.md)
   ——`market-sizing` / `project-economics` 两件入 preset 并 live 验证；其余 9 件的取舍理由与
   下一切片清单在彼。
4. **挂起不阻塞**：OpenViking 层 1 的两道真人门（AGPL 复核 + §六旋钮剖面过目）等本人方便时点，
   不排在本主轴关键路径上。
5. **UX 下一轮改动的判据**：必须引用 desk-loop/feedback 报告里的具体摩擦条目；无摩擦证据不动。

## 输掉的方案

- **继续盲改 UX**：第一公里的教训——修得都对（发现性真改善了），用户仍无感；无真实使用输入的
  UX 打磨没有收敛判据。
- **先重想产品形态**（分身的主动感、概念税回收等）：方向（CEO/VP 数字分身）2026-09-25 已拍板且
  未被证伪；形态问题记入真用后按摩擦裁决，不预先重设计。
- **先收尾 OpenViking 再谈使用**：记忆双层已够 G2/G3 用；情景记忆不是当前瓶颈
  （短会话 commitTokenThreshold 缺口已登记在其卡，属层 1 实施切片的校准项）。
- **继续堆机制/门禁**：宏观计划 §七 已判——上层证据（评测/真实会话）缺席时，下层绿不算前进。

## 验收

- **G2 打分（零作业形态）**：机器按判例乙逐题预判回填打分表、G2 判据（事实正确 ≥1 比例 ≥90%、
  0 分题 ≤2、应拒答题全拒答）算出红绿；本人抽检推翻预判时以本人为准——这是
  [评测卡](../../_backlog/plans/260928-domain-eval-v0.md)的毕业件。
- **首批真人摩擦读数**进 desk-loop 报告（含 §7 赞踩与备注），作为下一轮 UX 的唯一依据。
- **基座搬运**：首批角色技能入 preset 技能面（`pnpm build` 后 preset 会话可加载）、知识种子落
  `draft` 待人审；切片遵守垂直切片纪律（代码+测试+docs+note 同 diff）。
- 若真用暴露"形态层"问题（主动感/概念税），立独立推敲卡裁决，不在本卡内顺手改。
