# 工作台 tabs：桌面/自动化任务与对话同一壳

## 问题（可观察行为）

现在「桌面」「自动化任务」是独立主面板，右栏只在会话里存在；用户为了看一眼 Viki/知识/记忆，得先新建会话再开右栏。前两版原型（右缘小把手、应用级 overlay 右栏）都被否：形态不像对话页，且右栏/桌面关系仍然是“页面附属物”。

用户确认的目标：**一个工作台，顶部一条 tab，右栏常驻；切 tab 只换中间内容，不换壳、不重置右栏。**

## 提案

1. **工作台级 tab 条**：`对话 | 轨迹 | 桌面 | 自动化任务`。`对话/轨迹` 属于当前会话；`桌面/自动化任务` 是工作台固定页（全局数据，不按会话复制）。
2. **右栏常驻**：沿用会话原生右栏的形态与行为（开合、拖宽、窄屏收 rail）；切中心 tab 不重置栏内已打开的 Viki/知识/记忆页。
3. **详情进右栏**：桌面上的事项、任务页的任务，选中后详情在右栏打开；只有「去处理/打开原会话」才切回 `对话` tab 并带入上下文。
4. **左栏去重**：左栏的「桌面 / 自动化任务」入口只作为切 tab 的快捷方式，不再打开独立主面板。
5. **状态记忆**：每个工作台记住最后 active tab 与右栏布局；刷新不退回默认页。

## 输掉的方案

- **每个全局页自带一套右栏**（前两版原型）：切页像换应用，右栏内容重置；用户否。
- **右缘小把手 + 浮层**：不是对话右栏的待遇。
- **给全局页造 Session**：为了开栏多出会话，列表被污染。
- **改 vendor `rightbar` 为全局**：平台契约是 per-Session；不在插件里反向改上游。
- **每个会话复制一份桌面 tab**：同一份全局数据出现 N 个入口，用户会分不清。

- S2：`自动化任务` 作为同一 tab 条的第 4 项；优先复用 vendor `TaskManagerPage`，若它没有公开导出，就用 `remote.schedule` 做薄任务列表 + 右栏任务详情，不复制整页。
- S3：移除左栏「桌面/自动化任务」的独立主面板语义，改切 tab；移除任何 per-page 右栏残留。
- S4：工作台级 tab 状态与右栏布局持久化；窄屏 rail。

## 边界

- 右栏里的工作区文件、终端仍按会话能力显示；没有会话时显示可用项，不伪造终端/Session。
- 这是 UI 结构变更，不改变 OpenViking 层 2 / Viki 的 host 路由与数据合同。
