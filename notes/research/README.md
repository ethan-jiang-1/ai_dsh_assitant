# notes/research/ —— 调研底稿与普查

> 这里放**调研文档**：生态普查、技术选型调查、外部方案对照——自足成立，不依赖先运行
> 助手产品。判据与决策不放这里——决策进 `proposed/`（已定未建）或 `implemented/`
> （有证据）。**研究线索本体**（助手自己的探索：未决的问题、为什么值得追）住**家的
> `research/` 房间**（`<dshHome>/assistant/research/`，经 `assistant_research` 工具管理）；
> 本目录不是它的必备前置——开发者调研与助手运行期线索各管各的，需要互通时用
> `sources:` 指针互链即可。
>
> 形态规范（借自来源仓 research 文件，战役 note 登记过）：
> - **一手引证**：承重结论后跟来源 URL / npm 包名；二手转述不算数，跟到源头
> - **证据分级**：逐条标注 [affordance]（源码/接口可指认）/ [documented]（官方文档载明）/
>   [observed]（社区观察，注明出处）
> - **版本基线**：提到的每个包写明查证时的版本或 commit 日期
> - **承重结论内联自足**：只读本文即可成立
> - **普查底稿亲验**：进文前的承重主张由委托方复核（AI 检索结果不作最终证据）
>
> 文件名：`YYYY-MM-DD-<主题>-survey.md` 或 `YYYY-MM-DD-<主题>.md`。
