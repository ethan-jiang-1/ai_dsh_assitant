# 会话内工作台 tab：撤掉桌面的第二份副本

日期：2026-10-21 · 状态：**rejected**（会话内近似方案撤回；应用级 tab 仍待平台）

## 发生了什么

用户要“一个工作台，顶部一条 tab，桌面/自动化任务和对话同级，右栏常驻”。平台只有会话内的 `conversation.view`，没有应用级 tab strip。按用户裁决 1 先做了会话内四 tab：`对话 / 轨迹 / 桌面 / 自动化任务`，桌面 tab 复用 `DashboardMainPanel`，任务 tab 读 schedule catalog。

真机一看就露馅：左栏「桌面」有投影数据，会话里的「桌面」tab 却是同一组件的第二份挂载，读不到账本投影，显示“这个环境读不到账本投影”。同名的两个桌面内容不同——不是两个产品面，是同一个东西的两份挂载在会话里失效。用户直接问“这到底什么意思”。

## 决定

1. **撤掉 `assistant-desk` / `assistant-tasks` 的 `conversation.view` 注册**，恢复只有一个桌面（左栏主面板）。
2. **不再用会话 tab 近似工作台**：同名第二份挂载会造成“两个桌面”的认知分裂，比没有 tab 更糟。
3. 应用级 tab strip 仍只能等 DSH shell 提供；在平台具备之前不重开这个方案。
4. 任务页同理：薄列表与左栏完整页并存也会分裂，随 tab 一起撤。

## 输掉的方案

- **会话内四 tab**（本方案）：桌面数据不共享、同名不同内容；撤。
- **桌面 tab 改成跳转主面板**：跳转后 tab strip 消失，还是“两个世界”。
- **只撤桌面、留任务 tab**：同类分裂仍在，不成立。
- **浮层/假 tab**：用户已否，不再试。

## 边界

- 桌面/自动化任务仍是左栏独立主面板；Viki/知识/记忆/技能仍在会话原生右栏。
- 想做真正的同壳工作台，需要 DSH 提供应用级 tab 合同，不是插件侧能补的。
