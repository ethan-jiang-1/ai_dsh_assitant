## 一、初始意图（2026-09-23）

**动机**：想要一个 DSH 插件，是一个**领域专家式的聪明助手**，它自己拥有并安排上下文/工具/提示词，
核心诉求是**让这个专家有一个很好控制的上下文**。

**预期外部可观察行为**（逐条可验）：

| # | 意图 | 外部可观察行为 | 状态 |
|---|---|---|---|
| I1 | 聪明的助手 | 挂上 `assistant` preset 的会话有它自己的 persona、工具集与技能；其他会话不受影响 | proposed |
| I2 | **很好的记忆管理** | 会话能记住跨会话的事实/偏好/决定；重启后仍在；记忆以**有界摘要**进上下文（不爆上下文），需要时用 `assistant_memory` 深入检索 | proposed |
| I3 | **很好的技能管理** | 技能按需加载（目录 + 渐进披露）；技能目录可被 agent 自己扩充并**立刻可见**（无需重启） | proposed |
| I4 | **很好的自我学习能力** | 一次会话能被复盘（`assistant_reflect`）成：新的记忆记录 + 新的技能草稿；两者都落成**人能读、能改、能删的文件** | proposed |
| I5 | 很好控制的上下文 | 上下文由 preset 组装；记忆只以有界摘要常驻；过程性知识放技能（抽屉），不常驻桌面 | proposed |

## 二、补充意图（2026-09-23 用户追加，同样是一等公民）

**动机**：插件自己拥有一个 **working folder**（它的"家"）。这个家就是它的 harness 那一圈；
**把里头的content整理对、清理干净、让 agent 很熟悉很清晰**，本身就是一件重要的事。

概念依据：`/Users/bowhead/ai_dev_sdlc_aidc/talk-ai-coding-evolution-agent-101`
（`Agent = Model + Harness`；五件事 = 看到什么/懂什么/会什么/怎么做/怎么验；主线是信噪比；
"能让代码查的，别让 AI 自己说"；桌面 / 抽屉）。

**预期外部可观察行为**：

| # | 意图 | 外部可观察行为 | 状态 |
|---|---|---|---|
| I6 | 家有**固定、可读的布局** | 一个目录一眼看懂：`HOME.md` 是地图；`memory/` 是长期记忆；`skills/` 是学到的本事；各有各的职责，不混 | proposed |
| I7 | agent 对家**很熟悉** | 家的地图与记忆摘要常驻上下文（桌面）；细节用工具取（抽屉）。agent 不需要猜"我这儿有什么" | proposed |
| I8 | 家要**整理与清理** | 一个**机器能跑的检查**（不是 AI 自己说）报出：重复/矛盾/过期记录、摘要是否超预算、孤儿文件；agent 据此合并/退役 | proposed |
| I9 | 家要**清晰可审** | 学到的东西全是人可读的文件（Markdown + frontmatter），可 git、可 diff、可手改、可删；来源可追（哪次会话学来的） | proposed |

## 三、补充意图（2026-09-23 用户追加 · 探索与 backlog）

**动机**：我们**有时候会做研究推敲** —— 意图还不清晰、还不该进入工作流程的那种。
需要有个地方放它们：研究打磨之后，**成立的留着，不成立的丢弃**。像一个 backlog。

**为什么这是流程的入口而不是例外**：不清晰的意图如果没有落脚点，只有两个下场 ——
要么被硬塞进正式流程（污染记忆与技能，信噪比下降），要么蒸发（下次从零重开同一个问题）。
**输掉的方案要留下尸体**，这样同一个问题不会被反复重新讨论。

**预期外部可观察行为**：

| # | 意图 | 外部可观察行为 | 状态 |
|---|---|---|---|
| I10 | 探索有**自己的房间** | 家的 `research/` 放开放线索：一条线索一个文件，带状态（`open`/`parked`）与"为什么值得追" | proposed |
| I11 | 探索有**三档出口** | `promote` → 变成记忆记录或技能（成立就留着）；`drop` → 进 `archive/` 并**必须写理由**（不成立就丢弃，留尸体）；`park` → 留在 `research/` 但不占桌面 | proposed |
| I12 | agent **知道自己悬着什么** | 常驻摘要里有"开放线索 N 条 + 前几条标题"，不需要翻文件 | proposed |
| I13 | 悬着的线索**会烂，机器能发现** | `curate` 报出长期未更新的开放线索（建议 park 或 drop）与缺理由的 drop | proposed |

## 四、判据（借 talk 的两句，用于决定"搭多厚"）

- **错了赔得起吗？** —— 记忆写错：赔得起（可改可删，人可审）→ 所以记忆走"文件 + 可审"而非数据库。
- **错了多久能发现？** —— 记错了要尽快能发现 → 所以要有**机器能跑的检查**（I8）与**摘要可见**（I7）。
- 反过度工程：不建向量库、不建索引服务、不建后台自动学习循环 —— 等真实痛点到再上（见 proposed note）。
