# _backlog 治理借鉴：主干框架、挂起池、reference 区、backlog-liveness 门禁

日期：2026-10-02 · 状态：**implemented**

来源：用户指示"治理规矩要从 `ai_dsh_loop_advisor/_backlog` 学习来整理我们的 `_backlog/`，尽量借鉴，
整个结构多少都是一样的"。对照通读两仓全部治理文本（章程 + 9 份子 README + 代表卡片）后落此切片。

## 出身链（都记在各自章程里）

本切片对齐的 `ai_dsh_loop_advisor/_backlog` 是同一制度的更成熟形状（其链：ai_dsh_architect

## 借入（制度级）

1. **主干框架**：缓冲（半成品合法）→ 毕业（唯一车票）→ 管道（notes/ 唯一实施通道）→ 回写；
   三条硬规矩：无 proposed 卡不产生行为／卡记思考 note 记决定／回写不搭车。
2. **写回与不复活规则**：毕业卡永不重开；该做不现在的触发条件住决定 note（第二门改为"卡关闭 +
   指针"，触发到场以引用本卡的新卡/RFC 重进）；已在决定 note 里 deferred-with-trigger 的条目
   不再立卡（第二队列 = 源仓记录过的失败）。本仓批量清理卡的既有实践（关闭行 + 去向）与此一致，
   章程文本追认。
3. **挂起池** `_done/_suspended_{plans,bugs}/`：**未裁决即显式搁置**的暂停件（既非完成也非删除；
   挂起跟显式指示走、agent 不得自行挂起；回活需显式新优先级决定；挂起卡不是实施授权）。
   2026-09-28 的否决（"另立第二事实家"）被其边界划分解掉：池只收**未裁决**暂停件，已裁决的
   该做不现在仍以决定 note 为家——不借表两行翻案（用户指示即翻案触发）。
4. **reference/ 调研材料区**（活跃卡专用 + 随卡 `git mv` 至 `_done/_reference/`；无状态行；
   价值超卡的材料归 notes/archived）：**调研卡的收卷证据台账不变**（仍是
   notes/archived/research，2026-09-28 拍板机制）——两个家语义不重叠（喂活跃卡 vs 收卷已毕业
   调研卡）。
5. **`backlog-liveness` 门禁**（verify 31→32）：制度目录在场 / 活跃卡首 12 行有 `状态：` 户口 /
   索引互查（plans·bugs 活跃名册、_closed_plans 索引、_done 归档行）——核在
   verify-checks.mjs，红绿夹具三组在 verify-gates.spec（死稿卡 / 未点名 / 缺池 / 归档未点名）。
6. **章程/账本二分** + "状态行是归档卡唯一会活的部分"（指向的 note 挪走时指针跟随更新）+
   带日期的负知识行（本表 `_suspended_*`/`_reference_` 两行翻案即此形态）。

## 刻意不借（负知识，登记进章程不借表）

- **全日期卡名**（loop_advisor 用 `YYYY-MM-DD` 并主张全仓一个格式）：维持 2026-09-28 用户拍的
  六位 `YYMMDD`——改名收益不值 30+ 张卡的机械重命名与链接翻修。
- **id 冲突守卫**：同其"压力下再借"立场。
- 调度/排序、复盘卡：两仓同款负知识，维持。

## 本仓既有、loop_advisor 没有的（保留）

- 🔒 常设保留卡纪律（真实越界事故 + 行为评测任务钉着）；
- 调研卡形态规范与收卷台账机制；
- 命名六位适配的用户拍板。

## 验证（真跑过的命令）

1. `pnpm verify`——32 项全绿（新门禁 `backlog liveness` 在列；institution 目录、状态行、
   索引互查对现仓 4 活卡 + 1 bug + ~30 归档卡全过）。
2. `pnpm test`（verify-gates 38 夹具含三组新红绿）——绿。
3. 索引实态核对：plans 活跃清单 4 行、bugs 活跃表 BUG-001、_closed_plans 索引 ~30 行——
   门禁保证账本不落后于树。

## 输掉的方案

- **维持 2026-09-28 原状（零门禁 + 两行不借）**：负知识已过期——同源仓把这套制度演化出了
  更成熟的形状（挂起池边界、reference 区、索引互查门禁），而本仓 30+ 张归档卡只有文件名可考古、
  死稿卡只能靠人眼；"无复发证据不预铺"的登记前提（plans-liveness 等"有压力再借"）已被
  34 张卡的真实规模满足。
- **全盘照搬兄弟仓文本**：其章程是英文、卡名全日期、notes/implemented 分 process/feature/
  architecture 子目录——本仓语言分工（人与仓文档用中文）、2026-09-28 的六位日期拍板、
  扁平 notes/ 结构都不同。结构同源 ≠ 逐字照抄；借的是制度形状，落的是本仓语境。
- **只改章程文本、不做门禁**：没有机械看守的账本必然再烂（第二份清单漂移正是本仓自己记录过的
  失败）；借鉴源把门禁做进 verify 恰恰是这套治理能长期运转的原因——章程与门禁必须一起借。
- **只做门禁、不动章程**：门禁的索引互查预设"章程声明了账本"——没有制度文本的账本是无源之水；
  两者互为成立条件，同 diff 落地。
