## 借入（制度级）

来源：用户指示从 `ai_dsh_loop_advisor/_backlog` 借鉴治理结构；两仓同源（本仓初版借自 `ai_dsh_company`
D31，loop_advisor 是同一制度的更成熟形状）。借制度形状，不逐字照抄。

1. **主干**：缓冲（半成品合法）→ 毕业（唯一车票）→ 去向（work 或 memory；2026-10-25 收窄，见上）→
   回写。三条硬规矩：实施要有授权（work 走 proposed/收口卡）；卡记思考，note 记决定；回写不搭车。
2. **写回与不复活**：毕业卡永不重开；该做不现在的触发条件住决定 note 或 trigger；已在 note 里
   deferred-with-trigger 的条目不再立卡（第二队列是源仓记录过的失败）。本仓关闭卡的「关闭行 + 去向」
   与此一致。
3. **挂起池边界**：只收**未裁决**的暂停件（既非完成也非删除）；挂起跟显式指示走，agent 不得自行挂起；
   回活需显式新决定；挂起卡不是实施授权。已裁决的该做不现在仍以决定 note 为家。
4. **调研区**：活跃卡专用，随最后一张使用它的活卡 `git mv` 到 `_archive/research/`；收卷后还会被重提的
   事实写进拥有该决定的 note。现行规则见 [`_backlog/research/README.md`](../../_backlog/research/README.md)。
5. **liveness 与毕业门禁**：liveness 证明卡活着（制度目录在场、活跃卡首 12 行有状态户口、索引互查），
   但看不见「卡该走了」。毕业门禁补这一半：卡首声明关闭条件已满足、却仍留在 `issues/`，就红；
   若它还出现在活跃名册里，报错会点名那处残尾。核在
   [`scripts/checks/gates/backlog.mjs`](../../scripts/checks/gates/backlog.mjs)，真回归第一次跑就抓到了
   一张这样的卡。现行翻转表与字段（`可关闭：是` / `关闭条件 = 已满足`；旧卡 `毕业门` 字段保持兼容）见
   [`_backlog/README.md`](../../_backlog/README.md) §卡的生命周期 与
   [`_backlog/issues/README.md`](../../_backlog/issues/README.md)。
6. **章程/账本二分**：章程拥有规则，卡拥有历史；状态行是归档卡唯一会活的部分，指向的 note 挪走时指针
   跟随更新。带日期的负知识行记在章程的不借表里。

## 刻意不借（负知识）

- **全日期卡名**：维持 2026-09-28 拍板的六位 `YYMMDD`；改名收益不值全量重命名与链接翻修。
- **id 冲突守卫**：同其「压力下再借」立场。
- **调度/排序、复盘卡**：两仓同款负知识，维持。

## 本仓既有、源仓没有的

- 🔒 常设保留卡纪律（真实越界事故 + 行为评测任务钉着）；
- 调研卡形态规范与收卷台账机制；
- 命名六位适配的用户拍板。

## 输掉的方案

- **维持 2026-09-28 原状（零门禁 + 两行不借）**：负知识已过期——源仓已演化出挂起池边界、调研区、
  索引互查门禁；本仓关闭卡的真实规模已证明需要门禁，死稿卡不能只靠人眼。
- **全盘照搬兄弟仓文本**：其章程是英文、卡名全日期、notes 分 class 子目录；本仓语言分工、六位日期、
  扁平 notes 都不同。结构同源 ≠ 逐字照抄。
- **只改章程、不做门禁**：没有机械看守的账本必然再烂（第二份清单漂移是本仓记录过的失败）。
- **只做门禁、不动章程**：索引互查预设「章程声明了账本」；两者互为成立条件，同 diff 落地。
- **复用 `GRADUATED_STATUS` 匹配 plan 状态行**：它要求 `状态：**完成词`，而问题卡的状态是推敲态、
  完成判断在关闭条件/毕业字段；直接复用会把「推敲中但四门已判该做」的诚实卡判红，等于逼人谎报。
  故另立判据。
- **把「人待」算毕业**：能把等待中的卡提前归档，让名册更干净；但会把「等真人」这件正在发生的事实
  从活跃面抹掉。门禁宁可少抓，不逼出假绿。
