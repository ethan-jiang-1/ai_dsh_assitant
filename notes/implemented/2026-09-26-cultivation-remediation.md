# 培养面整改包：内容准入 → 异步闭环 → 机械缺陷 → 语义 → 密度

日期：2026-09-26 · 状态：**implemented**（S1–S4 + S6 + S7 全部交付、S5 由第一公里 P2 判定闭环；逐片验收在本文，决策理由见[第一公里卡](2026-09-26-first-mile-landing.md)与[设计 owner 卡](2026-09-26-cultivation-surface-design.md)）

## 问题（可观察行为，开发者已逐条核实）

两份独立评审——[对抗性设计评审](../research/archive/2026-09-26-adversarial-design-review.md)（不知情新 agent，
读代码 + 真实 desk 文件）与[运行中页面独立体验反馈](../research/archive/2026-09-26-ux-review-feedback.md)
（真机点过页面）——一致指出、并经开发者核实的可观察缺陷：

1. **内容准入缺失**：首屏放大的正是助手家务（真实 desk 文件 `decisions[0]` = "培养面接着做深，还是先停一停？"）；
   知识室半是维护间（12 条技能 / 2916 字符英文描述）；开发素材（DSH 机制、仓库纪律、评测过程）进入委托人面。
2. **异步闭环缺失**："已提交 ≠ 已完成"——`busy` 在提示被受理时即清除（毫秒级 vs 助手几十秒）；
   决定要"看选项 → 回对话看 → 再回来手抄"；行上没有回执；破坏性动作无确认、无撤销说明。
   真实代价：A3 在 90 分钟内收到 **7 条互斥指令**，助手最终把该行"封存"。
3. **机械缺陷 A1–A10**（评审 §7 列表；含技能行发错对象类型、右栏陈旧告警失准、跨会话静默回退等）。
4. **视觉层未验证**：开发者从未见过渲染结果；UX 专家明确"无真机截图不下视觉结论"。

## 提案（切片，按序；每片＝一个垂直切片，独立提交，verify 随片走）

### S1 内容准入与首屏经营优先（两份评审一致；专家验收问题①）

- **契约**：`decisions[].kind: "business" | "upkeep"` + `rank`；SKILL.md 写死规则——"最多一条 business
  上引导卡；写之前先问：**只有本人能拍、且拍完会改变外面的动作**吗？"
- **面板**：引导卡只吃 business 的第一条；没有则**诚实显示"目前没有需要你拍板的经营事项"**；
  upkeep 进折叠组「助手自己的事（N）」，渲染为每行只有标题的紧凑列表。
- **内容资格**：技能列表降级为一行计数；开发素材默认不进委托人面（规则写进 SKILL.md）。
- **验收**：只有 upkeep 的夹具 → 无引导卡 + 诚实空态；有 business → 上卡；专家问题①（三秒内说得出
  "我来这里要做什么"）。

### S2 可核验的异步闭环（专家验收问题②）

- **契约**：`decisions[].options[]`、行级 `pending: { at, action }`、`reply?`、`actions[].note?`
  （最后一项真实文件里已有、今日被静默丢弃）。
- **面板**：解冻条件改为**数据闸门**（`pending.at` 晚于文件 `generatedAt` 才解冻，而不是 promise 闸门）；
  行内回执"已交给助手 · HH:MM · 正在处理"；破坏性动作二次确认 + 明说可恢复；选项渲染成行内按钮
  （点一下即回答，不必回对话手抄）。
- **技能**：同 diff 更新（写 pending/reply/options/note）。
- **验收**：数据闸门夹具（替换现在"手设 busy"的测试）；用户能区分已提交/处理中/完成/失败；
  完成后能确认**哪一行**被改了。

### S3 机械缺陷 A1–A10（无需价值判断；可与 S1/S2 并行）

A1 技能行发错对象类型；A2 右栏陈旧告警失准；A4 跨会话静默回退；A5 tab 卡在"正在读"；
A6 tab 空态无刷新按钮；A9 固定重读窗口 → 数据驱动；A10 面板消息来源标记；
IME `isComposing` 守卫 + 换 textarea。**验收**：每缺陷一个能红的夹具 + 全套门禁。

### S4 三室语义落地（专家验收问题③；用户拍板保留三室）

三室含义改为三个用户问题（**现在要采取什么行动 / 你凭什么这样判断 / 你把我理解成什么**）；
桌面上的 draft 指针**落到那一条**（需摸平台 `selectPanel`/定位 API，可能触发型）。
**验收**：标签与分区标题一致；指针可达具体条目（若平台不允许，明确降级为房间入口并记录原因）。

### S6 着陆：第一次打开要知道怎么进来（用户实测发现，2026-09-26 晚追加）

**用户原话**："不知道怎么落脚，一不知要干什么也不知道……我是不是要选一个工作目录啊？"
**切片**：没有桌面文件时，桌面面板自述三步（①在旁边的对话里跟助手说句话 ②它把这个工作区的桌面
建起来——这里是你的仪表盘，不是要你配置的东西 ③之后一直显示等你拍板/在办/缺什么，每条可就地处置）；
来源行从倒原始路径改为说人话："桌面跟随当前对话的工作区，更新于 HH:MM（换一个对话，桌面跟着换）"，
完整路径进 tooltip。**平台层管不到的部分**（DSH 会话创建问"选工作目录"）记入设计卡未决——
**2026-09-27 已查清**：平台本身会给默认工作区（空注册表时建
`<Documents>/deepseek-harness/default-workspace`），用户当时的问法更可能是 affordance 问题；
结论与复现配方见[第一公里走查](../research/archive/2026-09-26-first-mile-walkthrough.md) §3/§4b。

### S5 密度（最后；等真机截图/录屏）

内容过滤后再看真实密度；在此之前**不动**字号、配色、暗色、砍结构。

**2026-09-26 更新：僵局已解，证据已取。** 第一公里 P0 的截图管线自产真机窄栏证据
（[走查报告](../research/archive/2026-09-26-first-mile-walkthrough.md) + [截图目录](../research/2026-09-26-first-mile-shots/)），
第一次能按"有截图才有结论"下判断：右栏 ~530px 内每条「在办」6–9 行、动作按钮在行底（要读完
审计行才够得着）——内容本身是 S1 过滤后的经营实质，所以这是**层级**问题不是内容问题。

**2026-09-27 闭环：层级已判定并落地。** 三条候选里取了「动作移到标题行」（`CorrectableRow`
一处改动，六种行类型共用），另两条（「它记」折行截断／「在办」折叠）**不采纳**——它记是信任线、
折叠会藏起判据。真机前后对比与理由在
[第一公里卡（已交付）](../implemented/2026-09-26-first-mile-landing.md) P2 与判定记录 1。

## 输掉的方案

- **按对抗评审直接重切三室**（Inbox/审计/忙什么）：用户 2026-09-26 拍板——分歧以 UX 专家版为准，
  保留三室入口、改语义；对抗版的实质指控（内部数据模型泄漏、upkeep 占据委托人面）由 S1 的两条规则吸收。
- **先做视觉大改**（字号/对比度/暗色 token）：无真机截图前不做（专家方法纪律 + 开发者盲区）。
- **先做搜索/过滤**：问题不是搜不到，是内容没资格在这里（专家 §2.5、对抗评审 §6 同向）。
- **保留"忙时冻结"**：窗口＝受理窗口而非工作窗口，已被真机实测证伪；S2 改为数据闸门。

## 验收（包级）

> **补记（2026-09-26 收尾整备）**：S1–S4 全部落地后跑 `pnpm release-smoke` **passed**（pack → 干净 home →
> plugin add → 组合读回断言：host 行在组合、preset 是 profile 默认、preset-mounted runner 可组合）——
> 整改没有破坏安装形状。桌面数据由 eval 复验持续刷新（20:52 版，business/upkeep 分类与选项/note/reply
> 全部在场）。仪表"面板动作"计数含本仓 eval 复验自己发的 `[桌面]` 提示（消息层与真人点击不可区分），
> 读数时须知。

- 每片：`pnpm verify` 31/31 + 本包测试 + 相关夹具**能红**（新守卫必须证明会失败）；
- 涉及模型面/契约：同 diff 改 SKILL.md，并跑 `pnpm eval -- --only desk-refresh-loop`；
- 交付：`pnpm build` + 干净目录起 web + preflight 绿 + **真人（或 UX 专家）点得通**——
  "装得上"不算"点得通"（P0 教训）；
- 专家三问：①三秒内说得出"我来这里要做什么"？②能否区分已提交/处理中/完成/失败、并确认哪一行被改？
  ③三室是否被理解为三个问题（行动 / 依据 / 对本人理解）？
