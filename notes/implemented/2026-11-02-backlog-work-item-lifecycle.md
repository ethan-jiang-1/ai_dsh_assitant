# backlog 工作项生命周期：五道门与双向 handoff

日期：2026-11-02 · 状态：**implemented**

## 问题（可观察行为）

2026-10-12 的流程把「做」的结论压在 issue 的 `推敲中` 里：卡上没有「准备进开发」的独立位置，验收标准与去向散在正文，`修复就绪` 之外没有状态能表示「ready」。2026-10-25 把 work 与 memory 分成两个 handoff，但接收端只有 notes 的分类章程，agent 进 `notes/` 时没有一份收件、写入时机与对账的操作面；最后一步靠散文，`待落地` 的 note 可能提前写、`去向` 可能只写一句、审查可能被写成 verified。research 题名页也没有阶段，证据区的「还在做 / 已结论」只能从消费者行推断。

## 决定

采用五道门，三轨保留自己的词；状态命名「已过哪道门」，不是「正在做什么」：

| 门 | issue | bug | research 题 |
|---|---|---|---|
| 研究 | `推敲中` | `排查中` | `调研中` |
| 定性 / ready | `待落地` | `修复就绪` | `已定性` |
| 落地 | `待落地` 期间 | `修复落地` | 结论转卡 / note |
| 审查 / 验收 | `审查：` + `## 验收标准` | `## 修好定义` + 证据 + `审查：` | `> 结论：` + 证据评审 |
| 归档 | `已结` | `已修` / `待修` | 目录 + `> 归档：`（status 不变） |

1. **`待落地` 是 ready，不是授权**：只用于 `毕业：做现在`；需要非空 `## 验收标准`、`去向` 与方案/取舍；卡覆盖整个落地期，进度/证据住收口卡 `## 切片台账`，不设 `落地中`。
2. **`修复就绪` 保持授权边界**：`## 修好定义` 非空；P1/P2 修复型自授权，P0 或触及入口链 / 门禁与验收合同 / 文档合同 / 包公共行为 / 已记录决定 → `等人拍板`。`修复落地` 是「修进树，判据、证据、审查未过」。
3. **审查是分层守卫**：机械检查不跳；语义自审按风险（跨面 / 持久决定 / 入口链 / 门禁与验收合同 / 文档合同 / 包公共行为 / P0-P1 必审）；用户验收按重要性；跳过记 `审查：跳过 — 理由`，不写成 verified。没有 `待复核` 状态。
4. **`去向` 在 ready 门选**：`implemented` / `proposed` / `rejected` / `deferred` / `none`；`待落地` 不写 note；`implemented` 与交付/卡关闭同变更；`proposed` 与卡关闭同变更，卡关闭 ≠ 批准，毕业才写 implemented；`none` / `deferred` 不进 notes；`rejected` 仅防复犯价值。
5. **research 题名页也有阶段**：`status: 调研中 | 已定性` + `opened` + `> 状态` + `> 结论`（`已定性` 非空）；材料仍 `topic` / `intent`，不装 status；归档靠目录 + `> 归档`，status 保持 `已定性`。
6. **操作面与章程分家**：[`_backlog/AGENTS.md`](../../_backlog/AGENTS.md) 是生产端状态机/守卫；[`notes/AGENTS.md`](../AGENTS.md) 是消费端收件/写入时机/对账；两份 README 仍是章程与模板；[`issue-to-note`](../../_backlog/methods/issue-to-note.md) 是程序；根 [`AGENTS.md`](../../AGENTS.md) 是总线；门禁钉结构。

## 与旧流程的关系

- 收口卡从 `推敲中` 直接进 `待落地`，交付同变更 `已结`；`## 切片台账` 继续是跨会话证据表，但不再被读成第二个状态。
- 旧卡上的 `毕业门判断` 字段保持兼容；旧归档卡不迁移，历史状态行不回填。
- research 旧题名页没有 frontmatter 的不回填；新题从 `调研中` 起，结论落 `> 结论：`。

## 输掉的方案

- **issue `落地中`**：把判断记录变成任务追踪器，执行可见性被拉进卡的状态；输给「`待落地` 覆盖全程 + 会话 plan/todo 与收口卡账」。
- **issue `待审` / `待复核`**：与 `等人拍板` 重叠，模糊「谁能移动」；审查是守卫，不是状态。
- **research `待定性` / `已归档`**：前者没有独立动作，后者与目录重复；旧决定里「不把原料伪装成结论」的一半仍然成立。
- **给 research 材料加 status**：一份证据一个状态，制造第二状态源；状态留题名页。
- **统一三轨状态名**：丢掉 bug `修复就绪` 的授权边界，也让 research 的「结论」与 issue 的「裁决」混词。
- **backlog 变实施前置门**：用户直派应直接执行；`待落地` 只对需要推敲的卡设门。
- **`待落地` 写 implemented note**：把计划伪装成已交付事实；写入时机推迟到交付/卡关闭。
- **`去向` 直接链未来 note**：交接期目标还不存在，markdown 链接会红；交接期用 inline code，关闭期改 live link。
- **把 `审查：跳过` 写成 verified**：完成定义失真；跳过与阻断都如实写，note 的验证节只收实际跑过的检查。

## 验证

本片的最小证据是 `pnpm test:tooling`（backlog 与 notes 门禁族的正负例）和 `pnpm verify`（结构、链接、入口稳定性）；真结果留在提交说明，本 note 不记计数。

## 后果

- 新 issue 只有 `毕业：做现在` 才能进 `待落地`；`以后做 / 不做 / 已在别处` 直接 `已结`。
- 新 bug 在 `修复就绪` 前必须有非空 `## 修好定义`；`修复落地` 出口前必须有 `审查：` 记录。
- 新 research 题名页必须带 `status` / `opened` / `> 状态`；`已定性` 必须带结论。
- 旧 note 的「验收在场检查族刻意延后」到此触发；后续同类门禁按本 note 的五道门处理。
