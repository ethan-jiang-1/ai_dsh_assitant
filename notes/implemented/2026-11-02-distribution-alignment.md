# 发行版口径：术语、六轴与文档骨架对齐 DSH 推荐

## 问题（可观察行为）

代码侧已经按 DSH 的形态改对了（bundle 携带默认值、安装器出包、npm 为主渠道、Plugins 页为默认入口），
但**说法、文档和证据链没有跟上**，两份独立审计（6 面并行 + 1 次全链 fresh-eyes）确认了 40+ 处不一致：

- 术语仍把交付单位说成「产品 = 一个 profile 的组合」，并成对使用 DSH 已退役的「产品 profile／产品 bundle」；
- 宪章没有六轴 owner 表，也没有生命周期十段索引——"完整/可控"两个判据无法从合同自证；
- 包 README 的七节是仓库自造的（含架构段，缺"验证/排障"），且被门禁钉死；
- 生成的手册教用户往 headless profile 写裸 `- id: agent-preset-registry`（该行在 headless 不存在），
  并在恢复备份处要求"目标目录先清空"（与 `import --replace` 相反，会删在用数据）；
- 两条发布 smoke 仍断言"解包里带 `bootstrap.mjs`"，在安装器出包后必然红；
- 两篇 implemented note 互相矛盾且都自称当前。

## 决定

1. **术语线**：`product` 只指 ① 整台运行中的 dsh（引述 DSH 时）与 ② 这份业务/产品定位（P1–P3、产品口味）。
   **不修饰任何交付对象**——不用产品 profile／产品 bundle／产品行／产品门／产品 home／产品安装器／产品模式。
   对象名一律用 DSH 词：bundle、custom profile `assistant`、发行版、专用 home、入口行 `assistant-product`、安装器。
   代码身份（`assistant-product`、`productHome`、`src/host/product/`）不改。
2. **宪章成为发行版的单一说法**：`docs/release.md` 加 §〇 术语与判据、§一 六轴 owner（运行时／profile／patch 层／
   app surface／home 与数据／生命周期）、§七 生命周期十段索引；每轴写"我方定法 / DSH 机制 / 读回方式 / owner 文件"。
3. **文档骨架回到宿主形**：包 README 七节 = 装什么/安装/验证/配置/升级/卸载与数据/排障；架构与实现说明移出
   （住 `docs/architecture.md` 与生成物 catalog）。安装手册十段 = 是什么/前置/选运行时/安装/首启/验证/配置/升级/
   卸载/排错 + 安全。
4. **默认部署 = 专用 custom profile + 安装器**，理由是本 bundle 的默认值带产品口味（停用右栏终端、关轨迹页、
   `locale: zh`），装进别人既有的 web profile 就是改他的组合。**同时 bundle 不假设 profile 名**：装进任意
   web profile 都能工作——那是健壮性，不是推荐路径。
5. **历史按取代判据逐篇判**（`notes/README.md` §〇之二）：完整取代则吸收后删除；部分取代则双方保留 + 旧篇顶部
   指针；纯历史冻结，只在索引加一行"前提已不成立/已落地"。
6. **防回潮**：退役词、README 骨架、六轴/十段存在性进机械门禁，各带 prove-it-red 负例。

## 输掉的方案

- **只改 README 与手册，不动宪章**：说法没有家，下一个人还会再造一套；六轴与十段索引解决的正是"没有单一出处"。
- **把「装进任意 web profile」当推荐路径**：bundle 能用是真的，但我们的默认值会改用户既有组合（停终端、换语言、
  关轨迹页），默认路径不能拿别人的组合做代价。
- **保留仓库自造的 README 七节**：宿主只读 `package.json` 与导出 locale，人需要的是"装得上、怎么验、怎么退"；
  架构说明占掉第一屏，与 DSH 自家包的形不同，工具也不认。
- **全量删除被推翻的 implemented note**：会同时丢掉仍然有效的负知识（数据边界、不打包运行时、多租户不做）；
  只有"完整取代"的篇才删。
- **让 profile 承担产品身份**：profile 可被重置、可被用户改 patch；身份一旦住进 profile，模板重置就等于产品消失。
- **保留 `产品` 作为对象名**："产品"在这份 repo 里同时指整台 dsh 与这份业务，再拿去修饰单个对象必然歧义；
  半退役更糟——作者看不出边界。

## 后果

- 一个新会话只读 `AGENTS.md → docs/release.md` 就能判断"要交付什么、每条轴谁拥有、生命周期每段谁写"。
- 用户拿到的手册不再教会丢数据或必然失败的操作；README 第一屏回答装/验/退。
- 历史不再有两篇都自称当前；归档只作历史引用。
- 退役词与骨架由门禁守，同一类漂移下次会红而不是靠审计。
- 代价：一次性的全量措辞替换（docs/README/当前权威 notes）；归档正文不重写，只在索引声明口径。
