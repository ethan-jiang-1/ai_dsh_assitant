# 维护面 B1：Viki 记忆可枚举、可读

日期：2026-10-19 · 状态：**implemented**

## 问题（可观察行为）

Viki 的记忆没有读者：`ov-shield` 只挡工具/技能面，抽取物照样进每轮召回；人能看见它的唯一方式是"觉得它记错了"。真正的抽取物在 `viking://user/<space>/peers/<peer>/memories/events/YYYY/MM/DD/*.md`，`user/<space>/memories` 只有 `identity.md`/`soul.md` 模板；`fs/ls.abstract` 对这批文件是空串，标题/摘要/类型在 `fs/attrs.result.attrs.memory`。B1 让面板能列出它记得什么、逐条读正文，且不靠模型回合。

## 决定

1. **新 host 行 `assistant-viki`**（`GET /api/assistant/viki`，`ctx.connection.fetch.register`，owner-only）：不继承 A 卡路由；A1a 的 tab/drawer 骨架复用；`POST` 留给 B2。
2. **`VikiClient`**（`src/host/viki/client.ts`）：`baseUrl`/`apiKey` 来自 config → `OPENVIKING_URL`/`OPENVIKING_API_KEY`；空 base 是合法"未连接"（503），不阻断启动；`fs/ls` 显式逐层走树（`events/YYYY/MM/DD`，不假设一次 recursive 到底）、`fs/attrs` 摘要/标题/类型、`content/read` 正文、`stats/memories` 交叉核；过滤 `.overview`/隐藏；摘要为空时回退 frontmatter `title:`/首行；`..` 段拒绝；`Authorization: Bearer` 仅在有 key 时。
3. **树 = 两处真值**：`user/<space>/memories` **与** `peers/<peer>/memories/**`；peer 可配置限定，缺省列出 space 下所有 peer；路由只接受配置的 space/peer 与白名单内 URI（`?space=`/`?peer=`/`?uri=` 都校验）。
4. **客户端**：房间 tab 骨架新增 **Viki tab**（2026-10-24 起只在 debug flag 开时注册；`room-tabs` 注册，复用 `ContentDrawer`；不另造 store/parser）；列表显示两处计数/摘要/类型/peer，点"读全文"经路由取正文；503 → "Viki 未连接" + 重试；**不投 prompt、不跑模型**。
5. **同 diff**：`docs/architecture.md` host 行、`docs/identity.md` 行 id、`cordis.patch.yml`、`package.json` 的 `./viki` export、`docs/package-catalog.md` 重生成、`tests/composition/export-shape`、`client-entry` 的 tab 期望。

## 输掉的方案

- **只列 `user/<space>/memories`**：只剩 2 个模板，真正的 events 一条看不见（B 卡实测）。
- **`fs/ls.abstract` 当摘要**：这批文件空串；会显示空列/父目录摘要。
- **假设 `recursive=true` 一次到底**：实测只到 `YYYY/MM`，不到 `DD`/叶子。
- **把 `assistantViki` 做成 A 卡路由的复用/Remote**：A 不拥有 Viki 路由；删除/读都不走 Typert Remote。
- **硬编码 `127.0.0.1:1933` 或 dev auth**：配置/凭据链是 owner；dev 的 `OPENVIKING_URL` 显式给。
- **把 Viki 当权威/灌进房间**：抽取质量不足以当权威；房间仍是唯一权威。
- **先建派生索引**：`fs/ls`+`attrs` 已够，7 条规模不需要。
- **server 缺席时阻断启动**：OpenViking 是可选增强。
