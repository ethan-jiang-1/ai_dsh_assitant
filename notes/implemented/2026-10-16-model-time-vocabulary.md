# 模型面时点术语与日期口径：让读回用同一套词

日期：2026-10-16 · 状态：**implemented**

## 问题（可观察行为）

**外部结果三要素：** 触发＝本人读晨报、读回一件事的现状；本人得到＝**同一套词**——时点用账本的那几个（承诺日 / 预测到账 / 下一次核对点），日期用 ISO；完成条件＝真跑里不再出现第三种写法（人工核对）。

**缺口是怎么被发现的**：2026-10-16 真机走查素材里，同一个时点概念有三种写法 ✗——产品面与合同用「核对点」（ISO），模型在简报里自己写「检查点」、日期漂成 `10/20`。用户不会崩，但要在两套词之间做翻译——对一个"读回你的事"的产品，这正是要避免的摩擦。

## 交付

`desk-daily-brief/SKILL.md` 末尾新增 `## Time vocabulary`：三个时点**只用账本的词**（对应 `promised_deadline` / `forecast_at` / `next_checkpoint`，禁用 检查点 / 截止日 / 到期日 等）；**日期一律 ISO**，相对说法只允许出现在**逐字引用**里；pending 不算生效日期（与工具的 `pending — NOT in effect` 对齐）。

**根因（grep 实测）**：模型用技能里**根本没有**这套词汇（`grep "检查点\|核对点\|承诺日\|预测"` 零命中）⇒ 技能从没钉过，模型自由发挥；**其他技能也不谈这套词**，所以一处钉死即可，不会"别处照漂"。

**证据**：`pnpm verify` 41 绿 · `pnpm release-smoke` passed（技能随 preset 进发布物）· 真跑 `node dev/probes/web/desk-daily-brief-live.mjs` `passed: true`（load 7.23）+ **人工核对**该次简报：检查点 / 截止日 / 到期日**一个都没出现**、承诺日 / 预测 / 核对点**在用**、ISO 日期 37 处。

**如实记的残留**：模型自己的叙述里仍有一处相对说法（"明天早上开始执行"）与一处斜杠日期——**术语表那半完全生效，日期口径那半部分生效**；下次真跑再看，稳定残留则另立一片（把口径写进更靠前的段落，或由工具输出固定格式）。

## 输掉的方案

- **在探针里加措辞判据**：本仓教训——判据钉账本事实、**不钉模型措辞**（[结构还清 note](2026-10-16-structure-paydown.md)）。锁技能文本、回归靠人判。
- **让 UI 改用模型的词**（把「核对」改成「检查点」）：合同是 contract，模型漂移不是改合同的理由。
- **改 `docs/operating.md` 迎合模型**：同上，反向漂移。

## 还会约束以后的后果

- **账本的词就是产品的词**：模型输出的时点一律沿用工具字段与产品屏幕的措辞，不再造同义词；
- **日期一律 ISO**：相对说法只能出现在逐字引用里（本次残留说明这条要靠人看，且可能需要更靠前的位置）；
- **模型可见面的词汇约束写进技能、不写进判据**：探针继续只判账本事实。
