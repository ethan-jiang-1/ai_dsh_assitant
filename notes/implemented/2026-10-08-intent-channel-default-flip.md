## 决定

根 AGENTS.md「新会话开工」意图通道节**默认翻转**：

- **默认**：重大新工作（跨切片 / 流程面 / 模型可见面新能力）开工前先立 proposed 卡呈批，
  **点头或点名即开工**；
- **豁免清单（轮内直落保留）**：机械与局部编辑（与 note 义务豁免同口径）、已授权切片的轮内延续、
  用户本轮明确点名的具体任务、bug 修复卡毕业（巡检流自带呈批点）；
- **机制零新建**：proposed 卡四件套与毕业门都不变——翻的只是「何时必须有卡」。

## 输掉的方案

1. **维持直落默认 + 事后审计**——velocity 最高，但审计 R4 实证（proposed 空 / ~90 直落）说明
   事后审计拦不住方向偏差；「驾驭无力」体感不解。
2. **按规模阈值机械切（如 >N 文件必须卡）**——把意图判断降成行数统计：小而方向重的事（改一条
   standing order）会漏网，大而机械的重构会被误拦。
3. **废除直落通道**——过度翻转：机械修复与延续工作走卡是纯仪式（R5 流程自重）。

代价（用户知情接受）：velocity 降——大事多一跳呈批；换回方向盘感（R4 收口）。

## 交付收口

行为对齐——三要素：触发 = 用户对呈批卡点头；用户看到 = 重大新工作开工前有卡可拍板、意图通道节
写明默认与豁免清单；完成条件 = 验收对账（下节）。**签收** = `pnpm verify` 全绿（entry-files 门确认
常设指令形态、断链门确认新链）+ 本切片自身即「呈批 → 点头 → 毕业」流程的首个完整实例。
**未跑项**：`pnpm eval`（「走卡」是流程观察项，无对应行为任务——行为面按卡验收以第一次真实
重大新工作为验据）；`pnpm test` 全量（改动面 = 两页 markdown + 索引，verify 已覆盖该面）。

## 验证（真跑）

- `pnpm verify`：35 门全绿（entry-files / 断链四连 / notes 形状 / gen-notes-index freshness）。
- 行为面观察项：下一次重大新工作以 proposed 卡开工；无法预跑，首次呈批即验据。
