# 安装/配置是一等交付：可选层必须自己站得住

## 问题（可观察行为）

插件本体能导出，但导出包只教「装插件」，不教把 profile 的默认 preset 切到 `assistant`；OpenViking
的安装/配置只活在 `dev/experiments`、`.env.local` 和本机 live 探针里；一键脚本依赖本仓 dev home 与
本机绝对路径。结果是「把这插件给另外一个人，另外一个人跑不起来」：包能装上，但跑起来不是助手。

## 决定

- **安装/配置是交付的一部分，不是文档尾巴**。发布物 = tgz + 生成的《安装手册》，手册覆盖：前置版本、
  插件安装、**preset 默认切换步骤**、可选 OV 安装/配置/启动/自检/故障表、卸载。
- **自检随包走**：`bin/ov-doctor.mjs` 进 tarball，只用 Node 内置；仓内开发与安装后的 profile 用同一个
  文件。OV 缺席时它 exit 2 且不阻断 DSH。
- **可选层必须可降级**：OV 缺席 → 插件照常启动、Viki 503、doctor exit 2；OV 在场 → doctor exit 0、
  Viki 200。两者都由干净 home 的发布冒烟覆盖。
- **手册只写被冒烟验证过的路径**；命令和占位说明要能照抄（例如新 profile 的 patch 文件里是占位 `[]`，
  手册写「整行替换」，而不是「追加」）。
- **不依赖本仓 dev home、`.env.local` 或 live 探针**：另一个人的路径只依赖导出包、手册与他自己的
  环境（包括他自己的 OV 安装）。
- **交互式 wizard 不是阻塞项**；远程部署指引只在真实远程部署出现时再做；用户侧 OV 安装脚本是可选
  增强，手册路径已经能跑通就不预建。

**重开触发**：真人按手册走查出现同类卡点 **≥2 次**，或第一次真实远程部署（与 `triggers.md` 同口径）。

## 输掉的方案

- **把安装说明留在 README 的尾巴**：另一个人拿不到可执行顺序，也看不到 preset 默认这一步；不选。
- **把 wizard 当阻塞项**：先付一个交互面，而手册 + doctor + 干净 home 冒烟已经能回答「装不装得上」；
  不选。
- **安装路径依赖本仓 dev home / `.env.local` / live 探针**：不可从他机复现；不选。
- **把 OV 行写进 tracked profile-patch**：可选层变成 fresh home 的常态警告；不选。
- **让 OV 成为必需依赖**：单点故障，且违反「可选增强」的产品边界。
