# 立条目制：ROADMAP 根部队列与 fresh-agent 入口链

日期：2026-09-24 · 状态：**implemented**
依据：用户决定（2026-09-24）——借鉴 `ai_dsh_company` 仓 ROADMAP.md（其 D23/D24：条目制、
根部队列文件）的**精神**按本仓哲学适配；起因 = 用户问"换了对话接下来做哪一个怎么判断"，
前一日盘点确认本仓缺口：三层队列机制在（intents / proposed / 延后项表）但无单点入口，
跨会话重建靠 git log + 状态行的人肉链。

## 决定（借什么、怎么适配）

1. **`ROADMAP.md` 根部队列**（借形）：三段——队列 / 搁置池 / 维护规则。
   **只写"接下来"，完成即离队**（不打 ✅——记录活在收尾 note + git，队列不积历史）；
   **队列 = 有序索引不是全文**：条目 ≤3 行（主题 / 标记 / 链接或触发条件），全文住
   `notes/proposed/` 提案或条目开工的 plan。标记制：▶ 可开工 / ⏸ 等拍板 / 🧹 卫生 / ⏳ 触发型。
2. **两道机械门禁**进 `pnpm verify`（16→18 项）：
   - `proposal-scheduled`：`notes/proposed/` 每个文件必须在 ROADMAP 出现——提案被遗忘时红；
   - `proposal-graduated`：状态行含"已全部实施/已消化/已毕业"的提案必须离开 `proposed/`。
   首跑即红 = 活反证：tri-line 已全部实施却还赖在 `proposed/`，被门禁当场抓住。
3. **两份提案毕业**（graduated 纪律的首次执行）：
   - `2026-09-24-tri-line-synthesis.md`：已全部实施 → `notes/implemented/`，§六延后项表
     **移交队列**（⏳ 各行）并在原表加移交注记（一处事实一个家）；
   - `2026-09-23-iteration-rhythm.md`：三条归宿钉死后毕业（b 层=1e 已实施；a 层=persona
     在场；c 层=未立案有理由）——**毕业 ≠ 全部实现，而是每条有归宿**（对齐借入语义）；
   - 全仓 9 处 inbound 引用同步 `proposed/`→`implemented/`；家内 decision 记忆的旧路径
     不动（运行时状态 + commit 锚，git 历史可回溯）。
4. **fresh-agent 入口链**（本片另一半）：AGENTS.md 新增「新会话开工（先读这段）」节——
   现在与下一步的唯一权威 = ROADMAP；**不要从 git log 或记忆发明任务**；交接链 =
   AGENTS.md → ROADMAP → 条目链接。布局表加 ROADMAP 行（队列调整直接改 + 维护规则记一行）。
5. **不借的**（登记）：轮次制（对方已自行废弃——R6 后转条目制，我们从未有轮）；维护规则
   长卷（对方该段 170 行是治腐化战场——我们借形不借量，每决定一行，细节进 note）；
   `plans/roadmap.md` 路径与 guides/60 生命周期合同（我们没有对应文档层，AGENTS.md 节够了）。
6. **部分替代登记**：本决定替代 `docs/discipline.md`"已声明的适配"原第 2 条（工作队列不落
   文件——原表述见 [对齐复盘](2026-09-23-discipline-alignment.md) 逐源对照"队列不积累历史"行）
   的"无队列文件"部分；"完成的进 implemented/、不积历史"不变，那边已同 diff 收口。
