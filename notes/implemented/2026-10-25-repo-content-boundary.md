# 入库边界：三问判据 + 两道内容门禁

日期：2026-10-25 · 状态：**implemented**

## 决定

仓库只收"换台机器逐字节相同、且有人守得住"的内容。规则本体 = 根 `AGENTS.md` 硬规则 9；分类表、开源多环境
条款与机制清单 = [`docs/dev.md`](../../docs/dev.md) §八。本 note 只留取舍与代价。

触发是这一轮审计：`snapshots/` 的 web 渲染期望先被判"该不该入库"，随后扫出三类边界问题——无消费者的 306 KB
录制语料、录制语料里的宿主绝对路径、安装手册里无人守的"共 N 个条目"。三次都是同一类问题：**判据没写在纸上，
于是每个新文件重新推一遍**。

**判据（三问）**：① 换台机器是否逐字节相同；② 入库后谁保证它还是真的（门禁 / 人审基线 / 生成器 freshness）；
③ 机器相关但必须留的，是否声明"不参与判定"且消费方守约。

**为什么必须门禁化**：这三种漂移随每次迭代新增文件回来，不是一次性事故。每条边界各配一个机械检查：
「tracked files are content, not residue」（构建/运行残留 + 1 MiB 上限）与「tracked data files carry no
host-absolute paths」（录制语料在核里按路径正则显式豁免）；既有的「residue and credentials are ignored」
与「contract docs cite no machine-local absolute paths」各守另一面。

## 输掉的方案

- **只写 `.gitignore` 注释与 `AGENTS.md` 一句话，不建门禁**：ignore 只影响未跟踪文件，`git add -f` 与"本来就
  跟踪着"的路径它一概不管。这次的 306 KB 死语料和手册里的陈旧数字都是"已经跟踪着"的形态，注释型规则零作用。
- **全仓扫描宿主绝对路径**：`notes/`、`_backlog/` 的历史证据与测试夹具大量合法引用 `/Users`、`/home` 形态
  （门禁自己的正则与反例也在里面）。全仓扫要么一片假红、要么靠大名单豁免，而名单会腐。取窄面：只扫数据/配置
  扩展名，录制语料按"同目录 README 声明不参与判定"的机制豁免，正文 prose 交给既有的 markdown 门禁。
- **体积门槛设 512 KiB**：`pnpm-lock.yaml` 已经 861 KiB，会立刻假红；把锁文件列白名单又等于给"大文件"开后门。
  取 1 MiB，让门槛只拦真正的 dump。
- **把"条目数"接成门禁**：`verify` 必须在 fresh clone（`lib/` 未建）也能跑，那时 `pnpm pack` 的条目数必然与已
  提交手册不同——接了就是假红。手册侧的处理因此是**删掉这条无守卫的声明**，而不是给它加守卫。
- **在 `AGENTS.md` 复写整张分类表**：常设指令面必须无状态、短；表只有一份，住 `docs/dev.md` §八，`AGENTS.md`
  只留三问与指针。

## 后果

- 新增文件/目录先过 §八 的表；新增一类"合法例外"，同 diff 在 owning README 或表里写理由，不靠口头约定。
- 三道门禁把"反复打扫"变成"提交时红一次"：残留、超大 blob、数据文件里的宿主路径都在 `pnpm verify` 里现形。
- 未覆盖的边界：正文 prose 的宿主路径仍只由既有 markdown 门禁与 `notes/` 豁免覆盖；钉存 tgz 只按路径白名单，
  不做内容检查。
