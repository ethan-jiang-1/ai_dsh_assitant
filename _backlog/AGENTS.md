# AGENTS.md —— `_backlog/` 门牌

> 根 [`AGENTS.md`](../AGENTS.md) 管全仓；本文件拥有**五道门、状态机、翻转守卫、审查记录与去向**。
> 模板、初始 frontmatter 与字段顺序在各 README；收件与写入时机在 [`notes/AGENTS.md`](../notes/AGENTS.md)。

## 这里有什么

问题卡 `issues/`（推敲 + 收口卡）、缺陷卡 `bugs/`、调研 `research/`、方法 `methods/`、触发器账本 `triggers.md`、出口 `_archive/`。

## 两条铁律

1. 卡上的状态、方案或建议不授予实施权限（唯一例外：修复就绪的缺陷卡；边界见 [bugs/README](bugs/README.md)）。
2. 没有用户点名，不从卡片清单自行开工。

## 五道门（三轨保留自己的词）

| 门 | issue | bug | research 题 |
|---|---|---|---|
| 研究 | `推敲中` | `排查中` | `调研中` |
| 定性 / ready | `待落地` | `修复就绪` | `已定性` |
| 落地 | `待落地` 期间 | `修复落地` | 结论转卡 / note |
| 审查 / 验收 | `审查：` + `## 验收标准` | `## 修好定义` + 证据 + `审查：` | `> 结论：` + 证据评审 |
| 归档 | `已结` | `已修` / `待修` | 目录 + `> 归档：`（status 不变） |

侧态：`等人拍板`（只有用户能移动）、`叫停`（issue）、`待修`（bug）。最小链：

```text
issue:    推敲中 → 待落地 → 已结
bug:      排查中 → 修复就绪 → 修复落地 → 已修
research: 调研中 → 已定性
```

## 下一步

读 frontmatter `status`，做它指向的下一步；不要从正文重推流程。**`待落地` 是 ready，不是授权**；`修复就绪` 按缺陷修复通道（P1/P2 即授权，P0/例外走 `等人拍板`）。其余授权来自本轮请求或 [`notes/proposed/`](../notes/proposed/README.md) 卡。

- **`待落地`**：只用于 `毕业：做现在`；`## 验收标准` 非空 + `去向` 已选（值见下）+ 方案与取舍。`待落地` 覆盖整个落地期，不追「做到哪」；进度/证据住收口卡 `## 切片台账`。`以后做 / 不做 / 已在别处` 直接 `推敲中 → 已结`，不经过 `待落地`。
- **`修复就绪`**：根因有证据 + 修法选定 + 非空 `## 修好定义`；P1/P2 修复型 = 修复授权；P0 或触及 [例外面清单](bugs/README.md)（唯一正文）→ `等人拍板`。
- **`已定性`**：`> 结论：` 非空 + `> 产出的卡：` 已链 + 证据评审；最后一个活消费者离开 → 整目录归档。
- **`已结` / `已修`**：审查/跳过已记 + 业务验收（如需）+ 去向载体成立 + 归档同变更；永不重开（复发 = 引用旧卡的新卡）。

`可关闭：是` 只在归档同变更里翻；活跃卡保持 `可关闭：否`。沉默不翻转：只有用户答复移动 `等人拍板`，只有用户叫停/复活；状态行带 🔒 的触发只有用户能判。

## 审查

审查是守卫，不是状态。分三层：

| 层 | 规则 | 谁 |
|---|---|---|
| 机械 | `pnpm verify` / `pnpm test` / 适用冒烟；**不跳** | agent |
| 语义自审 | 跨面 / 持久决定 / 入口链 / 门禁与验收合同 / 文档合同 / 包公共行为 / P0-P1 → 必审；其余按风险 | agent |
| 用户验收 | 业务结果 / 产品口味 / 合规 / 阶段边界 → 请人；其余可跳 | 用户 |

记录写在状态行：`审查：agent — …` / `审查：user — …` / `审查：跳过 — 理由`。`跳过` 不写成 verified；note 的验证节只写实际跑过的检查 + 跳过理由/残余风险。

## 去向与归档

`去向` 在结论确定时写：issue 的 `待落地` 或 `推敲中 → 已结` 同一次改动，bug 的 `修复落地` 出口；值 = `implemented | proposed | rejected | deferred | none`。它决定结论住哪，不是授权。写入时机与对账见 [`notes/AGENTS.md`](../notes/AGENTS.md)：

- `implemented` → 结论进 note；`proposed` → 进 proposed 卡（**卡关闭 ≠ 批准**，毕业才写 implemented）；`rejected` → 仅防复犯价值；`deferred` → trigger/owner；`none` → 只链已有载体。
- 交接期计划路径用 inline code（`` `notes/implemented/…` ``），关闭期改 live link；`待落地` 不提前写 implemented note。
- 卡 `git mv` 进 `_archive/`，出口值在这次改动里翻；卡与去向载体同变更。关闭条件见[入口 README](README.md#关闭条件)。
