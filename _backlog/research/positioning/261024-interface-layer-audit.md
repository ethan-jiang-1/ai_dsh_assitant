# 三层界面安排审计（第一轮）

> 2026-10-24。对象 = `eff990d`（三层合同）的 dev 实例，主面板 + 一个真实 dev home
> （3 件事在账、5 条待认领、2 个日程），另起一个空 home 对照首开。
> 方法 = 代码注册面 + 真机走查（主面板 → 全部 → 完整看板；新会话 → 首开卡；会话 tab；
> 右栏 guide；设置三档；专家档；`#debug=1`）+ 文案/门的代码读回。
> 边界：第一轮**没有**覆盖窄视口、审批 dock、空会话 tab 生命周期、调试字段；这些进第二轮。
> 证据截图在 `.tmp/shots/audit-*`（机器本地，不入库），正文引用文件名。

## 0. 结论（先给判断）

**三层在主面板内部成立；离开主面板，旧的 feature silos 仍平行存在，而且各自带门。**
所以“混”不是错觉：新三层是主面板的一层新皮，旧桌面/任务/房间/插件仍是并列的顶层面，
密度三档继续扮演“用户档位”，并且**把一个调试面（Viki）交给了“专家”档**。

直接伤用户的三个问题（P0）：

1. **常用面的「它记下的」是死门。** 主面板没有右栏；点它没有任何可见变化。标准档实测
   `audit-standard-records`：DOM 文本没有知识/记忆/技能，页面不变；代码却把 `openRecords`
   接到了 `openBeside('knowledgeRoom')`（`index.ts:207`），而这个服务只在会话右栏有落点。
2. **调试面 Viki 由「专家」密度打开，不是 debug flag。** 设置原文：“专家显示全部，含 Viki(调试)”
   （`audit-settings2`）；专家档右栏 guide 实测出现 **Viki(调试)**（`audit-expert-guide`），
   而 URL 没有 `#debug=1`。这与三层合同“调试面只由 flag 注册、不是客户面”直接冲突。
3. **会话的「桌面」tab 是第二个首页，同屏两个输入。** 会话 tab 用同一个 `HomeSurface`，页内
   “还有别的事？说一句… / 交给它”下面是会话 composer“发消息或创建任务…”（`audit-conv-desk`）。
   两个输入、两种语义（`[首页]` capture vs 聊天），用户很容易用错；两个实例还有各自的选择 store。

**深看面本身也不干净**：`全部事项` 列表在 3 件事之后接了 5 条超长的「有一条还没归户的事 / 待认领」
原始笔记（`audit-list`）；完整看板仍是旧 dashboard——capture 输入、“＋交代新事项”、“有问题？跟助手说”、
“重新读取”、“让它替你盯 3 条”、看板/流水、待认领（`audit-board`）。这不是“人话的深看”，是旧操作台。

**命名至少有 7 个**：今天 / 桌面 / 桌面全景 / 你的桌面 / 看板 / 全部 / 全部事项 / 完整看板。
同一个对象，用户要在四五个名字之间翻译。

## 2. 发现分类

### A. 混层 / 重复

**A1 桌面 tab 是第二个家。** 会话 tab「桌面」渲染 `HomeSurface`，页内还有自己的输入；会话
composer 同时在场（`audit-conv-desk`）。两个输入、两个选择 store；在会话里点「桌面」看到的是
另一个首页实例，不是主面板那个。用户不知道“桌面”和“今天”哪个是家。

**A2 任务有两个顶层面。** 左栏「自动化任务」和会话「自动化任务」tab 都到任务页（`audit-conv-tasks`）；
研究的设计是“自动化任务 → 深看面的「它在盯什么」”，实现却是并列的第五个顶层面。三层合同没有它的位置。

**A3 房间是并列的右栏 tab，不是深看的「它记下的」。** 知识/记忆/技能/Viki 四个 tab 通过右栏 guide
打开；首页“它记下的”只开知识室，而且在主面板是死门（见 0.1）。研究里“四个房间 → 深看面的它记下的”
没有落地；现在是旧 feature navigation。

**A4 首开有两张面。** 空 home 是“今天 / 最近哪件事让你拿不准？”（`audit-empty-home`）；blank conversation
是“这是你的一把手桌面——三句话，说完就办 / 在办的事项…都在桌面全景里——那是账本的投影，唯一的桌面 /
打开桌面全景”（`audit-conversation3`）。后者把内部架构词（账本、投影、唯一的桌面）直接给客户，
而且“三句话”与首页“说一句”不一致。

**A5 审批有两处。** 首页审批卡（“N 页知识草稿等你审批 / 去审批”）和会话 dock 的审批 banner；
同一件事两个入口，文案不同。审批“永在常用面”是对的，但两个面同时出现会让人不知道哪个是主。

**A6 完整看板仍是旧操作台。** `audit-board`：标题“你的桌面”、统计“1 件在办 · 1 条等你确认 · 5 条待认领”、
“回到今天 / 重新读取 / 有问题？跟助手说 / ＋交代新事项”、capture 输入“有新的事，直接说… / 交给助手”、
“让它替你盯 3 条”、“看板 / 流水”、待认领原始长文。深看面里混了常用 intake、刷新工具动作、
主动建议设置、系统统计和后台碎片。

**A7 深看列表被待认领污染。** `audit-list`：标题“全部事项 3 件在账上”，下面 3 行事项 + 5 条
“有一条还没归户的事 / 待认领”的超长原始笔记（几百字一条，含“主键/归户/claim/重复留痕”）。
列表是给人读的；这些是机器/后台材料，且行数与“3 件”不一致。

### B. 越层 / 门不一致

**B1 调试面被密度档打开。** Viki(调试) 在专家档 guide 出现，不需要 `#debug=1`；设置文案明说
（`audit-settings2`、`audit-expert-guide`）。调试面的门不是权限，但它是“我们”的面；现在任何
把密度调到“专家”的客户都能打开。**这是三层合同与实现的直接冲突。**

**B2 两个调试门，两个位置。** 开发调试 tab 需要 `#debug=1`，且只在有内容的会话出现（空会话没有 tab，
`audit-debug-tab` no-debug）；Viki 不需要 flag，在右栏。一个调试用户在空会话里看不到调试面，
一个客户在专家档里却看得到 Viki(调试)。门与面都错位。

**B3 简洁“隐藏房间入口”不彻底。** 设置说“简洁…隐藏房间入口”；但首页“它记下的”始终在，点了没反应
（主面板无右栏）。简单档实测 `audit-simple-records2`：点击后页面不变、没有知识室。所谓“隐藏入口”
只隐藏了右栏 guide，没有隐藏首页的入口，也没有给它一个可用的落点。

**B4 “只影响「全部」”是歧义。** 首页“全部（3）”进的是人读列表；设置里的“「全部」的流水/主动建议”
说的是完整看板。列表本身不随密度变；被影响的是看板内部和房间 guide。文案把“全部（列表）”
与“全部（看板）”混成一个词。

**B5 三档仍是用户档位的语言。** 简洁/标准/专家三个词天然读成“新手/普通/专家”；其中“专家”
真的多给一个调试室。合同说“三档不是三层”，但 UI 的标签和门槛让它们看起来就是三层，而且第四层
（调试）藏在第三档里。

### C. 缺失 / 表达

- **C1 没有层的位置感**：首页/列表/看板都没有“你在哪一层”的提示；只能靠标题和返回链接推断。
- **C2 深看缺搜索/删除/合并记录**：列表无搜索、无删除；“它记下的”只到知识室，记忆/技能要另开右栏。
- **C3 调试面不全局**：主面板没有调试入口；调试 tab 只在有内容的会话里；空会话无 tab。
- **C4 任务未归层**：不知道属于常用、深看还是独立产品；三层合同没有它。
- **C5 空会话无 view tabs**：blank conversation 没有 对话/轨迹/桌面/任务/调试 的 tab bar（`audit-conversation3`），
  有内容后才出现（`audit-session-tabs`）。所以“桌面/任务/调试”在首开不可达。
- **C6 首开卡术语**：“账本的投影、唯一的桌面、桌面全景”是内部/架构词；“三句话”与“说一句”不一致。
- **C7 看板系统词**：“待认领 / 归户 / 主键 / claim / 重复留痕”直接给客户；数字统计“5 条待认领”抢在
  事项之前。

## 4. 建议的目标安排

**一句话：主面板是三层；会话只做编辑；所有旧 feature 面归到深看/调试，不再并列。**

1. **一个家**：主面板保留「今天 / 全部 / 完整看板」。**退役会话「桌面」tab**，换成「回到今天」按钮；
   会话不再渲染第二个 HomeSurface，也就没有两个输入。
2. **任务与房间折进深看**：深看的列表页头做三段：`全部事项 / 它在盯什么 / 它记下的`。
   任务（日程）进「它在盯什么」；知识/记忆/技能进「它记下的」；Viki **不进**深看。
   **退役左栏/会话的独立「自动化任务」顶层面**（或只留一个深看入口）。
3. **调试一个门一个面**：`#debug=1` / localStorage 同时控制「开发调试」tab 与 Viki；Viki 从三档
   guide 里移除；调试面可从主面板或一个全局入口打开，不依赖“有内容的会话”。空会话也要能进调试。
4. **密度不再是层**：要么退役，要么改名为「完整看板密度：紧凑/标准/完整」，并且只影响完整看板内部
   （流水/主动建议/房间 guide），不影响 Viki、不影响首页、不影响「全部」列表。文案不要再说“房间入口”，
   除非真的把首页「它记下的」也一起处理。
5. **首开只有一个**：空 home 的一问就是首开。会话 blank 卡改成一句指针（“回到今天，说一句就行”），
   不再讲账本/投影/桌面全景；审批 banner 保留（即时上下文），但文案与首页审批卡一致。
6. **深看去后台化**：待认领碎片移出人读列表（看板里的“后台/待归户”折叠区，或只留计数）；
   看板去掉 capture/＋交代/有问题/重新读取这些常用/工具动作，保留人话的依据、时间、下一步。
7. **命名收敛**：今天（家）/ 全部（列表）/ 完整看板（看板）/ 它记下的（记录）/ 自动化（日程）。
   退役“桌面 / 桌面全景 / 你的桌面 / 看板 / 全部事项”这些同物异名；「桌面」只在开发/内部语境保留。

## 5. 优先级

**P0（先修，直接伤用户）**
1. 主面板「它记下的」死门：要么在主面板给出可见的记录面（深看 section/独立页），要么隐藏这个入口。
2. Viki(调试) 从三档 guide 移除，改由 debug flag 控制；设置文案删掉“专家含 Viki(调试)”。
3. 会话「桌面」tab 的第二个首页与两个输入：退役 tab 或只保留一个「回到今天」，不要渲染完整 HomeSurface。

**P1（结构）**
4. 任务/房间折进深看；退役并列的「自动化任务」顶层面。
5. 待认领碎片移出列表；看板去 capture/主动建议/工具动作。
6. 密度改名/收窄；修正“只影响全部/隐藏房间入口”的文案。
7. 空会话的 view tabs 生命周期（桌面/任务/调试在首开是否可达）。

**P2（表达）**
8. 命名收敛（今天/全部/完整看板/它记下的/自动化）。
9. 首开卡术语；审批两处文案一致；调试面全局入口；列表搜索/删除。

## 6. 方法与边界

- 真机在 dev home（3 件事 + 5 条待认领 + 2 个日程）上走；空 home 只用于首开对照。
- 三档都实测了 guide：标准无 Viki、专家有 Viki、简洁无房间；主面板「它记下的」在标准和简洁下都点击无变化。
- 没有覆盖：窄视口、审批 dock 的实际文案、空会话的完整 tab 生命周期、调试面板字段、移动端。
  这些是第二轮；本报告先给结构与门的一致性判断。
- 本报告是**调查**，不是实施；调整方案需要用户确认口味（尤其“退役桌面 tab / 任务折进深看 / 密度退役”）。

## 7. 第二轮待办

- 空会话 vs 有内容会话的 tab 生命周期（为什么 blank 没有 tab bar）。
- 审批 dock 与首页审批卡的文案/状态一致性。
- 800×600 / 420×900：桌面 tab 的两个输入、右栏 guide、看板是否溢出。
- 调试面板字段与 Viki 内容是否重复；Viki 是否应该存在。
- 测试资产：有没有任何 spec 能抓住“它记下的死门”“Viki 由专家打开”“两个输入”；如果没有，补哪一层。
