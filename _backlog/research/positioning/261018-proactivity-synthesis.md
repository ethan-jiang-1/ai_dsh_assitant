## 一、这次要回答的三个问题

**用户原话（2026-10-18）**：「我们历史上的 research/issues 其实已经对这个 REPO 有较好的定位，因为其实就是上层管理的助手。最近有一堆 personal agent（muse, dots 等），你先研究研究后，看看有什么可以借鉴，尤其主动性这里；其实老的 hermes 也有些，但是那个其实上手难度颇高。我们场景比较窄，但可以借鉴/吸纳进入简单交互可以帮忙，尤其主动性这里，先考虑用户体验这里。」

拆成三个可回答的问题：

1. **外部**：近月 personal agent 在"主动性"上做对了什么、做错了什么（一手为准）？
2. **老 Hermes**：它的主动性机制有哪些、为什么上手难、哪些值得吸收、哪些必须不搬？
3. **我们**：在"窄场景 + 简单交互 + 严格本地 + 单主体辅助本人"下，哪条路值得走、走多小的一步？

**【推断】问题 3 的隐含前提**：用户要的不是"更多自主"，而是"它主动帮忙这件事，在体验上要成立"。这与本仓已有的定位判据（P1–P3 / O1–O6）和 261008 已确认的权限立场一致。

## 二、先把"主动性"拆成四层（全档坐标系）

| 层 | 问句 | 用户真正关心的是 |
|---|---|---|
| **L1 触发** | 谁决定它什么时候动？ | "它会不会在我没空的时候乱动 / 该动的时候不动" |
| **L2 开口** | 动了之后要不要出声、什么时候出声？ | "会不会吵我 / 我会不会错过" |
| **L3 内容** | 出声时说什么？ | "这条值不值得我看（什么变了、为什么现在、要我干什么）" |
| **L4 收口** | 我怎么答、怎么关、怎么知道它真的动过？ | "我回一个字够不够 / 不想收了怎么办 / 它到底在盯什么" |

**为什么先拆层**：本仓现有的讨论（261005 主动性形态、261008 权限、261012 对照）分散在各层里；拆开后才能看出"我们的欠账具体欠在哪一层"，也才能对外部样本做同层对比，而不是笼统地"抄主动性"。

## 三、回答问题的起点：本仓现状（事实，指针到 baseline）

### 3.1 今天"没人开口也会发生"的 8 件事（[baseline](261018-proactivity-baseline.md) §一）

4 条各走一次真模型回合：① 养护节拍器（goal 每 5 轮，插 curate turn）；② 提案槽（goal 完成时 propose-only turn）；③ goal 自动续跑（平台，节拍器与提案槽的底座）；④ 到期排程投递（vendor schedule，重启仍投）。
另 4 条是机械刷新：摘要重算、桌面投影 30s 轮询、房间数据读回、首开条/批准横幅。

**关键事实**：这 8 条里，**唯一主对象「桌面」只承载了第 8 条的一半**（批准横幅）——其余全部落在会话时间线或看不见的地方（[baseline](261018-proactivity-baseline.md) §一/§五）。

### 3.2 三个已观察到的摩擦（不是假设）

| 摩擦 | 证据 |
|---|---|
| **开口落空**：主动简报问了本人两句，零回复；事项 5 天后仍"到期无结果" | `dev/harness-home/sessions/…/session-45e89f04…`：`[SCHEDULE REMINDER]` user/message @2026-10-13T08:24:48Z 之后，turn 2 末 assistant 两句决策问句，此后无任何真人消息；`storages/schedule.json` 的 `deliveryHistory`（scheduledAt 01:00Z，deliveredAt 08:24Z，迟到 7h24m） |
| **盯守重复**：两条同 prompt、同周一 09:00 的 weekly 落在两个会话 | 同上 `schedule.json`（`b13ddcb8`/`be578c2c` 分属两会话）；**第二条就是那次迟到投递的 turn 里模型当场 `schedule_create` 的**；机理 = 模型侧 `schedule_list` 只看当前会话（vendor `schedule/schedule/src/tools.ts:175`、`index.ts:289-312`） |
| **看不见**：桌面头部只有 `N 件在办 · N 条等你确认 · N 条待认领`；节拍器与 curate 无任何界面 | [`projection-panel.ts:276-283`](../../../packages/dsh-smart-assistant/src/client/projection-panel.ts#L276-L283)（头部块＝h1＋计数行＋按钮；行号随 desk-side-capture 推进漂移，以结构定位为准）；[baseline](261018-proactivity-baseline.md) §五 |

### 3.3 已拍板、不能碰的约束（[baseline](261018-proactivity-baseline.md) §三）

1. **权限三分**：普通进展自动留存；确认性变化只走本人明确指令；推断的重大变化只走提案（[`docs/operating.md`](../../../docs/operating.md) §二）。
2. **节律**：提醒只按本案明确委托的核对点/已确认条件触发，**不预设固定节律、不回复不升级**（261008 L267）。
3. **形态口径（261005 已写）**：晨报/巡检/催收做成**可见可开关的例行清单**，不做隐藏魔法；节奏随真实事件顺延；v1 最小主动数据集 = 行动表 due + 待拍板 + 缺的数（261005 L260-L263）。
4. **对外**：不做 IM、对外内容本人过目；推送式（不经模型回合）主动生成已被否（[晨报 note](../../../notes/implemented/2026-10-10-desk-daily-brief.md) 输掉的方案）。
5. **节律立场**：一把手与它的自然关系是"每周一坐 15 分钟 + 遇事立刻问"，"打开频率低"是设计前提而非缺陷（261005 L151-L152）。

### 3.4 一个结构性事实（决定了形态）

**【事实】本仓没有"值班面"**：排程投递依赖进程在跑（10-13 那次迟到 7h24m 就是 app 没开），平台没有常驻网关；本仓也明确不引入（[baseline](261018-proactivity-baseline.md) §二，开源档 N1）。
**【推断】因此我们的主动性形态应偏"打开时补一次 / 放在待看的地方"，而不是"实时推送"**；这与外部四家"送达＝放进一个待看的地方"的做法天然同向（[UX 档](261018-proactive-ux-mechanics.md) §三.3）。

## 四、回答问题一、二：外部逐层答案（事实，指针）

### 4.1 personal agent 的六条共性（[UX 档](261018-proactive-ux-mechanics.md) §三）

1. 主动性被产品化为**具名管理页**（Lindy Routines、Claude Scheduled、ChatGPT Scheduled、Muse Goals），不是开关、不是隐藏智能。
2. 被产品化的触发**只有两类**：定时 + **人可读的事件过滤器**（Lindy Smart Filter 原话 "so it doesn't fire on everything"）。**空闲巡检只有 dots 有，且限只读**；Claude/Lindy 文档里根本没有这一类。
3. 送达＝"放进一个待看的地方"＋**只在"完成 / 需要你点头"两个时点出声**；Lindy 更进一步：做完**默认不汇报**。
4. 审批是**逐任务 × 逐对象的分档**，且都区分"这一次"与"以后都这样"；硬底线一致：**不可逆动作任何档位都要问**。
5. **没有人做打扰预算**（四家文档对静默时段/次数上限零命中）；可查的"预算"全是算力额度；降噪靠机制：变更检测、批量摘要、一句话关掉一类通知。
6. 官方把"无人看管"与"审批疲劳"写进文档明说，共同句式是"别把不可逆的事放进无人值守通道"。

### 4.2 老 Hermes：机制不少，但主动性=常驻网关（[开源档](261018-oss-proactivity-mechanisms.md) §二）

- **机制**：H1 cron（gateway 60s tick）/ H2 会话级心跳（idle-only）/ H3 webhook / **H4 预检脚本 `{"wakeAgent": false}`**（不叫醒模型）/ **H5 建议面**（consent-first、`MAX_PENDING=5`、`dedup_key` 永不再提）/ H6 轮后背景 self-review（直接写记忆/技能）/ H7 curator（**空闲触发，非 cron**：7 天间隔 + 2 小时空闲 + 首次运行推迟一个周期）/ H8 kanban。
- **上手难的来源（可指认，不是感觉）**：配置参考单页 247KB / 142 节；示例 config 28 节、`.env.example` 563 行；十几个概念同屏；**"要主动性就必须跑 gateway daemon"**；文档站 511 页，quickstart 自己写"先跑通一次正常对话，再加 gateway/cron"。
- **【推断】一句总结**：Hermes 的主动性价值集中在"机制库"，成本集中在"必须有常驻服务 + 平台投递面 + 一整套配置"。我们场景窄、单主体、本地，**取它的机制，不取它的形态**。

### 4.3 同类开源里可搬运的（[开源档](261018-oss-proactivity-mechanisms.md) §四）

M1 变化门（巡检先跑便宜判定，变了才叫醒模型）｜M2 静默标记 + **失败一律投递**｜M3 建议而非代劳（consent-first、去重闩、待处理上限）｜M4 空闲触发 + 首次宽限｜M7 并发模式默认 single + 记警告｜M9 心跳重锚不积压｜M5 git 即回退 + "什么不进仓"清单｜M6 记忆分层（根文件常驻、带索引的子目录不进上下文）。
**明确不搬**：N1 常驻 gateway/平台投递面；N2 记忆沉淀进 SQLite/向量库；N3 让 agent 自己排班（Hermes 同名开关**默认 false**）；N4 多租户云 cron 机械结构。

### 4.4 逐层对照：我们欠在哪一层（合成）

| 层 | 外部做法 | 我们的现状 | 判定 |
|---|---|---|---|
| L1 触发 | 定时 + 人可读事件过滤器；无人值守限只读 | 有 4 条真触发（节拍/提案槽/goal/排程），但**用户看不见、开不了、停不了** | **欠"可见与可控"，不欠触发** |
| L2 开口 | 放进待看的地方；只在完成/需点头出声 | 有"无事一句话"的口径，但产出落在会话里，桌面不知道 | **欠送达面** |
| L3 内容 | 为什么现在 + 结果导向 + steerable | 261008 已定"四问"，但没有载体落地 | **欠落地** |
| L4 收口 | 一键答、一次性≠改规则、管理页、失败必出声 | 提案有"等你确认"；**请示没有未答状态**；投递迟到/失败不可见；重复不可见 | **欠收口（最重）** |

**【推断】结论：我们不缺主动性，缺的是主动性的"脸"（L1–L3 的可见与送达）和"收口"（L4）。** 这也解释了两个观察到的摩擦：简报落空（L2/L4）、重复排程（L1/L4）。

## 五、回答问题三：候选路线与判据

### 5.1 四条候选路线

| 路线 | 一句话 | 新增机制 | 与已拍板约束 |
|---|---|---|---|
| **A 可见化与收口**（建议） | 把已有主动性搬到桌面：它替你看过 / 它在等你 / 让它替你盯；自主度不变 | 1 个客户端纯核 + 1 条桌面行 + 3 条具名建议 + 1 段模型侧红线 | 一致（不预设节律、不新增对外、不改权限） |
| **B 加自主度** | 到期自动巡检、无人值守自己决定盯什么/做什么 | 新触发器 + 新权限档 | **相抵**：与 261008"不预设固定节律/不自动升级"直接冲突；本地无值班面；重复已实证 |
| **C 维持现状** | 主动性留在会话里，等真用出更大摩擦再说 | 0 | 一致，但已观察到的摩擦（落空/重复/迟到不可见）继续 |
| **D 换触发面** | 把节拍器/投递从"轮次/钟表"改成"空闲触发 + 首次宽限"（Hermes curator 式） | 1 个空闲判据 | 一致，但收益面窄（只治"在人干活时插养护"） |

### 5.2 判据矩阵（自评，供评审攻击）

| 判据 | A | B | C | D |
|---|---|---|---|---|
| 覆盖已观察摩擦 | 三条全覆盖 | 只覆盖"没自动动"这一条（而它未被观察为核心痛点） | 0 | 1/3 |
| 与约束一致 | 一致 | 冲突 | — | 一致 |
| 新增机制数 / 可回退 | 少 / 纯只读易退 | 多 / 权限面难退 | 无 | 少 |
| 验证成本 | 低（纯核 + shots + 零模型调用比对） | 高（行为 + 权限 + 安全） | 无 | 中 |
| 用户可见收益 | 立刻可见（打开桌面就有） | 需要信任才敢用 | 无 | 几乎不可见 |
| 被外部样本支持 | 六条共性里五条同向 | 只有 dots 做且限只读，官方自己劝退 | 与 Pulse 教训相反（不做=放弃 steerable 的主动权） | M4 支持 |

**【推断】选 A**；把 D 里的"空闲触发"作为**独立评审项**单列（它动的是养护节拍器，不属本次主刀）；B 保留为"明确不采纳并写明理由"，C 替身为"A 的最小版：只落片 1"。

### 5.3 选定路线（A）的四片

1. **片 1 桌面「它替你看过」**：两个**已有**只读源（账本投影 v2 + 平台排程全局目录 `remote.schedule.catalog`）在客户端合并成一条三行式；派生走纯核；零 token、零写入、零新工具。
2. **片 2「让它替你盯」**：≤3 条具名建议；每条"先试跑一次"（只读、不建排程）与"替我盯上"（一键接受才建，走既有面板代发车道）；忽略即封口；未答请示走 question 交互（`tool-ask-user` 在组合在场，已核 `--dump-config`）。
3. **片 3 无人值守 turn 红线**：允许读 / `note` / `propose` / "建议盯守"；不允许 `confirm·reject·complete·revise·discard·claim·promote_page·land_skill`，**也不自动新建常态排程**；失败一律出声。
4. **片 4 带触发**（明细/失败可见化/平台缺 `pause` 记上游）。

## 七、反证与风险（每条给缓解与退出）

| # | 风险 / 反证 | 依据 | 缓解 / 退出 |
|---|---|---|---|
| R1 | **可见化不改变行为**：桌面多一行，人还是不看 | 本仓无任何真人读数（[baseline](261018-proactivity-baseline.md) §四/§六；输入观察 30 天窗口实际未启动） | 明说本卡不承诺效果；先落片 1（零成本），用走查 + 本人日常使用判口味；不达标就删行退场 |
| R2 | **桌面条变成噪音/免责声明** | Pulse 被下线；四家都在治噪音 | 三行上限 + 全空不渲染 + 每行恰一个动作；文案守四问；片 1 不新增通知 |
| R3 | **确定性行误报**（时间/时区/回执语义） | 本仓刚有过"模型时间词汇漂移"类 bug（BUG-015） | 判据写死并进纯核测试（边界、时区、已了结不出现）；文案对"迟到"只说事实不归因 |
