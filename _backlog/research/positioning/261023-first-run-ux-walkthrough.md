# 首开体验走查：一屏功能是怎么堆出来的

> 2026-10-23。为 [首开重做卡](../../_archive/settled_issues/261023-first-run-ux-reframe.md) 收集；本档只做证据与推敲，
> 不是实施提案，也不构成任何落地授权。用户当天原话：「一启动插件之后就有点不知所措……堆叠了一堆功能，
> 但体验上它就是让人手不知道哪着手」「感觉要费太大的力气消化了」。

## 1. 要回答什么

1. 一个全新用户打开这个插件，实际看到什么、被要求做什么？
2. 「不知道从哪下手」是缺一张引导卡，还是信息架构的问题？
3. 若要做结构性调整，有哪几条路、各自代价与风险是什么？
4. 哪些结论已经足够硬，可以进 issue 卡；哪些还得继续想？

## 2. 走查方法与现场

- 空 home：`ASSISTANT_DSH_HOME=.tmp/ux-fresh-home bash dev/env/start.sh`
  （四房间为空、无 desk 文件、账本空；preflight 绿）。
- 三屏截图 + DOM：`pnpm shots '<URL>' --dom --size 1600x1000 --name ux-fresh-desk|ux-fresh-blank|ux-intake-entry`
  （落 `.tmp/shots/`，随清扫回收；本档保留结论与 DOM 文本，不链接易失文件）。
- 一次真模型回合：`node dev/probes/web/webui-loop-probe.mjs '<URL>' --ask '我下季度销售掉了20%，帮我看看该怎么办' --home .tmp/ux-fresh-home`
  （PASS；会话日志 `session-2da25a77…` 可读）。
- 对照：M2 简洁档真机截图（`.tmp/shots/m2-simple2-1600x1000.png`）与
  [三档界面决定](../../../notes/implemented/2026-10-23-ui-modes-and-panel-surface.md)。

### 现场 A：空桌面（启动默认）

- 标题「你的桌面」，统计行「0 件在办」（空账本）。
- 捕获行「有新的事，直接说…」+「交给助手」+ 一段解释「轻的走这里……要正式立项用「＋ 交代新事项」当面谈」。
- 「让它替你盯 · 3 条」：到期核账 / 每周对账 / 每天看桌面，每条都有「先试跑一次」「替我盯上」「×」。
- 空态句：「还没有经营事项资料。交代一件试试——它会被记进权威账本，事事有着落。」
- 首开还被 DSH 自己的「预览版说明」与「开始使用」弹窗盖住（harness 面，不是本插件）。

**DOM 计数**：桌面上 15 个 `button`（含弹窗「继续」）；不含左栏导航。业务数据为 0。

### 现场 B：空白会话（点「新会话」或「＋交代新事项」）

- vendor hero「探索未至之境 预览版」；工作区/助手 preset 两个 chip；模型选择器；
  composer 占位符是开发者语言「描述你想要构建的内容, / 调用指令, @ 文件或对话」，左下「工作区内修改」。
- 插件卡：「这是你的一把手桌面——三句话，说完就办」＋「在办的事项、等你确认的、快到期的，都在桌面全景里
  ——那是账本的投影，唯一的桌面。」＋「打开桌面全景」＋「有新的事，直接在下面说」。
- 真正设计的 Day-0 文案（「第一次来？说一句话，它先问你。」＋示例＋「开始第一件事」）**不出现**。

### 现场 C：真发一个问题

- 输入：「我下季度销售掉了20%，帮我看看该怎么办」。
- 模型分 3 步：查 memory（0 条）→ 加载 `management-breakdown` → 查 knowledge（无匹配）→
  加载 `decision-routing` → 产出答复。
- 首答 **2055 汉字 / 44 行 / 6 个小节 + 1 张 6 行动作表**：5 个原因假设、3 个视角、6 个动作、
  末尾 3 个口径问题。
- 质量不差；但这是「咨询报告」，不是「一次对话」。末尾说「我可以把『下季度销售恢复』作为一个事项放到桌面上，
  设 48 小时检查点——你说一声即可」——界面上没有承接这句话的按钮。

## 3. 五条可观察事实

1. **首屏是仪表盘，不是入口。** 空桌面上 14 个操作控件（另有 1 个系统弹窗按钮），业务数据为 0；
   用户先看到机器，后看到价值。
2. **唯一解释「第一句话说什么」的卡不可达。** `hasDesk = Object.keys(walk.data).length > 0`；
   rooms 路由即使四房间全空也返回带键对象 → Day-0 分支永远不走。空 home 看到的是「有桌面」文案。
   已立 [BUG-025](../../_archive/fixed_bugs/BUG-025-first-run-day0-unreachable.md)。
3. **两个主对象互相指路。** 桌面 →「＋交代新事项」→ 空白会话 → 卡片「打开桌面全景」→ 桌面。
   每一面都把用户推给另一面，没有一条路通向「先做成一件事」。
4. **人面没有能力菜单。** 模型侧 15 个技能、6 个工具（[package-catalog](../../../docs/package-catalog.md)）；
   人侧只有「有问题？跟助手说」和一个空输入框。用户必须先知道该问什么，能力才存在。
5. **首答密度与界面密度同源。** 2055 字是「一次给完」的默认；用户要的是「一次一步」。

## 5. 机制诊断

1. **两个产品塞进一个壳。** 会话（聊天）与桌面（经营账本）都自称主对象：各有输入、空态、词汇与导航。
   用户要先理解二者关系，才能开始做事。
2. **流程先于价值。** 事项/认领/确认/核对点/在办/流水是任务管理系统的名词；第一天账本为空，
   仪表盘只能展示机器。价值（它替你想清楚一件事）要等用户先学会流程才出现。
3. **能力只在模型侧。** 15 个技能是模型的路由表，不是人的菜单；人面没有「雇它做这件事」的动词。
4. **历次 UX 修复都在缝上加卡。** 首开条、审批 banner、主动建议、捕获行、三档界面、命令——
   每次单独合理，但它们没有共同 owner；首屏是这些独立决定的累加。三档是止痛药：
   M2 简洁档把按钮 15→6，但它是选装（默认标准），空态仍无第一件事的引导。
5. **输出密度没有被当成 UX。** 首答一次给完，用户要自己拆成下一步；「聪明」变成了消化负担。

**历史重复**：同类症状已出现三次——[首开卡](../../_archive/settled_issues/261001-first-open-ux.md)、
[Day-0 intake](../../../notes/archived/2026-10-05-day0-intake-first-conversation.md)、
[桌面主对象化](../../../notes/archived/2026-10-06-desk-primary-view.md)。每次都以「再加一张卡/再换一个视图」收口。
这一次若仍只在缝上加东西，大概率第四次复发。

## 6. 目标用户与形态：一页纸（推荐）

### 6.1 目标用户的硬约束

用户 2026-10-23 原话：「我们的用户其实说实在对 AI 是不熟悉的，都是高层管理，你让使用的代价过高，
那你这套程序就已经是个废物了。」结合既有 CEO 研究（[视角合成](../../_archive/research/positioning/261005-ceo-viewpoint-synthesis.md)、
[外部首跑模式](261005-external-ux-patterns.md)），把约束写成可检查的六条：

1. **零学习**：第一小时不引入新名词（账本/投影/事项/认领/在办/流水/房间/技能/模式），一律用日常词。
2. **零配置**：不连邮箱/日历/IM（产品边界也不许），不选模型/工作区/模式；打开就能说事。
3. **输入税 ≤ 1 句**：第一次只要说一句。不做三问访谈、不做表单、不做「请介绍一下你的公司」。
4. **第一产出 ≤ 5 分钟**：一页能读的东西，不是聊天记录，也不是仪表盘。
5. **一屏一个决定**：任何时刻屏幕上只有一个「下一步」；其余是文字链。
6. **深度按需**：默认给结论；要看分析再展开；主动性只在具体一件事上问，不泛泛推荐。

### 6.2 一句话形态

这个产品不是「一张桌面 + 一堆房间」，而是**一把手的一页纸**：每次打开，屏幕上只有当前最该看的那一页；
它把一件事变成一页决策简报，然后替你盯到有结果。**聊天是改这一页的工作台，不是家。**

### 6.3 三个密度

| 层 | 是什么 | 长度 | 谁看 |
|---|---|---|---|
| 页 | 当前这件事的一页纸：判断、三个选项、建议、缺的数、复查日 | 200–400 字 | 一把手，30 秒读完 |
| 展开 | 同一页的完整版：现象 / 原因假设 / 取舍 / 来源 | 1 页 | 要追问时 |
| 对话 | 改这一页的工作台：一次一个问题、一次一个动作 | 3–5 轮 | 想深聊时 |

关键：**页是产物，对话是编辑**。现在的产品把对话当产物（首答 2055 字），所以用户要「消化」。

**不是每件事都有三个选项。** 事实/材料类（「这份合同有什么坑」「这单赚不赚」）用同一骨架的简版：
答案 + 依据 + 下一步；不硬造决策选项。页的形状随任务类型变，但**一页、结论在前、可展开**不变。

### 6.4 首 10 分钟（空 home 的真实脚本）

- **0:00 打开**：主区一页，标题「今天」，中间一行问句「最近哪件事让你拿不准？」；
  下面 3 个示例 chip：销售掉了 / 报价接不接 / 老客户涨价；一个输入框「说一句就行」。
- **0:30**：用户点「销售掉了」，或说一句。
- **0:30–1:30**：页面变成「正在做」——一张骨架卡，写「我在拆：这件事的三种可能原因」，
  下面「大约 1 分钟」。不是转圈，也不是「已交给助手」。
- **1:30–2:30**：第一版简报出现：结论一句话、三个选项（各带代价）、我的建议、还缺的一个数、复查日。
  底下一行小字：「三条假设：……哪条不对，直接改」。
- **2:30–5:00**：用户读；点「改一改」→ 对话打开并带着这一页；说「第二条不对，客户没丢，是延期」→ 页更新，
  不需要重新解释背景。
- **5:00–6:00**：用户点「就这么办」→ 页上出现「已记下：你选了 B；我 48 小时后核对」；
  可选「替我盯着」。
- **6:00–10:00**：用户可以说第二件事；页面变成「今天 1 件 + 它在盯 1 件」，或直接关掉。
  **没有教程、没有 mode 选择、没有房间。**

### 6.5 稳定态（第 2 天以后）

- 有在办：一页当前事 + 一行「还有 3 件」+ 一个输入。
- 没有在办：一句「今天没有要你拍板的。昨天我核了 2 件，1 件有结果」+ 输入。
- 有到期/等你确认：这一页就是那件事；不另开通知中心。
- 想看全部：右上角「全部（4）」→ 简单列表（标题 + 状态 + 日期），点开回到那一页。
- 想看它记了什么：右上角「它记下的」→ 记忆/知识各一个搜索框，不是四个 tab。

### 6.7 被拿掉的东西（以及去处）

| 现在 | 去处 | 理由 |
|---|---|---|
| 看板 / 流水 / 筛选 | 「全部」列表 | 高层不需要项目管理视图；列表够用 |
| 待认领碎片 | 后台；助手并进某件事或问一句 | 「认领」是系统词，不是用户任务 |
| 三条主动建议 | 删；改成具体事上的「要不要我盯」 | 泛泛建议是噪声，且首屏无内容可盯 |
| 房间四 tab | 「它记下的」一个入口 | 记忆/知识是抽屉，不是首页 |
| 自动化任务 | 「更多」 | 排程是机制，不是用户目标 |
| 三档模式 | 设置里的密度偏好；默认只有一页 | 模式是给专家的，不该是新手的第一个选择 |
| 首开卡 | 页面空态本身 | 空态已经是「它先问」，不需要第二张卡 |

### 6.8 助手的对话合同（模型面，待验）

1. **draft-first**：用户说一句，先给一版带显式假设的草稿，不先问三个问题。
   问题是用来改草稿的，不是入场券。
2. **一次一个**：一回合最多一个问句、一个建议动作。
3. **首答 ≤ 400 字**：结论 + 三个选项/建议 + 缺的数 + 复查日；展开由用户点。
4. **说人话**：不用「账本/投影/归户/认领/在办」；用「这件事 / 我记下了 / 我替你盯着 / 到期我来找你」。
5. **承诺可承接**：凡是说「我可以……」，界面上必须有对应按钮；没有按钮就不说。

### 6.9 为什么这是 A 的收敛，而不是 A

A 说「桌面＝今天这一件」，方向对，但「一件」仍是一张任务卡；对高层来说，「页」更接近他们的工作产物
（备忘录 / 决策简报）。页有三个好处：它是一份可以读、可以转、可以打印的东西——价值可见；
它天然有结构（判断/选项/建议/缺数/日期），把 2055 字的报告压成一页；它让对话退回编辑层，
不再和「家」争主对象。

B（会话优先）的问题不变：vendor 的空白会话是开发者语言，且聊天记录不是高层要的产物。C 不够。

**页还是学习与信任的载体。** 用户改一句（「第二条不对，客户没丢，是延期」），助手把这条偏好记进记忆，
下一页显示「按你上次的标准：先看客户级数据」；页上每个数字可以点开看来源。P2/P3 的「越用越像本人」
与「可追溯」因此有了可见的落点，而不是藏在房间里。这是页比仪表盘更强的地方：仪表盘展示状态，
页展示**判断**，而判断正是可以学、可以纠、可以署名给某次对话的东西。

### 6.10 四条不变量（不变）

1. **一屏一个主动作**（primary action ≤ 1；其余降为次要文本链）。
2. **先给价值，再给机器**（看板/流水/房间/主动盯只在有内容或用户主动展开时出现）。
3. **助手提议，界面能一键接**（消息上的结构化动作可点，点了有可见回执）。
4. **深度按需**（首答只给结论 + 一个问题 + 一个动作；展开由用户要）。

### 6.11 可行性掂量：账本现在装不装得下这一页

账本当前装的是：`title` / `summary` / `responsible` / `status` / 四种业务时间 / `evidence` / `proposals` / 回执
（[operating.md](../../../docs/operating.md) §二）。页要的是：**判断 / 三个选项（各带代价与可逆性）/ 建议 /
还缺的数 / 复查日 / 来源**。差三样：选项结构、建议、缺数清单。

三条落法：

| 落法 | 做法 | 代价 | 何时用 |
|---|---|---|---|
| a. summary 装简报 | 模型把一页写进 `summary`；页渲染 summary + 时间 + 证据；三个按钮只做路由 | 零 schema 变更；页是「摘要卡」不是「结构化一页」 | **v0 验证形态** |
| b. 新 `brief` 字段 | matter 加 `brief{verdict,options[],recommendation,missing[]}`；工具、投影、解析器、测试同改 | 账本 v3 + 迁移 + 约 1 周 | 形态被 v0 证明后 |
| c. deliverable 文件 | 简报写成交付文件，matter 挂链接；页读文件渲染 | 要打通文件读取/权限/版本；按钮最难映射 | 需要可转发/可打印的正式件时 |

**建议**：先用 a 做 2–3 个真实案例的纸面/真机走查——如果「一页」能让人 30 秒读出判断并愿意点按钮，
再付 b 的成本。c 不当第一步：它把「页」变成文档系统，偏离了「打开就看到当前这一页」。
**按钮的映射**也要先想清：`就这么办` 是确认 pending 提案、还是发一句话？`先放着` 是设核对点、还是静默？a 阶段
只能路由到对话，b 阶段才能做真正的结构化动作——这正是 b 的价值，不是 UI 装饰。

**三案例走查后的修正（2026-10-23）**：知识房间已经有 `type: decision-memo` 的一页纸落点——
`project-economics` / `market-sizing` / `finance-compliance` 三个技能都要求 `assistant_reflect save_page`
写这种页（sources 必填，draft 直到本人批准）。所以 **B 的 v0 首选不是新字段**，而是：
**常用面的页 = 账本 `matter.summary`**（200–400 字，带判断/三条路/建议/缺数/日期），
**深看面 看依据 = matter.evidence + 已存在的 decision-memo 页**（完整一页 + 来源）。
v3 `brief` 只在 summary 装不下结构化三选项、或页上按钮需要选项级写入时才需要。
这样 v0 的账本/投影/解析零 schema 变更，只改客户端渲染与模型写法。

### 6.12 层次表达：常用 / 高级 / 调试（用户 2026-10-23 追加）

用户原话：「留个调试的口子……有些高管比较聪明，可能能从高级那边看点东西……调试过程中我也需要看到一些东西。
我们以前的做法是把所有东西都展示出来了，这确实不太适合。……留在常用的高管手上，或者有些是为了辅助我们调试
看内部的，把它区别出来。第一个版本这些东西都有，只是高管不用那个调试或者高级的接口，因为它是独立的一个 tab
里头还是哪个地方的一个表达……我们有层次的表达。」

**核心判断：层不是密度，是「谁在问什么问题」。** 旧的简洁/标准/专家是同一屏的疏密滑杆；
新的三层是三个不同的门、三个不同的问题域，默认面不出现另外两层的东西。

| 层 | 回答谁的问题 | 入口 | 默认 | 看什么 |
|---|---|---|---|---|
| **常用面** | 我该拍什么板？它替我做了什么？ | 主区一页 | **是** | 一页纸 + 一个输入 + 「全部 / 它记下的」 |
| **深看面** | 它凭什么这么判断？我还想深看 | 页内「看依据」、「全部」、列表里的「完整看板」 | 不挡路，随时可点 | 完整简报、依据、来源、列表、完整看板、房间 |
| **调试面** | 系统现在到底在干什么？ | `#debug=1` 或 localStorage 置标志后出现的「开发调试」tab | 否（dev flag） | 投影/账本 JSON、revision、session id、工具调用与耗时、错误、feature flags、探针链接 |
| **原始出口（调试面内）** | 给我原始文件 | 调试面里的下载/路径 | 否 | `ledger.json` / 投影 JSON / 会话日志 |

**七条层次规则：**

1. **层不是密度**：不是同一屏多显示少显示，而是不同的门、不同的问题；层与层不共享主视觉。
2. **默认面零调试**：常用面不出现 JSON、revision、session id、工具名、模式名、「调试」字样。
3. **高级不是第二产品**：深看面只加深当前这一页（依据/假设/历史/原文），不引入看板/房间/任务这些新主对象。
4. **调试必须显眼是调试**：调试面有独立标题「开发调试」与不同底色，只读为主，不伪装成产品功能。
5. **可回退**：调试面由 flag 关闭（刷新后不残留入口）；深看面靠「回到今天」回退，不是一个开关。
6. **呈现层不是权限层**：调试面只是把已有数据换个门展示；敏感数据的边界仍按原合同，不因「高级」放开。
7. **第一版三层都带**：常用/深看/调试都可交付；高管默认只见 常用面，聪明高管自己点进 深看面，我们开 调试面。这正是用户说的
   「第一个版本这些东西都有，只是高管不用那个接口」。

**旧面去哪（按层重排，不按模式重排）：**

- 看板 / 流水 / 筛选 → 深看面的「全部 / 历史」；常用面只留「还有 N 件」。
- 四个房间 → 深看面的「它记下的」；Viki / 诊断 → 调试面。
- 自动化任务 → 深看面的「它在盯什么」；原始排程/触发记录 → 调试面。
- 三档界面 → **退役**（或只作为 深看面 内部的显示密度偏好），不再承担「新手/老手」的分层。
- 审批 / 错误 / 风险 → **永远在常用面**，不能因为「简洁」藏掉；这是底线，不是层级。
- 首开卡 → 常用面的空态本身，不再是额外一层。

**为什么这能同时解决三件事：**

- 高管：默认只有一页，零学习；
- 聪明高管：想深看时有一扇明确的「看依据」门，而不是被迫学一套系统；
- 我们：调试面可以做得比现在更全（JSON、日志、耗时），因为它不再和高管抢首屏。

## 7. 三条路与 D 的取舍

### D. 一页纸（推荐，A 的收敛）

- 主面板 = 一页纸：空态是它先问，有内容是当前简报；看板/房间/任务/建议全部退到「全部 / 更多」。
- 聊天 = 编辑这一页的工作台；页是产物，对话是操作层。
- 三档退为设置里的密度偏好；默认只有一页。
- **代价**：约 2–4 周（S0–S2）；**风险**：① 模型能否稳定产出好的一页（draft-first 的行为要训）；
  ② 页的数据从哪来（账本 `matter` 的 summary/proposals/evidence 够不够，是否要新 `brief` 字段）；
  ③ 30–90 秒的异步等待体验。
- **理由**：最贴近高层的工作产物（备忘录/决策简报）；输入税最低；把 2055 字压成一页；
  账本仍作为底层，不丢已交付的连续性机制。

### A. 桌面＝「今天这一件」（D 的前身）

- 主面板从仪表盘改成**一屏一事**：空态 = 它先问；有内容 = 下一件事卡 + 一个输入 + 「其余 N 件」。
- 看板/流水/筛选/主动盯/房间收进「全部事项」「更多」；新 home 默认简洁档。
- 会话不再是并列主对象：从卡片「和助手谈这件事」进入，会话里带这件事的上下文条。
- 助手提议的动作在消息上一键承接（收进桌面 / 设检查点 / 记住）。
- 首答限长（模型面：首回合 ≤ 400 汉字 + 最多 1 个问题 + 最多 1 个动作）。
- **代价**：约 2–3 周（S0–S2）；**风险**：若用户根本不想维护一件事清单，它会变成更精致的任务管理器。
- **与 D 的差别**：A 的「一件」仍是任务卡；单做 A 会得到更精致的任务管理器，仍不像高层要的产物。

### B. 会话优先，桌面退居二线

- 启动进会话，助手先开口；桌面降为按需面板；房间只从「更多」进。
- **代价**：约 1 周；**风险**：空白会话的 hero/composer 属 vendor，插件只能加 dock 卡，「家」的质感天生弱；
  账本与投影的投入变得不可见；「第一句话说什么」仍要靠模型开口。

### C. 只修引导与文案

- 修 BUG-025、空桌隐藏看板/流水/建议、默认简洁档、把「账本投影」等词换成人话。
- **代价**：1–2 天；**风险**：两对象互指、能力菜单、首答 2055 字都不动，大概率复发。

## 8. 还没想清楚的（设计议程）

这些想完，结论才能进 issue 卡；现在不写规格：

1. **页的数据从哪来？** 账本 `matter` 的 summary/proposals/evidence 够渲染一页吗？
   要不要新 `brief` 字段（判断/选项/建议/缺数/日期）或把页存成 deliverable 文件？迁移成本？
2. **异步态**：模型回合 30–90 秒，页面怎么显示进度、失败、重试？能不能在回合结束前拿到中间产物，
   让「正在做」不是假动画？
3. **draft-first 的模型行为**：一句输入能产出多好的 v0？假设怎么显式标注？eval 题集怎么建、怎么判好坏？
4. **页上的三个按钮各写哪里**：「就这么办」是 ledger confirm 还是发一句话？「改一改」是开对话并带上下文？
   「先放着」是 remeasure？失败怎么显示？
5. **页与对话的上下文同步**：对话里改了，页怎么刷新？页上改了，对话怎么知道？同一件事会不会出现两个版本？
6. **「全部」与「它记下的」的信息架构**：列表多少条、怎么搜、怎么删、怎么跳回页？
7. **老用户与已有账本**：已有 matter 怎么映射成页？历史 activity 放哪？没有页的旧数据会不会消失？
8. **vendor 外壳**：左栏「插件/工作区/自动化任务」、模型选择器、开发者占位符——哪些能藏、哪些只能忽略？
   Desktop app 是否比 Web 更干净？这决定产品的「第一眼」能做到多纯。
9. **怎么量「改对了」**：到第一页的时间、首答字数、页上按钮点击率、7 天回访；
   哪些能从 session log / ledger 读，哪些要新增读数？
10. **删得起吗**：三档、首开卡、主动建议、捕获行、看板、房间 tab、任务页——退役顺序与依赖，
    哪些有别的 owner 依赖，哪些删了会有人抗议？
11. **三层怎么落地**：深看面 是页脚链接还是设置开关？调试面 是设置里的「开发者模式」、URL `?debug=1`，
    还是独立 profile/preset？v1 的 深看面/调试面 最小形态是什么？调试面第一版要能看到哪些字段（投影/账本/revision/
    session/工具调用/耗时/错误）？谁能开、怎么关、关了入口是否残留？

## 10. 三案例纸面走查（B/C 的判据，模拟）

> 目的：证明「一页纸」在三种典型任务里都立得住，并决定 B 的 v0/v3。
> 所有数字都是示例（simulated），不冒充真实经营事实；案例 1 的骨架来自 2026-10-23 真模型回合，
> 案例 2/3 按 `project-economics` / `management-breakdown` / `decision-routing` 的技能骨架写。

### 案例 1：销售掉了 20%

输入：一句「我下季度销售掉了20%，帮我看看该怎么办」。

```
Q3 销售掉了 20%                              在办 · 复查 10/26

我的判断：不是市场淡，是 1–2 个集中点。先别裁人、别降价。

三条路：
 A 48 小时拆前 20 客户 / 产品 / 渠道     代价：两天；可逆
 B 立刻降价 5% 冲量                     代价：毛利与价格体系；难撤回
 C 冻结招聘 + 保一线                    代价：慢；但保住产能

我建议 A：缺口还不知道在哪。
还缺：前 20 客户的两季收入明细。
复查：10/26（周一）

[就这么办]  [改一改]  [先放着]
```

**30 秒读数**：能不能说出「它建议我先做什么、为什么、不做什么」——能。
**它不知道的**：口径（订单/收入/回款）、同比/环比、去年是否有一次性大单；页上以「还缺」一行说明，不编数。
**深看面「看依据」**（同一案例）：

```
三条假设：
 ① 降幅集中在 ≤5 个客户或 1–2 个渠道
 ② 均价/产品结构没变，是量或客户丢了
 ③ 去年同季没有一次性大单
来源：你 10/23 的原话；Q2/Q3 订单表（未提供，标 unverified）
上一版 vs 这一版：上一版建议「先降价」，你补了「毛利底线 30%」后改成「先拆客户」
这件事怎么来的：10/23 你在桌面说了这一句；它 10/26 来复查
我还不确定：口径三问
[打开完整备忘]  [回到页]
```

### 案例 2：报价接不接

输入：一句「XX 项目报价 480 万，接不接？」

```
XX 项目 480 万，接不接？                    在办 · 复查 10/24

我的判断：按 18 人周投入，毛利 23%，低于你说的 30% 底线——不接，或改范围。

三条路：
 A 报价提到 560 万                       代价：可能丢单；可谈
 B 砍掉二期交付，降到 420 万              代价：客户可能不接受；可逆
 C 接，但写明变更单与付款节点             代价：现金先垫 2 个月；风险中

我建议 A 或 B；C 只在客户接受预付 30% 时成立。
还缺：你们的人周费率、客户预算上限。
复查：10/24

[就这么办]  [改一改]  [先放着]
```

**30 秒读数**：能说出「为什么不能按 480 万接、两条可走的路」——能。
**它不知道的**：人周费率与客户预算没给，页上标「还缺」，不编毛利结论（技能明确：未证实的单价不产生货币结论）。

### 案例 3：老客户涨价

输入：一句「老客户 A 续约，涨不涨 5%？」

```
老客户 A 续约，涨不涨 5%？                  在办 · 复查 10/30

我的判断：涨，但只对非核心 SKU 涨；核心 SKU 锁价 6 个月。

三条路：
 A 全线涨 5%                             代价：可能丢 20% 订单；难撤回
 B 核心锁价 + 非核心涨 8%                 代价：短期毛利改善有限；可逆
 C 不涨，换账期 / 交付范围                 代价：现金流更紧；可逆

我建议 B：你上次说过「老客户先保份额」。
还缺：A 的近 12 个月订单结构。
复查：10/30

[就这么办]  [改一改]  [先放着]
```

**30 秒读数**：能说出「涨哪部分、为什么不全线涨」——能。
**它不知道的**：如果没有记忆里的「先保份额」，这行会写成「没有你的旧标准，先按通用标准；
你可以告诉我一条，下次按你的来」——不冒充。

### 走查结论

1. **三页都立得住**：每页都有「判断 / 三条路或下一步 / 建议 / 还缺 / 复查日」，30 秒能读出主张；
   案例 2/3 证明非销售类任务也能套同一骨架。
2. **B 的 v0 定了**：常用面的页 = `matter.summary`（200–400 字，模型按上述结构写）；深看面 = `matter.evidence`
   + 已存在的 `decision-memo` 页。**不做 v3 `brief` 字段**；只有当页上按钮需要选项级写入时才重开。
3. **按钮的 v0 映射**：`就这么办` = 批准 decision-memo（draft→stable）+ 确认/设置 matter 核对点；
   `改一改` = 开对话并带当前页与 matter 上下文；`先放着` = 保留 draft，设一个复查日。
   三者失败都要有可见回执，不能静默。
4. **深看面的差异行**需要版本信息：v0 只能显示「上一版」如果是同一会话里改的；跨会话历史要等交付物版本化。
   这一行可以后置，不阻塞常用面。
5. **页的诚实机制是「还缺」一行**：它把「我不知道」变成页面的一部分；没有这一行，页就会像编的。
   这是验收项，不是文案装饰。
