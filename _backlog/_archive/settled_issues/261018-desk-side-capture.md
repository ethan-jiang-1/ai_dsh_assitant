# 推敲：桌面侧发起——新事项在桌面上就能被收下

> 立卡：2026-10-18 ｜ 状态：已结（2026-10-18 关闭）｜ 类型：Feature ｜ 可关闭：是 ｜ 结论：4 项判定经逐条过、**本人全部拍板**（2026-10-18，均照 agent 判定；第 3 条为拍板第 2 条后修订的版本）——默认记一笔→待认领／最小信号（在途→轮到我，显形它那一句问话）／客户端回执 + 原生 `SessionStatus` 三格／两门并存且重量写在文案上。**去向**：实施切片落 [proposed 卡](../../../notes/implemented/2026-10-18-desk-side-capture.md)（五片 + 可执行验收），实施另需授权——卡上判定与提案均不授予实施权限。

**问题与期望结果：** 本人在真机桌面上提出（原话）：「桌面上要有新的 ITEM，这个流程是如何弄？原来是靠对话的，但这个切换…看着桌面有点想不起来」，并要求「东西都要显性化」。期望结果：本人**看着桌面**想起一件事时，**在桌面上就能把它收下**；收下之后，桌面**看得见它处在哪一态**（还没交出去／已交给助手还没进账／已进待认领／已成事项），既不必靠记忆，也不会被"切换"把提示源夺走。

**当前情况：** 桌面唯一的新事项入口是工具栏按钮「＋ 交代新事项」，它是一扇**通向对话的门**（点了会把主区切到会话），桌面自身没有任何就地输入位；而 Day-0 的面板反而有就地输入并**不切主区**。账本侧"捕获但未归类"已是一等状态（`note` 无归属 → 待认领），客户端→会话的投递通道与"在途不许撒谎"的冻结范式都已存在——**缺的只是桌面这一侧的位子与在途态的显性化**，不是新语义、也不是新写入面。三轮同源推敲（10-05／10-11／10-16）裁决的都是"给一扇通向对话的门"，**"桌面自己收下一句话"从未被裁决**。

**判定（4 项已全部经本人逐条拍板，2026-10-18；逐条理由、代价与可推翻点见「判定与理由」）：**
1. **默认去处 = 记一笔（→ 待认领）**，不默认立项；助手在同一回合用一句话提议"要不要立成事项"。
2. **助手立刻回话**（一句 ack + 提议），不做长处理；它需要本人回答时，桌面显形"轮到我 + 它那一句问话"（≤ 一行）。
3. **状态的家**：「刚投、账本还没动静」归客户端回执（不持久化、不进账本）；「它在跑／轮到我／它说完了」读原生 `SessionStatus` 三格（durable、非会话正文）。
4. **两扇门并存**，重量写在文案上：受理位＝记一下；`＋ 交代新事项`＝当面立项。

**下一步：** 据上述判定出实施切片 → 立 proposed 卡呈批。**实施尚未授权**（卡上判定不授予实施权限）；一次性原型可直接看着判，见「一次性原型」节。

## 已知与未决

### 现在是什么样（真机与代码证据）

- **入口是门，不是位子**：`＋ 交代新事项` → intake 臂 `startIntake()`（[desk-arms.ts](../../../packages/dsh-smart-assistant/src/client/desk/desk-arms.ts)）复用/新建会话并 `openSession` 把主区切走；本人要在**另一个面**里把话说出来。
- **桌面没有就地输入位**：`pnpm shots` 的真机 DOM 里 `textarea`／`textbox`／`contenteditable` 计数全为 0；截图上桌面主区只有看板/流水与右侧详情空态（证据：`.tmp/shots/desk-intake-1600x1000.{png,dom.txt}`，仓内临时面）。
- **Day-0 反而有，而且做法不同**：[first-mile.ts](../../../packages/dsh-smart-assistant/src/client/chrome/first-mile.ts) 有 `说说你现在要处理的事…` + 发送，`send()` 走 `sendPrompt(text, 'desktop-landing', 'desk', sid)`——**把话投进会话，人不离开当前面**。同一意图，两个年龄的界面两种待遇。
- **"捕获但未归类"账本已有一等状态**：`note` 操作在没有事项归属时被 `retain` 成 `UnclaimedMaterial`（[ledger.ts](../../../packages/dsh-smart-assistant/src/domain/operating/ledger.ts) `applyNote`，"绝不按标题匹配"）；桌面已有「待认领——还没说清是哪件事，不猜」一栏，卡片带原话、徽标、来源会话。
- **客户端→会话的投递通道已有**：`panelPromptRequest`（[room-data-io.ts](../../../packages/dsh-smart-assistant/src/client/rooms/room-data-io.ts)，`mode: 'queue'` + 来源标记 `[面板] `）；面板动作与臂的种子都走它，**不等主区切换**。
- **"在途 vs 完成"本仓已解过**：面板动作以 `pending` 冻在 DATA GATE 后，等**投影真的动了**才解冻；同处注释记录了固定延迟的代价（一条动作收到七条自相矛盾指令，2026-09-26）。
- **动作词汇已有**（[projection-panel.ts](../../../packages/dsh-smart-assistant/src/client/projection/projection-panel.ts)）：`交办立项／更新事项／记一笔／认领归户／办结`，以及 `存入待认领`。本卡要提的不是新词，是给已有语义接一个桌面入口。

### 三轮同源、结论在变

- 2026-10-05：诊断缺口在**入口编排** → 首切交 A'「它先问」（Day-0 访谈式 intake，技能 `first-conversation` 仍在）。
- 2026-10-11：真机走查发现"**真人找不到手动加事项的入口**" → 当场加 `＋ 交代新事项`（进对话交代）。
- 2026-10-16：走查判"两入口并排**保留**"，备选"给交代按钮加副标题"。
- 三轮裁决的都是"给一扇通向对话的门"。本人本次的现象与三轮**同源**，且同时构成 10-16 遗留「口味 5 问」之 #3（两入口并排第一眼会不会分不清）的答复：**问题不在两个按钮分不分得清，在于这扇门语义过重（承诺立项）、且它把你正在看的那个面夺走**。

### 被否的（不重提，理由在案）

- **桌面表单直写账本**：客户端不拥有经营权威；写入必须走 `assistant_operating` 带逐字引用与来源会话（[2026-10-11-one-operating-desk.md](../../../notes/implemented/2026-10-11-one-operating-desk.md) 输掉的方案 3）。
- **桌面内联下拉选归属 + 自动代发指令**：把桌面变成写入口、替本人**偷发**，且归属确认本身可能是一问一答，对话不该被跳过（[261012-desk-selection-contract-attach-ux.md](261012-desk-selection-contract-attach-ux.md) 输掉的方案 1）。
- **只加提示文案教本人去会话说**：死胡同依旧、负担没动（同上，输掉的方案 2）。
- **两张桌面并存 / 会话侧桌面改名保留**：同名面在本人脑海里只有一张。

### 停在别处的（不混进本卡）

- **碎片收件箱＝推迟而非否决**：随「输入边界」的 30 天观察（[261007-input-boundary.md](261007-input-boundary.md)），重开条件＝读数落账。
- **本轮读数为空**：`pnpm observe --home dev/trial-home-30d` 报会话 0、本人轮次 0、无账本、0 次入口。该条件**尚未产生证据**——本卡因此以本人证词为依据，并把"证词要与那台仪器对齐"写进验收标准（见下）。
- **待认领没有噪音出口**（"是噪音、不归户"无处可去）与 Attach UX 深化：归各自 owner，触发＝真实摩擦。

## 判定与理由（含代价与可推翻点）

依据分三层：**平台事实**读钉住的 vendor（不用二手转述）、**本账本自己的纪律**、**外部同向范式**（只作旁证，未逐字引用）。

### 1. 默认去处：`note`（→ 待认领），不是 `entrust`（立项）——**本人已拍板 2026-10-18：照此**

- **账本纪律**：`entrust` 的必填是 `title` + `summary`——默认立项等于让助手**在一句半成形的话上替本人命名**；而账本的既有纪律恰是"归属永不按标题猜"（[ledger.ts](../../../packages/dsh-smart-assistant/src/domain/operating/ledger.ts) 的 `applyNote` 注释；认领臂"未经本人确认不自行归户"，[261012 选择契约](261012-desk-selection-contract-attach-ux.md)）。且账本**没有**"提议归户"这条路：`propose` 是**事项内**变更（reschedule/checkpoint/complete/abandon），所以"这条该不该成为事项"只能由人在对话里一句话定。
- **外部同向（旁证）**：成熟做法把"捕获"与"归类"分成两步、且要求捕获侧无摩擦（GTD 的 Capture → Clarify 分步、inbox → triage 模式）。默认立项＝把第二步塞进第一步。旁证：[GTD 五步](https://www.taskade.com/wiki/productivity-methods/getting-things-done-gtd)、[inbox capture/triage 模式](https://davidamitchell.github.io/Research/research/2026-03-08-inbox-folder-capture-triage-pattern.html)。
- **代价（我接受了什么）**：待认领栏会长东西——**所以"栏卫生 + 噪音出口"是这条判定的前置**，不是可选项（见「B 的三个前置」2）。
- **可推翻点**：若读数显示桌面捕获绝大多数本就是正经事项（待认领→立项转化率高、弃置率低），默认可翻成"立项草案 + 等你确认"。

### 2. 助手立刻回话（一句），不是静默入队——**本人已拍板 2026-10-18：照此（最小信号：在途→轮到我，显形它那一句问话）**

- **平台事实**：`session.prompt` 返回 `{ accepted: true }`，其注释是"收据：一条 prompt 进入目标 Agent 的收件箱"（`vendor/dsh/packages/api/session-controller/src/types.ts`）——**"受理"是机器可读的，"我会处理"不是**。静默入队会让人分不清"它在忙"与"它没收到"（原型里 ⑥ 那一态正是这个问题）。
- **产品立场**：桌面上的一次"交代"是**对人的承诺**；好幕僚会应一声。且**静默在本产品里是新失败模式**——今天不存在：现状是当面说、当面答。
- **平台惯例（只用来定投递方式）**：DSH 忙时输入的默认行为本就是排队（`BUSY_ENTER_BEHAVIORS = ['queue','steer']`、默认 `queue`，`vendor/dsh/packages/client/ui-conversation/src/submission-settings.ts`）——排队这一层用平台惯例，桌面补的是"人需不需要知道"。
- **代价**：每次捕获起一个回合（成本与噪音）。缓解：ack 回合极短（记一笔 + 一句提议），不做长分析。
- **可推翻点**：若读数显示 ack 回合造成明显噪音或成本，可降级为"静默入队 + 在途条超过阈值未处理时显形"。

### 3. 在途的家：客户端回执 **+ 原生 `SessionStatus`**（原判已修订，2026-10-18）——**本人已拍板 2026-10-18：照修订版**

- **原判**：在途＝客户端内存回执（不持久化、不进账本、不读会话）。
- **修订缘由**：第 2 条拍板选了"最小信号"（桌面要显形"轮到我 + 它那一句问话"），而客户端内存**刷新即失**——两条直接相冲。读完 DSH 原生状态面后，这段不必自己记。
- **修订后的判定**：只有"**我刚投、账本还没动静**"那一小段归客户端回执；"**它在跑／轮到我／它说完了**"三态**一律读原生的 `SessionStatus`**。vendor 的 `ui-session` 为每个会话给三格：
  | 原生字段 | vendor 注释 | 桌面上的意思 |
  |---|---|---|
  | `running` | 最新的运行状态 | 等助手 |
  | `pendingInteraction` | "当前等待用户交互的最高优先请求"（带 domain `kind`） | **轮到我** |
  | `completionUnread` | "在主视图之外停跑、仍需确认" | 它说完了、你还没看 |
- **零新增管线**：我们的客户端**已经注入并在用**这个服务——`desk-arms` 的 `uiSession.sessionStatus`（今天用于回桌面判据：绑定会话已停跑、无待处理交互）。
- **为什么比原判好**：原判下"轮到我"靠桌面自己记，刷新即丢；修订后丢的只是"刚投、还没落账"的短暂叙述，而"它在等我"由原生状态兜住，且它是**结构化状态、不是会话正文**——不会滑向"第二张桌面"。
- **由此得出一条设计规则**：要让"轮到我"durable，助手**必须用平台的 question 交互来问**（`pendingInteraction` 由 domain 交互设置），而不是只在正文里写一句问话——**要问就正经问**。
- **依据**：`vendor/dsh/packages/client/ui-session/src/client/index.ts`（`SessionStatus` 三格及注释）；`vendor/dsh/packages/api/session-controller/src/types.ts`（`SessionPromptRequest.mode`、`requestId` 持久化在被受理的用户消息上、ack `{ accepted: true }`、队列项 `MessageId` 与 pending 生命周期）。
- **代价**：仍不把会话正文搬上桌面——"它在问什么"只给 kind 与一行指针，问句全文要看会话。
- **可推翻点**：若在真实组合里对 intake 会话拿不到这三格（服务未挂或 kind 不出现），退回"桌面只显示在途"的最小版。

### 4. 两扇门并存，重量写在文案上——**本人已拍板 2026-10-18：照此**

- **本账本**：两个动作是两种结果（`note`→待认领／`entrust`→事项），产品也已经有两个人类词（"记一笔"／"交办立项"，`projection-panel.ts` 的 `OP_LABEL`）。合并＝让助手替本人猜重量。
- **本人的现象**：抱怨是"这扇门太重、并且把桌面夺走"，**不是**"不该有这扇门"。
- **选择契约的精神**：一个入口一个语义——契约要求每个 item 选中即有相称动作，入口同理，不该一个按钮兼两种重量。
- **代价**：两入口并排可能第一眼分不清（10-16 走查遗留 #3 未答）——用文案消歧（本产品已有"按钮 + 副标题"先例）。
- **可推翻点**：若读数显示 `＋` 极少被用、而捕获路径承担了绝大多数立项，可把 `＋` 收成受理位的次级动作。

## 方案与取舍

### 设计原则（「东西都要显性化」落成可检验的规则）

1. **捕获点＝意图发生处**：意图在桌面发生时，桌面必须收得下它；不得要求人先迁移到另一个面再表达。
2. **每一态都写明"等谁"**：一句话从"心里"到"账本"不止四态——未投递（等我）／在途（等助手）／等本人（助手有问未答）／已进账·待归户（等归户）／已成立（在办）／未成（失败或噪音），每一态在桌面上必须长得不一样，且一眼看出**现在轮到谁**。状态轴是"等谁"，不是固定的四格。
3. **不承诺未进账的东西**：在途不得长得像待归户／已成事项；桌面永远不说"已记下"，除非账本真有那一条。
4. **原话第一等公民**：不要求本人先想好标题；账本 `quote`／未认领片段的 `note` 本来就保存原话。
5. **归类是看得见的待办**：谁在等谁必须显式，不做隐形后台——**含助手的回合**：助手要问的话，必须能在桌面上看见（否则等于让人对着空气说话）。
6. **捕获不能把桌面变脏**：捕获入口的承载面必须有卫生与出口，否则"好收"会变成"越收越乱"（见下 "B 的三个前置"）。

### 选项

| 选项 | 内容 | 取舍 |
|---|---|---|
| **A 现状** | `＋` → 开会话 → 对话里说 | 违背原则 1 与 2；且已被判"只加文案"是死胡同——现状连文案都没有 |
| **B 桌面受理位 + 四态显性**（推荐） | 桌面常驻一行受理位（Day-0 的形态回到桌面）；提交＝把**本人原话**投进 intake 会话（来源标记如 `[桌面] `），**不切主区**；桌面立刻出现"在途"条，等账本出现该片段/事项后由③／④接管并高亮 | 不直写账本（写入仍走 `assistant_operating` 带逐字引用）；不偷发（话是本人打的、发送是本人按的、在途条写明已交给谁）；把负担真的移走。唯一新增硬点是②的家（下节） |
| **D 降级／过渡** | `＋` 改为就地开一条侧栏会话，不遮桌面 | 解决"看不见桌面"，但不解决"没有位子"与语义过重；B 不做时的最小改动 |
| **E 叠加（独立成立）** | 待认领栏标注来源（`来自：桌面直接交代`）＋ 补"是噪音、不归户"的出口 | 治的是另一个已登记缺口；不依赖 B |
| C 桌面表单直写账本 | — | **重提被否方案，不列入** |

### 唯一硬点：②"已交给助手、还没进账"住在哪

三个候选的取舍与依据见「判定与理由」3（判定：**客户端内存的投递回执**）。那里同时给出代价与可推翻点——本节不再复述，避免同一事实两处维护。

配套的**否定断言**（要写进验收）：刷新后桌面**不得**显示任何账本里不存在的"在途/已记下"条目。

### B 的三个前置（自审咬出来的，缺一个 B 就会被做坏）

1. **助手回合的可见性**（**已由判定 2+3 解决**）：桌面不再自己记"它问了我什么"，而是读原生 `SessionStatus.pendingInteraction`；剩下的约束是——**要问就正经问**：助手必须用平台的 question 交互追问，只在正文里写一句问话不会产生 `pendingInteraction`，桌面也就无从显形。
2. **待认领栏的承载能力 + 噪音出口（原 E，实为前置）**：今天该栏里的卡片是**助手的长篇分析原文**（真机截图两张），不是本人原话；捕获一开，短句会涌进一个"看起来像待办工作"的栏。且已登记缺口：**"是噪音、不归户"没有出口**。故：栏内要能区分"本人一句话"与"助手分析残留"，并补弃置出口——否则"好收"会变成"越收越乱"。
3. **intake 臂的"返回"语义要跟着改**：今天是"交代 → 做 → **回桌面**并选中新事项"；桌面能就地受理后，桌面不再是"被返回的地方"，而是在途条的落点与结果的接管处（`IntakePath` 的绑定/返回判据、以及"首次回复只追问不落账则不返回"这条负例，都要按新形态重述）。这是**契约改动**，不是纯加法。

### 一次性原型（让方案看得见，便于拍板）

`prototype` 技能走的是 **LOGIC 支路**（四个待拍板问题都是状态/流转，不是像素），产出一份单文件、无依赖、状态只在内存的一次性原型：

- 文件：`.tmp/prototype-desk-capture/desk-capture.html`（仓内临时面，硬规则 8；**不属于产品代码**，被清掉可随时重生）
- 打开：`open .tmp/prototype-desk-capture/desk-capture.html`；或直接进某一态 `?s=draft|inflight|asked|timeout|unclaimed|matter`
- 它会做的：按"自由试"八个按钮把状态机走一遍；右侧**状态面板**每次动作后显示「桌面这一格／投递回执／账本实有／现在等谁／**桌面诚实吗**」——把"不承诺未进账"变成一眼可判的红绿；底部四个走查页签对应上面四个待拍板问题。
- 原型里看得见的两件事：① **在途条刻意不是事项卡的形态**（虚线 + "在途/还没进账" 徽标），② **待认领栏里"本人一句话"与"助手分析残留"并排时的落差**——前者一行、带"来自：桌面直接交代"与 `认领归户／是噪音，不归户` 两个出口，后者是助手的长文。

原型的**状态机**（这才是真正要拍板的东西，原型只是把它显性化；转成耐久记录如下）：

| 态 | 谁在等 | 桌面显示什么 | 账本实有 |
|---|---|---|---|
| 未投递 | 我 | 受理位里字还在 | 无 |
| 在途 | 助手 | 虚线在途条 + "还没进账" | 无 |
| 等本人 | 我（它问了） | 在途条上显形助手的问题（或指针） | 无 |
| 待归户 | 归户（我或助手） | 待认领栏多一条短原话 + 来源 + 出口 | `unclaimed` 有 |
| 已成事项 | 办结 | 事项卡（高亮接管在途条） | `matters` 有 |
| 未成 | — | 弃置后不留痕（不进待认领） | 无 |

原型咬出来的一个边界：**刷新后投递回执消失**——若账本仍无该条，桌面**不得**再显示在途条（宁可少说，也不假称已记下）；这条正是要写进验收的否定断言。

## 验收标准

下游若实施，按下面这些算合格（本卡现在不要求执行）：

| # | 断言 | 证据形态 |
|---|---|---|
| 1 | 在桌面上就能说出一件新事，**主区不切走**（提交后桌面仍在） | 真机走查相位 + 截图，断言主区仍是桌面 |
| 2 | 每一态在桌面上**各有其形**，且写明"等谁"：未投递／在途（等助手）／轮到我（助手有问）／待归户／已成事项；且**状态取自原生**：`running`／`pendingInteraction`／`completionUnread` | 各态截图两两比对；DOM 断言在途条带独立标记（不得复用事项卡结构）+ 断言状态来自 `sessionStatus` 而非页面自存 |
| 3 | **捕获的默认结果是待认领**（不是事项卡），且助手在同一回合给出"要不要立项"的提议 | 真机走查相位 + 账本读回（`note`→`retained`） |
| 4 | **助手要问就正经问**：追问走平台的 question 交互（产生 `pendingInteraction`），桌面据此显形"轮到我"；只在正文写一句问话不算数 | 真机走查相位（投一句含糊的话 → 助手走交互追问 → 桌面显出"轮到我"）；负例：正文问话不产生该态 |
| 5 | 刷新后：客户端回执消失（桌面**不再**叙述"刚投、还没落账"），但"轮到我／它在跑／它说完了"**仍在**（原生状态） | 刷新前后两帧 DOM 比对 |
| 6 | 桌面**不承诺未进账**：账本没有对应记录时，桌面不出现"已记下"类措辞 | 负例断言（只投递、不让助手落账，检查桌面文案） |
| 7 | 归类的**待办可见**：待认领片段标明来源（含"桌面直接交代"）、能区分"本人一句话"与"助手分析残留"，且"是噪音、不归户"有出口 | 待认领栏断言 + 账本动作清单 |
| 8 | 两扇门的**重量在文案上写明**（受理位＝记一下；`＋`＝当面立项），首眼可辨 | DOM 断言两处文案 + 走查照片 |
| 9 | 与既有仪器对齐：桌面侧投递的**自发碎片**能被 `pnpm observe` 的 A 口径读到（或明确记录它读不到、并说明改用什么读数） | `pnpm observe --home dev/trial-home-30d` 读数前后对比 |
| 10 | 交付时 `pnpm verify` 全绿（新面进桌面须带选择契约断言） | 门禁链 |
