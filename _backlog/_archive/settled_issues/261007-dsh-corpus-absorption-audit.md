## 已知与未决

已核实（本卡立卡前的直读）：

- 本仓**已实质吸收**不少：`docs/discipline.md` 纪律表逐源枚举 + 六层反馈（借语料 repo-harness/05）+ 三道门禁边界；`docs/testing.md` 五台阶 / 禁令 / prove-it-red / 分层寻址；`pnpm verify` 机械链 + 负例夹具；pre-push-evidence / semantic-drift-audit 等开发技能。**问题大概率不是「没读」，而是「吸了什么形态、漏了哪条链」。**
- 语料主卷核心闭环 = 外部结果 → owner → 条件性记录 → 垂直切片 → 测试观察真实对象 → 安装形态验证 → 语义评审；核心断言 = **「能加载 ≠ 有行为证据 ≠ 能安装 ≠ 已获交付批准」四个结果须分别观察与记录**。
- 语料三卷各有立场：主卷给关系综合、sdlc 给精确条款、repo-harness 给「仓库作为开发 Harness」的参与机制（AGENTS/Skills/paved road/六层反馈/运行时查询/边界与成本）。

未决（审计要裁决的）：

1. **差距定位**：语料机制 × 本仓落点的完整对照后，哪些是漏吸、半吸、吸变形、过度吸收？

3. **瘦身面**：本仓流程文档/门禁是否已重到压制发力？承重件是否被非承重件淹没？
