# 收口：首开体验「一页纸」

> 立卡：2026-10-23 ｜ 状态：已结 ｜ 类型：Feature ｜ 可关闭：是 ｜ 毕业：做现在

> 现场与四条路 = [研究档](../research/261023-first-run-review/261023-first-run-ux-walkthrough.md)

## 外部结果三要素

- **触发**：用户第一次打开插件（空 home），以及之后每次打开。
- **用户得到**：一页当前事的决策简报（判断 / 三条路各带代价 / 建议 / 还缺的数 / 复查日），30 秒读完；
  一句话可改；一个按钮可定；默认看不到看板、房间、调试面。
- **完成条件**：2 个 fresh home 从打开到第一页 ≤3 分钟；空 home 主区控件 ≤3；首答 ≤400 字且最多一问一动；
  L2 默认不可见；审批/错误始终在 L0；`pnpm build` + `pnpm test` + `pnpm verify` 绿 + 对应 eval 绿；
  每片证据写进本卡台账。

## 已知（结论，不含过程）

1. **不是缺一张引导卡。** 首屏是历次独立修复的累加：首开条、审批 banner、主动建议、捕获行、三档界面、
   命令，各有其主、没有共同 owner；再加一张卡只会加深「堆叠」。
2. **两个主对象在互相指路。** 桌面 →「＋交代新事项」→ 空白会话 →「打开桌面全景」→ 桌面。
   没有任何一条路通向「先做成一件事」。
3. **唯一解释第一句话的卡是坏的。** 空判据读 `Object.keys`，Day-0 分支永远不可达
   （[BUG-025](../fixed_bugs/BUG-025-first-run-day0-unreachable.md)）。
4. **人面没有能力菜单。** 模型侧 15 个技能、6 个工具；人侧只有空输入框。「聪明的助手」只能靠用户凭空提问触发。
5. **首答 2055 字是 UX 问题，不只是文案问题。** 用户要「一次一步」；而模型承诺「你说一声即可」时，
   界面没有承接按钮——智能停在文字里。

## 设计判据（实施时逐条对照）

- **页是唯一产物**：页装判断/选项/建议/缺数/日期；对话是编辑层，不是家。
- **首 10 分钟可演**：它先问 → 一句话 → 异步「正在做」→ 一页 → 改一句 → 按钮 → 关掉；含失败/重试，不靠假动画。
- **draft-first**：不依赖三问访谈；假设显式；一回合一问一动；首答 ≤400 字。
- **三个按钮有契约**：就这么办 / 改一改 / 先放着，各写哪里、失败怎么显示。
- **三层表达**：L0 零调试；L1 人话深看、可关；L2 独立门、显眼「开发调试」、只读；审批/错误/风险永在 L0。
- **信息架构**：「全部」与「它记下的」有列表/搜索/删除/跳回页；不是四个房间 tab。
- **删得起**：三档、首开卡、主动建议、捕获行、看板、房间 tab、任务页——退役顺序与依赖写清。
- **vendor 边界**：左栏、模型选择器、开发者占位符哪些能藏、哪些只能忽略；不靠 CSS 隐藏冒充层级。
