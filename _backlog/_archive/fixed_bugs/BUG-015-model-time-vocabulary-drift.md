# BUG-015：模型面时点术语与日期格式漂移（合同写「核对点」，模型简报写「检查点」）

> 严重级别：P2（次要）｜发现：2026-10-16｜状态：已修（2026-10-16）｜修法：技能文本钉死术语与 ISO 口径（[决定 note](../../../notes/implemented/2026-10-16-model-time-vocabulary.md)）；真跑人工核对：禁忌写法零出现、钉死的词在用（残留：叙述里一处相对说法与一处斜杠日期，已记在 note 上）

## 症状

同一次真跑里，**同一个时点概念出现了三种写法**：

- 产品面（桌面卡片、合同 [`docs/operating.md`](../../docs/operating.md)）：**「核对」/「核对点」** ✓（ISO 日期 `2026-10-20` ✓）；
- 模型面（晨报简报的实际输出）：**「检查点」** ✗，日期也漂成 `10/20`、`10-20` ✗。

后果不是崩溃，而是**用户要在两套词之间做翻译**——对一个"读回你的事"的产品来说，这正是要避免的摩擦。

## 根因（假设）

模型面对应的技能文本（`packages/dsh-smart-assistant/presets/assistant/skills/` 下相关技能）**没有钉死时点术语与日期口径**，于是模型各自发挥 ✗。待确认：是技能没写、还是写了但被别处覆盖。

## 复现

```sh
node dev/probes/web/desk-daily-brief-live.mjs   # 相位 2 的简报文本里找时点措辞与日期格式
```

## 修复关联

- 模型用技能文本（晨报及相关经营技能）；
- **探针不加措辞判据** ✗——本仓既有教训：判据钉账本事实、不钉模型措辞（[结构还清 note](../../notes/implemented/2026-10-16-structure-paydown.md)）。所以锁的是**技能文本**，回归看人判/走查。

## 修好定义

- 技能文本钉死时点术语（与合同同词：核对点）与日期口径（ISO）；
- 下一次真跑里简报**不再出现第三种写法**（人工核对一次，不作门禁判据）；
- 改动触及**模型可见面** ⇒ 按根 `AGENTS.md` 的开工表，先立 proposed 卡呈批、等点名或点头 ✗（不自授权）。
