# BUG-023：到期 0 天；「下次替你看」可能指向过去

> 严重级别：P2（次要）｜发现：2026-10-19｜状态：已修

## 症状

- 刚过核对点 30 分钟的事项渲染成"到期 0 天，账上没有结果"（纯核已复现 `daysOverdue: 0`）。
- 一条 active 排程若 `scheduledAt` 已过去且没有 `lastDelivery`，行 3 照样说"它下次替你看：… · 2026-10-13 09:00"，没有"已过/没动"的标记（纯核已复现）。

## 根因（假设）

已确认：`daysOverdue` 用 `Math.floor` 天然落到 0，文案没有"今天/刚到点"分支；行 3 只取最早的 active，不比较 `nextAt` 与 `now`，`lateByMs` 只在有 `lastDelivery` 时才有值。后者的正确说法（过滤过去项 vs 显示"该看的时间已过"）需要一个小决定；前者只是文案。

## 复现

`deriveProactiveFace` 传入 nextCheckpoint=30 分钟前 / scheduledAt=6 天前的 active 条目，读返回行。

## 修复关联

同文件纯核；文案分支可独立修，过去时刻的口径先定再动。

## 修好定义

30 分钟内到期显示"今天/刚到点"而不是 0 天；过去时刻的行要么不出现，要么明说"该看的时间已过"；各一条纯核判据。

## 修复（2026-10-19）

- `daysOverdue === 0` 的到期行显示「今天到期」，不再「到期 0 天」。
- 行 3 新增 `overdueByMs`：`scheduledAt` 已过去时改说「它该在 X 看「title」，还没看到它动」，不再声称未来的"下次"。
- 纯核 1 案（过去时刻带 overdueByMs）+ 组件 2 案（今天到期、过去时刻文案）。
