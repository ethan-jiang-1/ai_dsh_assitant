# 原型候选：访谈、案例重放与可验证的能力积累

> 服务 [定位卡](../../plans/261005-open-value-deficit.md) 和 [自洽卡](../../plans/261005-turnaround-coherence.md)。这是可直接使用的访谈/记录/评估框架；未安装成运行时技能，也未证明访谈能提高决策效果。一手材料定位与访问限制归 [案例研究](261005-prototype-cases-and-interview-method.md)，本档拥有产品框架，不复制来源综述。

## 1. 原型现在如何推进

不等待真人给一件完整经营决定和两周回访。agent 先整理公开的一手决定/复盘，做有截止时点的情景重放，准备短访谈框架与可测试的学习变更。以后有人愿意提供片段，再增量访谈；拿不到的信息记未知，不发作业单。

公开案例只服务方法与典型约束，不是本人的公司事实。网页里高管谈自己的决策是公开案例，不是我们开展了访谈。模拟回答只能调试问题顺序、缺数处理与输出形状，不构成真实需求或能力增益证据。

### 案例记录模板（公开材料和未来访谈共用）

```text
case_id / revision:
record_kind: public_case | interview | simulated
source: URL或原始记录定位、作者/受访者身份、发表时间、抓取时间
context: 公司/职责/规模/时间，仅填来源可核部分
as_of: 决定当时的截止时点
trigger / desired_outcome:
known_then / unknown_then:
options_including_do_nothing:
criteria / constraints / reversibility:
chosen_action / alternatives_rejected:
owner / due / completion_evidence: 未披露就unknown
follow_up_signals / stop_or_change_condition:
observed_outcome / observation_time / evidence:
principal_quote / extractor_inference: 分开
scope / exceptions / contradictory_evidence:
learning_candidate / proposed_check:
```

## 2. 访谈框架：围绕一件事，而不是普遍自述

开场：“我们用一件你方便讲的事了解判断和跟进方式，不必给机密数字；不方便或记不清就跳过。先形成草稿，结束时你只需纠正最关键的误读。”实际记录/使用范围由参与者确定；本轮只设计，不联系他人。

| 顺序 | 主问（每次只问一个） | 回答后再追问 / 想获得什么 |
|---|---|---|
| 1 选事 | 最近一次你需要亲自拍板、后来还要跟进的事是什么？ | 不方便讲最近，就用以前公开/可脱敏的一件；不要求成功案例 |
| 2 触发 | 当时什么变化让你必须做决定？ | 最迟什么时候要定，不做有什么后果？ |
| 3 当时所知 | 你当时确实知道哪些事，还有什么不确定？ | 有哪份资料/哪句话影响最大？后来的发现另记，不混回当时 |
| 4 备选 | 你实际考虑过哪些办法？ | 是否考虑过等一等/不做；追问当时未选的理由，不推荐我们的选项 |
| 5 判断标准 | 最终哪条标准让你倾向这个选择？ | 你为了它放弃了什么；哪些是硬底线、哪些能谈？ |
| 6 分工 | 拍板之后，下一步是谁做、你等什么信号？ | 当时怎样记录/传达，哪里最容易丢；时间/owner不清就标缺口 |
| 7 调整 | 什么信号会让你催一下、换方案或停下来？ | 实际发生过吗，谁给信号、如何判断不是噪声？ |
| 8 结果（可跳） | 后来发生了什么，有什么材料支持？ | 尚未结束就记pending；区分结果、当时判断质量、外部运气 |
| 9 助手分工 | 在这条过程里，哪一步你愿交助手，哪一步要亲自做？ | 给一个具体输出让他删改；不问“你会不会喜欢自动督办” |
| 10 校准 | 我记到的标准是……，只在……条件下适用，对吗？ | 优先纠正1–2条可能影响后续做法的解释，允许“我还没想清楚” |

不是十问一次全发：按对方现有片段填表，只追问会改变建议的1–2个缺口。允许只完成一个3–5分钟片段。时间长度是候选交互节奏，不是研究结论。若对方不愿访谈，保留框架，不制造受访数据。

## 3. 信息如何变成未来能力

链路候选：**原始证据 → 有范围的提炼 → 知识/偏好/做法候选 → 针对性验证 → 启用 → 观察与修正**。增长是持久上下文和可加载做法的改进，不指模型权重训练，也不是增加文件数就算增长。

| 提炼内容 | 归属与候选动作 | 验证/启用条件 |
|---|---|---|
| 本人的明确偏好、事实、已做决定 | 产品 memory，注明本人原话/日期/适用场景 | 复述确认或可核明确表达；暂定、推测和别人的公司事实不能写成自己的确定事实 |
| 未决矛盾、例外、待补资料 | 产品 research | 保留冲突与来源；允许没有新知识，不强行结案 |
| 跨场景概念/方法、公开案例的经验 | knowledge draft + sources | 引用齐全、范围和反例明确；按现行本人审批规则启用，不宣称source存在已证明正确 |
| 可复用步骤、输出方式、追问策略 | skill proposal，写来源/作用范围/失败条件 | 做前后对照和未参与提炼的病例，满足约定标准才候选落地；既有手审机制不等行为测试已自动化 |
| 一次错误反馈 | 原答案/证据/纠正/影响记录 | 先诊断是知识缺失、检索失败、输入缺数、流程问题还是评价分歧，再决定是否改技能 |

不要把“某次现金压力下先保回款”蒸馏成“本人永远回款第一”。记成“某时/某项目/某约束下的偏好”；遇到例外再问范围。矛盾先保留时间和环境差异，不自动覆盖。

### 行为验证卡（候选）

```text
change_id / version / provenance:
expected_change: 从哪种错误到哪种可观察行为
scope / non_goals / failure_conditions:
baseline_output / candidate_output: 同一截止时点输入和预算
held_out_cases: 未参与规则提炼的案例/变式；公开/模拟分别标注
checks: 来源定位、缺数不编、标准作用范围、条件变化后能改变建议
regressions: 其他场景/冲突事实/撤回旧标准仍正常
cost: 追问次数、输出长度、检索量/延迟（实际执行后才有数字）
verdict: keep_candidate | revise | reject | eligible_for_review
rollback: 旧版本和引用修复方式
```

重复写同一案例不算泛化；公开企业案例的结果也不是唯一正确答案。评价应看推理是否遵守给定信息/约束、来源是否准确、能否识别未知。未来真人纠正才检验是否贴合本人，未来实际回访才检验经营采用和执行效果。

## 4. 与现有载体的关系：可承载，不代表自动闭环已建

代码/当前合同依据：[working folder](../../../docs/home.md#L72)、[reflect description](../../../packages/dsh-smart-assistant/src/learn/index.ts#L41)、[提案落地](../../../packages/dsh-smart-assistant/src/index.ts#L678)、[服务测试](../../../packages/dsh-smart-assistant/tests/host/skill-proposals.spec.ts#L47)。已存在来源必填的draft页、研究/记忆房间、propose/land和可恢复技能版本载体。

但 `save_skill` 可以直接写可加载技能（[实现](../../../packages/dsh-smart-assistant/src/learn/index.ts#L394)），提案车道不是所有写入的不可绕过守卫；`landSkill` 检查 approved 状态，不运行语义/行为回归。现有用量计数测加载，不能证明正确性或收益。完整访谈蒸馏/自动评分/受控启用还未实现，知识审批也有 [审计中指出的边界](../tech-exploration/261005-turnaround-evidence-audit.md)。

原型先用本框架做纸面/离线验证，开发材料留repo reference，不写日用dataDir。后续如要接运行时，毕业为有界实施提案：访谈输入/来源记录、四房间路由、验证集和预算、批准范围、失败/撤回/日志语义。可自主做的核查与提案生成不逐条请人；本人不可替代的是其标准、适用范围和实际纠正，不把大批评分作业抛回用户。

## 5. 现在的最小验收

- 至少两个一手公开案例，字段未知明确，决策时信息与事后结果分开；至少一个失败/反证场景。
- 对公开案例做资料层重放：列出关键追问、不同选项、缺数与跟进信号，结果材料只用于后验，不伪装模型运行。
- 一条学习候选含作用范围、条件变式/未见病例、预期行为与撤回办法；不宣称已经使助手增长。
- 框架可供未来零散访谈直接填入，真人不可用不阻塞原型方案成熟。真实采纳/长期个性化结论继续未验证。
