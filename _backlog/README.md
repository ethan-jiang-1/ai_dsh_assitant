# _backlog · 把问题想清楚

这里用卡片记录尚未确定的问题，收集依据，形成结论，再交接或关闭。做什么由用户本轮请求决定；没有点名，不从卡片清单里自行开工。落进这个区域的 agent 先读门牌 [`AGENTS.md`](AGENTS.md)——流程与状态机在那边；关闭条件、生命周期与目录约定的唯一家是本文件与各子 README。

**backlog 和 notes 不是一条管道，是两个下游。** backlog 把问题想清楚，再把结论路由到 work 或 memory：work 走 proposed/收口卡（切片台账、验收证据、开放 work 在 `_backlog`），memory 走 note 或 trigger。[notes](../notes/README.md) 只接收 memory 那一半；不是每张 issue 都会成为 note。work 由另立收口卡承载时，本卡记下去向即可按关闭条件结束，不等待实施完成；本卡自己转收口卡时，`待落地` 到交付。memory 去向记录后也不等待 note 写完。

## 入场票

**两轨共用一张入场票**：问题清楚（什么情况引出、期望什么结果、怎么算完成）+ 验收手段（决定做的事项按 [验收设计](methods/validation-design.md) 写 `## 验收标准`；缺陷卡在翻到修复就绪前写 `## 修好定义`）。票由格式承载，不由记忆承载——缺了哪半张，卡就还不算立起来。

五道门、状态机、翻转守卫、审查记录与 `去向` = [AGENTS.md](AGENTS.md)；本文件拥有入场票、关闭条件、生命周期与目录约定。推敲步骤按需查 [方法导航](methods/README.md)，路由结论见 [路由结论](methods/issue-to-note.md)。

卡上的状态、方案或建议都不授予实施权限。已由用户授权的工作按授权范围继续，不重复请求批准。**例外（2026-10-12 拍板，带范围）**：修复就绪的缺陷卡自带修复授权——除非该缺陷是 P0，或其修复触及 根 [`AGENTS.md`](../AGENTS.md) 常设指令 / [`docs/`](../docs/AGENTS.md) 合同 / 包的公开行为 / 已记录决定（notes），那些翻 `等人拍板` 走本人，或并进问题卡。严重级的消费方与翻转法见 [缺陷卡规则](bugs/README.md)。

## 缺陷怎么走

一条道（翻转表与守卫在 [缺陷卡规则](bugs/README.md)）：建卡即决定这次不修 → **排查**（「根因（假设）」到确认要有证据——一个 bundle、一段 git 历史、一次对照；被证伪的假设留在卡上，不擦）→ **修复就绪**（根因有证据确认 + 修复路径已选 + `## 修好定义` 已写；这一翻同时是车票和授权）→ **修复落地**（`## 修好定义` 满足、证据与 `审查：` 已记）→ 已修归档。查明但决定不修/延后的进待修池；本人叫停同池。`## 修好定义` 可点名验证随哪件工作走（riding 依赖），不写即兴句子。

## 关闭条件

问题已有明确结论，所需确认已得到，需要的去向（work 或 memory）已记录，才可以关闭；已有结论足以回答的，留下引用即可。不是每个问题都要实施，也不是每个问题都要成为 note。按结论检查：

| 结论 | 关闭前留下什么 |
|---|---|
| 做 | `待落地`：`毕业：做现在` + 非空 `## 验收标准` + `去向`；问题、方案、范围、真实比较过的选择及理由；work 去向（proposed/收口卡）已记录；审查/跳过已记；note 只在 notes §〇 要求时写 |
| 以后做 | `去向：deferred`；延后的理由、什么时候再看、到时观察什么；trigger/owner 已记录；条件到了新开卡并引用旧卡 |
| 不做 | `去向：rejected`（仅防复犯价值）或 `none`；原因和适用范围 |
| 结论已经在别处 | `去向：none`，指向已有决定或当前合同，说明它回答了本卡的什么问题 |

**卡与去向载体同变更**：`implemented` note / `proposed` 卡 / `rejected` 一行原因 / `deferred` 的 trigger 或 owner，与卡归档在同一次改动里落；`proposed` 卡关闭 ≠ 批准。写入时机与对账见 [`notes/AGENTS.md`](../notes/AGENTS.md)。

有了结论的卡用 `git mv` 进 [已关闭问题](_archive/settled_issues/README.md)，文件名和讨论正文保留，frontmatter 的 `status` 改为 `已结`，状态行补结论、审查与去向，修复相对链接并更新两边清单。以后出现新问题，新开卡引用旧卡。

被用户明确叫停、还没有结论的，进 [叫停的问题](_archive/suspended_issues/README.md)，`status` 改为 `叫停`；回到活跃区需要一次明确的新决定。证据或答复尚缺时，留在活跃区并写明下一步。

缺陷按 [缺陷规则](bugs/README.md) 处理：修好进 [已修缺陷](_archive/fixed_bugs/README.md)，查明但未修进 [待修缺陷](_archive/suspended_bugs/README.md)。研究题在最后一个活消费者离开时，整目录随迁到 [调研归档](_archive/research/README.md)。

## 卡的生命周期

frontmatter `status` 是当前阶段的唯一家——一个值，只在带守卫的翻转中变；状态行**镜像**它（issues 的引导词、bugs 的 `状态：` 记号、research 题名页的 `> 状态：`）并拥有**历史**——结论追加、出口补结论与去向；目录承载粗位置（活跃区 vs 归档池）。各轨的翻转表（守卫 / 谁 / 记录）分别在 [问题卡规则](issues/README.md)、[缺陷卡规则](bugs/README.md) 与 [调研规则](research/README.md)。

共享翻转法：**沉默不翻转**（等待答复不改变阶段）；**每次翻转是带守卫的动作 + 记录**；**出口值只在归档的那次改动里翻**；「可关闭：是」是出口守卫旗，与搬迁同落。状态行可带「毕业：」倾向字段，头必须是闭集 `未定 | 做现在 | 以后做 | 不做 | 已在别处`——四门就是关闭表那四行，头逼着倾向早点名；它是倾向不是阶段，不写不算错。`去向：` 与 `审查：` 也住状态行：`去向` 在 `待落地` 选，`审查` 在出口前记；两者都不改阶段。

`pnpm verify` 机械互查：清单点名、frontmatter 合法、**活跃卡**状态行与 frontmatter 镜像、闭集头合法、`待落地` 的验收与去向、`修复就绪`/`修复落地` 的修好定义、活跃 research 题名页的 status/opened/`> 状态`/`> 结论`、材料无 status。归档卡的历史状态行不回填也不复查——位置与 frontmatter 已经钉住它们，历史行是记录不是漂移。

## 文件与目录

| 位置 | 放什么 | 文件约定 |
|---|---|---|
| [issues/](issues/README.md) | 尚未结束的问题 | `YYMMDD-<slug>.md`；新卡正文可写 `Feature` / `Task` / `未定`，旧卡不回填 |
| [bugs/](bugs/README.md) | 这次不修的缺陷 | `BUG-<NNN>-<slug>.md`；下一个号在其 README |
| [research/](research/README.md) | 卡片需要的较长依据 | 按研究题分目录 `YYMMDD-<slug>/`；题名页带 `status`/`opened` 与 `> 状态 / 问题 / 消费者 / 产出的卡 / 结论`，材料 `YYMMDD-<slug>.md` |
| [methods/](methods/README.md) | 各步骤按需使用的方法 | 留在原处，持续改进 |
| [triggers.md](triggers.md) | 工作里会自然遇到的重新讨论条件 | 延后不自动加行，按该表规则收录 |
| [_archive/](_archive/README.md) | 已离开活跃区的卡片和调研 | 子目录区分有结论、叫停、已修和待修 |

新文件的 frontmatter 在各目录 README 的 `frontmatter` 节。问题、缺陷与研究题名页第一项是 `status`；研究材料第一项是 `topic`、第二项是 `intent`，材料不装 status。各 README 的清单须与目录一致，结构和链接由 `pnpm verify` 检查。卡已声明可关闭却仍在活跃区，也会被检查。

状态行带 🔒 的卡，只有用户能判定触发，详见 [问题卡规则](issues/README.md)。归档默认不展开阅读；需要某个历史结论时，从卡片链接进入。
