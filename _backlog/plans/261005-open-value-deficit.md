### 真人读数（2026-10-06，新形态首验）：「顺畅是顺畅，但是我不知道我在做什么」

**判据裁决**：「打开不困惑」**操作面通过**（首开引导→它先问→答→桌面长出→点桌面视图，全链无摩擦）；**叙事面未通过**。
这是同感家族第三次现身且已换层：①09-25「不痛不痒」②10-05「无从下手/为什么用它」（操作层）→ ③本次「不知道我在做什么」
（**操作层通了，缺的是循环与位置感**：用户不知道自己在参与什么节律、这一步之后是什么、做完该离开还是等待）。

记录与缺数，没说「今天的开场到此为止，桌面是你的起点，拍完可走」。修复候选 = 使用节律告知切片（模型可见 copy 为主，

主对象迁移（桌面为主、会话为动作）**片1 已交付**：桌面经 vendor `conversation.view` 缝升为主区 first-class 视图

以下十九轮是推敲过程，不逐段重写为今天的结论。读取旧轮次时按下列纠正边界：

- naive-CEO 是代理角色读数；trial 账面存在只证明产物形态，不是真人连续经营 n=1，也不证明“军师能力已经足够/只缺回来的理由”。
- 同一不适感反复出现支持重新检查主对象/输入成本，不足以证明唯一根因是 UI 或必须桌面先行；主对象、intake、样板间仍是候选。
- 外部 CEO/GM/SaaS 样本启发目标场景，不泛化为全部 SME/BU 一把手；负库存不能推出“永不仪表盘”，premortem 的数字不移植为本产品收益。
- MUM/坏消息研究不意味着系统数据无偏或能取消人报。当前只处理实际提供的本地资料/会话；未接入外部事实系统，不承诺实时坏消息通道；不做 IM 约束不因碎片输入研究解除。
- 竞品官网只证明其公开叙事；“管理层留空/没有对象模型/独占”是有限检索下的假设，不能排他证明。已找到的竞品治理/来源/问责能力是反证，演示必须同任务比结果。
- OKF/VK 方向确认与效果测量分开；知识满/空 × OV 只能测可用性，同内容平铺/OKF 才能辨识结构增量。现有 runner/home 不满足全状态/外部 OV 隔离，正式实验未跑。
- 字段存在不等于审批写 verified；留痕是可追溯性，不等于判断正确。审批 Remote 候选与当前 prompt fallback 不混为同一车道，事实见 [技术审计](../reference/tech-exploration/261005-turnaround-evidence-audit.md)。

本轮原型校准：用户指出很难拿到真实决定/回访，研究只选agent能做的。旧真用第一已移rejected；先做 [公开案例](../reference/positioning/261005-prototype-cases-and-interview-method.md) 与 [短访谈/能力积累框架](../reference/positioning/261005-interview-learning-framework.md)，分决策时信息/后验、事实/推论、知识/做法和行为验证。实际访谈/回访以后补，不当原型推进前置；公开/模拟证据不冒充本人需求或经营价值。

## 背景 / 触发

用户 2026-10-05 原话：repo「无痛无痒」；「开始动手的时候，好像有觉得应该有这么一个东西应该很有用，
但是刚刚打开了最终的界面之后，立刻感觉到好像有点像鸡肋」；「第一个反应就是无从下手，我为什么用它，
不知道」。

这是**同一感受第三次出现**，前两次各立过档：

1. 2026-09-25「不痛不痒」→ [总体思路](../../notes/archived/research/2026-09-25-grand-plan-enterprise-expert-assistant.md)
   §一：诊断为自指闭环、把容器当产品；处方 = 换北极星 + 真用驱动。
2. 2026-10-01「怎么看都好像不知道怎么用」→ [真用第一卡](../../notes/rejected/2026-10-01-real-use-first.md)：
   拍板 = 真用第一 + 无真实摩擦证据不动 UI。
3. 2026-10-05（本卡）：首开 UX 已修三轮共 18 轮（locale / 黑话 / 横幅 / 空态，见
   [261001-first-open-ux](261001-first-open-ux.md)），感受未变 → **根因不在之前修的那一层**。

## 已知与未决

### 已核实（证据面，全部当日读过）

1. **真实使用 ≈ 0 仍是现状**：trial home 4 个会话 = 3 个 naive-CEO delegated 读数 + 1 次真人点
   「刷新桌面」（261001 卡第 8 轮补记）。学习回路这台发动机始终没有燃料——而它需要燃料才发动。
2. **首屏形状**（[blank-first-open 快照](../../snapshots/web-face/blank-first-open/expected.dom.json)）：
   hero「探索未至之境」+ 引导条「直接说一句你手头的经营问题」+ 空 composer +「打开我的桌面」（空桌面）。
   首屏的**每一个动作项都要求用户先付出**：想一个真问题、给真数字、等 1–2 分钟回合。
3. **桌面是回放，不是供给**：[trial home 桌面文件](../../dev/trial-home/workspaces/deepseek-harness/default-workspace/.desk/state.json)
   内容质量其实很高（决策卡带 A–D 与不可逆标记、行动表带 owner/due/stop、缺的数明说），但内容
   **全部来自已发生的会话**，且要点按钮（跑一轮模型）才更新。助手从不先开口。schedule 已默认在车
   （2026-10-02 采纳卡），但全部用途是自我养护（curate 等），**没有一条在给主人干活**。
4. **能力面已被证实**：P1「出厂可用的管理岗基座」经 naive-CEO 读数两轮判定「军师级」「下周还愿意
   继续用」（261001 卡第 13/16 轮）。**缺的不是能力，是回来的理由。**
5. **生态对照**（[awesome-dsh-plugin `_digested/ecosystem/`](../../../awesome-dsh-plugin/_digested/ecosystem/)，
   0002 基线 4392 条）：
   - 记忆带 204 条（01 §表），头部 hindsight 43k★ / OpenViking 39k★（04 §2），卖点是**零努力自动
     注入**——单用户场景下「记得住」不构成差异点；
   - 头部共同特征（04 §6）：「常驻可视 + 零配置」「给 agent 可核验的输入」。本产品两头都不占：
     expert-setup / patch / locale 配置链长，首屏要用户给它输入；
   - 空位仍在：管理岗专家包（决策拆解/行动计划）生态里没有对手，identity 仅 24 条——**差异化判断未被证伪**。

### 诊断（为什么「想的时候有用、打开没用」）

- **价值全部延期，成本全部即时**。产品承诺（越用越懂你 / 学得进去 / 管得住）都要 N 次真用后才兑现；
  首开时刻多出来的只有成本。鸡肋 = 这个差值，与文案和按钮无关。
- **产品是「第 3 步体验」长在「第 0 步用户」上**。设计时脑中的 CEO 已有习惯、数据、每周要拍的决策
  ——想象的工作流从第 3 步开始；打开界面的真人站在第 0 步，中间没有桥。三轮 UX 修复修的全是
  「桥修好之后的路牌」，桥本身（零状态 → 第一个真任务）从未被设计——而它只有真人能造。
- **自指闭环的结构性残留**。总体思路 §1.3 早就写下「自治 + 没有外部判据 = 必然向内」；三轮 UX 的
  判据（探针 / DOM / naive-CEO subagent）依然全是 agent 可自证的。naive-CEO 测的是**答案质量**，
  不测**明天还开不开它**。产品在等用户给燃料，用户在等产品给理由——**双向等待**。
- **治理税错配**。draft→stable、审批、curate、人审是企业多人场景的价值；当前唯一用户是本人——
  **单人产品在收企业治理税**（首开即有「3 页知识等你审批」的待办感）。

## 候选与取舍

- **A. 首屏价值倒转（桌面先行）**：首开即晨报/周报（schedule 驱动，零会话也能从知识种子出一期
  「本周管理岗例行的三件事」），聊天降为桌面的下钻。收益：直接消灭「无从下手」——打开就有它做好的
  活；也把 261001 卡「等本人真用」的死结解开（晨报就是给真用的第一个理由）。代价：产品形态从
  reactive chat 变 standing briefing desk，触及 preset 人设与桌面契约；且与「无真实摩擦证据不动
  UI」的 10-01 拍板相抵——**需要用户拍板解除或改写那条冻结**。
- **B. 首任务桥（它先发问）**：首屏不是「说你的问题」，而是结构化 intake——它访谈你，拆你手头最难
  的一件事，主动去要缺的两个数。复用已有行为（澄清门、缺数据明说、decision-routing）。收益：改动
  面小；代价：仍要用户先开局面，弱于 A。
- **C. 诚实地降级为底座**：承认单人场景跑不出学习回路，治理面收进开发者面，产品面只留专家包
  （P1 拆解 + 决策卡），working folder 藏到看不见。与总体思路 §八 的 B 路线（底座+专家包）一致。
  代价：等于放弃「数字分身」的当前叙事；收益：最小自欺。
- **维持现状（继续等真用）**：真用第一卡的既定方针。代价：同一感受已第三次出现——三轮证据表明
  「等」没有等来摩擦读数，等来的是重复的失望。

## 第 2 轮（2026-10-05 续，用户追加拍向：「不只是 UX 糟糕，是主意没想清楚——完全重构」）

用户原话：定位其实是「UX 体验糟糕的一塌糊涂，打开了都不知道要干什么，价值点在哪儿」；
「我们现在更多是主意呀，到底这东西做成什么，用户的体验是什么，这里确实没想清楚」；「可能真是
UX 上要完全重构了」。追加要求：不只看 DSH 生态，到外面的生态找同类定位。

### 反思修正（第 1 轮诊断的再往下挖）

1. **「UX 糟糕」是症状，病根是信息架构：主对象错了。** DSH 的壳是开发者产品——主对象是
   「会话」（列表 + 聊天 + 轨迹）。本产品把 CEO 产品挂在会话上，于是所有**跨会话持久物**
   （记忆/知识/决策卡/行动表——产品的全部价值所在）在 UI 里全是二等公民（+ 菜单、右栏 tab、
   桌面全屏入口）。CEO 打开 = 每次新会话、每次从零、价值物藏起来。**重构第一刀不是画新界面，
   是宣布主对象：这个产品的主对象是「桌面」，不是「会话」**——会话降为桌面上的一种动作
   （点决策卡进拍板会话，像 issue 上的评论）。
2. **首日承诺卖错了层。** README 卖的是「数字分身/越用越像你」——这是**第 100 天的价值**；
   打开即失望是必然。三个价值层拆开：
   - **B 军师**（把难事拆成带行动表的处理单）——第 1 天可验（naive-CEO 两轮已判「军师级」）；
   - **A 随员**（它记得你的公司、盯着你批过的事到日期）——第 1 周可验（跟进行动表 + 缺数催收，
     全部原料已在家）；
   - **C 分身**（越用越像你）——第 30 天才兑现。
   **卖 B、用 A 留人、让 C 慢慢显形**——现在是把 C 当首日卖点卖。
3. **「无从下手」的机制解 = 任务从三处来，不靠用户凭空生成**：① 它先开口（晨报 = 到期驱动，
   不是新闻驱动：行动表 due、缺的数没到、待拍板项、知识页 stale——**v1 晨报不承诺新信息，
   承诺「你批过的事推到该发生的那天」**，这正是 CEO 最缺的跟进纪律）；② 它主动搭台
   （访谈式 intake：第一次打开是它问、你答，15 分钟建「公司卡」+ 交出第一份处理单 + 落一个
   回访 schedule——访谈同时是记忆/知识的诞生场景，治理税自然化）；③ 你丢的东西有落点
   （报价单 → 知识室草稿 + 回执）。
4. **治理税回收：审批从「队列」变「内联」**——记录动作的下一句话确认 + 随时撤销 + 每周抽查，
   替代攒一批事前审（企业语义保留：可追溯可撤销）。**反转 10-01 治理姿态，须用户拍板。**
5. **换位节律**：CEO 与它的自然关系不是「聊天对象」，是「每周一坐 15 分钟的随员」（批量拍板）
   + 「遇事立刻问的军师」（即时拆解）。「打开频率低」因此从缺陷变成设计前提。
6. **插件边界的可行性已核实**（[client-ui-contribution 技能] + 生态先例）：Conversation View
   标签页可以承载主视图（生态先例 dsh-morning-paper：报纸式会话视图、零 token、从不调模型）；
   主动唤醒有先例（dsh-proactive：host 级闹钟 + 静默时段 + 每日投递预算；dsh-heartbeat：
   心跳 + 代码规则决定能不能开口）；vendor 面（hero/composer/轨迹）动不了，继续走上游递交。
   **「完全重构」在插件边界内 = 主对象迁移（桌面成为 Conversation View 主页签）+ persona/
   技能的行为重构（先开口、访谈制）+ 审批内联化，不是重画组件。**
7. **一句话定位候选（待用户挑）**：A 随员「它记得你的公司，盯着你批过的事」；B 军师「把你的
   难事拆成能执行的行动表」；C 分身「越用越像你」。三者不互斥，排序即定位。

### 概念草案（重构后的第一周体验脚本——供拍板的具象层，非实施授权）

**定位一句话（三个候选，排序即定位）**：
- B 军师：「把你的难事拆成能执行的行动表。」（第 1 天可验）
- A 随员：「它记得你的公司，盯着你批过的事。」（第 1 周可验）
- C 分身：「越用越像你。」（第 30 天起显形）
卖 B、用 A 留人、让 C 慢慢显形；README 首日承诺改写为 B+A 的合取，C 降为渐进揭示。

**Day 0 · 第一次打开（15 分钟，访谈式 onboarding）**：
首屏不是空 composer——它先问（澄清门既有行为前移到首屏）：①公司做什么、多大、客单价
②眼下最头疼的一件事 ③这件事你手上有几个关键数。结束时交付三件：公司卡草稿（它理解的
你公司，逐条可改可删）、第一份处理单（拆解+选项+行动表）、下周回访的约定（schedule 落地，
到期它来找你）。

**Day 1-N · 有事问（即时通道）**：丢一个问题 → 处理单落在桌面「在跟的」，缺的数进「缺的数」，
要你拍的进「要你拍的」。会话从此有形状：不是聊天，是围绕一件具体事的拍板/追问。

**每周一坐 15 分钟（批量通道）**：桌面三列「要你拍的 / 在跟的（含到期）/ 缺的数」一屏批完；
到期行动、没到的数、过验证窗口的假设由它先开口（晨报 = 到期驱动，原料全部已在家里）。

**不做清单（对齐既有拍板）**：不做 IM 触达、不做新闻聚合简报（那是 heartbeat/闲聊型）、
不做用量仪表、不做通用聊天优化。

**技术落点（插件边界内，已核实）**：桌面升 Conversation View 主页签（生态先例
dsh-morning-paper 证 slot 可行；现状桌面只是右栏 pane tab——`src/client/index.ts` 的
`sidebarRightTabs.register`，被动旁挂）；主动唤醒借 dsh-proactive/heartbeat 的设计
（静默时段、每日投递预算、能否开口代码规则+agent 双层把关）；审批内联化动 persona/
技能行为面（须拍板，反转 10-01 事前审批姿态）；vendor 面（hero/composer/轨迹）继续走
上游递交（261001 卡台账）。

## 第 3 轮（2026-10-05 续，用户追加：自我净化 / 自我进化该不该进定位）

用户追问：产品里放「自我净化」会不会好一些；随后自己明确为「自我进化——不断长能力，不断能
明白 CEO/VP 到底需要什么，这种」。

### 裁决

1. **机制已建 90%，问题从来不是有没有，而是形态与位置。** curate（重复/悬空引用/预算/过期/
   技能遮蔽/断链…）+ memory-hygiene + propose_skill→land + draft→stable + OpenViking 层 1
   ——净化与进化的机器都在车上。总体思路 §1.2 点名的历史病恰恰是：**助手最擅长的是维护
   它自己的房子**（自指闭环）；首开 UX 卡里 CEO 侧栏那 17 条「运行 curate 并报告家现状」
   就是它长歪的样子。
2. **两种形态分开：净化自己 = 成本（藏）；进化懂你 = 价值（报）。**
   - 净化自己（重复、断链、预算）继续默跑，零 UX、零卖点——餐厅不挂「我们洗碗」的招牌。
   - **净化「你俩的事实底账」是总助的本分**：过期决定、过了验证窗口被「能杀它的数」杀掉的
     假设、与现行口径冲突的旧记忆——报出来，一句话级，涉主人口径的只提请不擅断。
   - 进化的可观察形态不是「我会进化」的承诺，而是**学习账本**：这周学了你的哪三个口径
     （带出处，P2 既定「指出这条是哪次学来的」）、长了哪个本事、两条拿不准待确认。
3. **「明白 CEO 需要什么」的具象化 = 口径库 + 决策路数。** 桌面决策卡已有选项结构；真实拍板
   流过若干次后，它能说出「三次里你两次选了先试探底线再让步——按你的路数，这里你会先问毛利」。
   这句话第一次出现就是产品的高光时刻——但它需要真实决定流过才存在。**进化是复利，复利需要
   本金；本金是真实使用。**
4. **与督办楔子的关系：督办是进化发生 loop，不是竞争定位。** 每一条盯到闭环的事都在教它
   主人的标准；楔子仍然是一个词（督办/你拍板它盯到闭环），进化是这个词跑起来之后的复利。
   首日卖进化 = 重演「卖 C 分身」的错误（第 2 轮已裁）。
5. **结构性偏向警示（对自己）**：净化与进化是 agent 最能自造自验的活——grand plan §1.3 记档
   的向内漂移正是从这里长出来的。本轮规矩：**不为净化/进化新增任何机制**，只做两层行为面
   ——①养护结果翻译成底账语言；②挂进每周一坐的固定议程（第三议程：账面与它的错，1-3 行
   确认式，不产审批队列；👎→修正提案管线已在 C2）。

### 落点（行为面，非实施授权）

- 每周一坐的三议程定形：**①要你拍的 ②到期与堵点 ③账面**（过期/冲突 + 学习账本 + 它的错）。
- 学习账本进桌面（或在跟的卡的 note 里）随写随记；出处必填（沿用 P2 语义）。
- 「决策路数」是第 30 天的渐进揭示，不进首屏文案；出现条件 = 同类决策样本 ≥3。

## 第 5 轮（2026-10-05，用户追加：WIKI/OKF 这类底层技术对 CEO/VP 到底帮多少——实验诉求）

用户原话：特别想实验 WIKI、OKF 这样的底层技术——「用一个有组织管理的信息系统，不管是管理
知识啊、管理技能啊、管理突发事件等等，技术上我要找到它到底能帮助什么」；「有了问题好修整，
就技术让它不断的往上提升的可能是存在的」。

### 裁决：该实验，且资产已在，用四格 A/B 别建新台子

1. **技术定位先说穿**：认知二分——情景记忆（哪天谁说了什么；OpenViking 层 1 已落地）与
   语义记忆（口径/制度/数字/决定；OKF/wiki 知识页六字段 + [[互链]] + curate）。「管理知识/
   技能/突发事件」三类恰好对应 knowledge/skills/research 三房间 + OV——这就是"有组织的
   信息系统"的本义。OKF 六字段子集每格都是给 CEO 的具体好处：`sources`→答案可归因（O1）、
   `status`→口径可撤销可演进（deprecated 留原位链接不断）、`stale_after`→过期机器可查、
   `generated/verified`→AI 起草与本人确认分离、`[[互链]]`→口径不孤立。
2. **预期管理：它是乘数不是加数**。拆解题（模型本来会）预计四格无差；引用/口径/数字/制度题
   知识层决定性；跨会话连续题 OV 决定性。repo 历史警示（押 OKF 时页面全关于自己→自指闭环）
   ——实验题必须全部来自 40 题真实域评测（用户自己出的；G2 机器预判已完成），题面不动。
3. **实验设计（2×2）**：知识室满/空 × OV 挂/不挂，四格各跑 40 题（`pnpm eval:domain`；
   技能面不动作为控制变量；dev-ov/dev-task 双 profile 先例在）。诚实记账：OV note 验收表
   承诺的「A/B 两臂补记」至今未落数（只有 S5 单题对照）——本轮顺手补上。
4. **判读指标**：①引用归因率（事实性回答带原文定位比例）②口径冲突数（应恒 0，冲突即红线）
   ③拒答正确性（知识室空时是否瞎编——O3 的技术读数）④跨会话追问组（OV 直接读数）⑤拆解题
   分数 = **阴性对照**（预计无差）。真用面第二判据：归因语句出现率（naive-CEO 读数「按你批准
   的那页闸门」已被感知为亮点 → 变成可数指标）。
5. **"有了问题好修整"的回路 = 失败按层归因**：每道失分题归四类——①缺页→修种子/导入管线；
   ②页在没召回→修检索排序/摘要预算；③情景没写入→修 commitTokenThreshold（3000 待真实使用
   校准）；④写了没审（draft 积压）→接第 2 轮审批内联化。**提升由评测分+归因分布驱动，不由
   "能否自造自验"驱动——防自指的关键。**落点：eval:domain 报告加归因列。
6. **可证伪预言**：知识层对口径/数字/制度题显著提升、对拆解题≈0；OV 对跨会话组决定性、对
   独立题≈0；拒答题在知识室空时塌方。任一意外都指向明确杠杆（知识层连拆解题都提升=种子太薄；
   拒答没塌=知识层价值全在归因）。

## 第 11 轮（2026-10-05 续，用户定调：为一把手「非黑白的判断工作」做小众）

用户原话：高管/一把手「一天到晚面临的问题不像代码——认知程度要高、决策性的、不确定性很高、
复杂度不低、信息分布很复杂，最主要是他要干的活儿。决策不是黑白的决策。现在 AI 的能力已经
很强了，所以我们看看能不能做出这个小众——全球 CEO 也没几个，这个方向可能更好」。

### 定调的展开（v1，待用户确认）

1. **工作性质的分野**：代码/执行层工作是**有序域**的活——有对错、可验证（测试通过与否 =
   ground truth），coding agent 的一切优势都长在这上面；一把手的工作是**复杂域**的活——
   没有标准答案、高不确定性、信息分布在外部（财务/销售/市场/人），唯一产出是**判断与决定**。
   AI 能力已经很强，所以差异化不在「更聪明」，在**贴住这种工作性质 + 信任架构**。
2. **由此派生的设计公理（五条，全部已在车上或已推敲）**：
   - 产品的工作单元 = **决定**，不是任务/答案（决策卡：选项/代价/不可逆）——四路调研里
     没有任何一家把决定建成一等对象；
   - **不合并分歧**：三透镜（whole outcome/cash/customer reality）保留分歧、主公拍板——
     非黑白决策的产品形态就是把选择变清楚，不是给答案；
   - **不确定性 → 可证伪化**：假设 + 「能杀它的数」，不假装确定（O3）；
   - **信息分布复杂 → 缺口是一等对象**：缺的数、该跟谁、堵在哪（督办楔子的认识论根据）；
   - **判断不可验证 → 留痕即信任**：sources/账面/留痕是判断工作的验证形式（OKF 的根据）。
3. **小众定位的含义**：全球一把手没几个 → 深度重于广度、手工质感重于规模化；竞争面只剩
   Huper 一家（alpha）；不迫降级「不做 IM/不做 scaled 部署」的既定拍板——小众身份反而让
   这些「不做」从限制变成立场。**且与第 7 轮「不是做产品、是打动管理层」完全兼容**：小众
   样板恰恰是最好的说服物。
4. **它顺手解决了**：演示的定调句（「别问它答案——它把你的选择变清楚、盯到底、留了痕」）；
   OKF 四格实验的题目倾斜（判断/口径类题为主）；Cynefin 复杂域语言可作为向管理层讲解的
   共同框架（snowden 框架本身是管理层熟悉的话语）。
5. **反方（自记）**：①小众若滑向「只为一个人写软件」，复用性叙事（专家包/换领域换包）会
   被削弱——边界是「一把手这类工作」而非「某一个人」；②非黑白 ≠ 无对错——事实层仍有硬
   对错（数字、出处），判断层才无对错，两层不可混淆（O1/O3 仍然承重）。
