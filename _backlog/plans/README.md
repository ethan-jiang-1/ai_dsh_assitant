> 一文件一张卡：**`YYMMDD-<slug>.md`**（六位日期 = 立卡日，归档后文件名排序即日期流；slug 用
> kebab-case）。毕业（批准 / 搁置 / 否决 / 消化）时 `git mv` 到
> [`../_done/_closed_plans/`](../_done/_closed_plans/)，文件名不变、内容不重写，状态行补去向指针。
> 规矩手册 = [`../README.md`](../README.md)。
>
> **活跃清单 = 本目录树本身**（位置即状态；不设第二份索引——[notes/README §三](../../notes/README.md)
> 同款纪律：第二份清单必然漂移）。毕业判断看各卡状态行。

## 🔒 保留卡（用户判触发）

状态行带 🔒 的卡 = **只有用户能判触发成立**：agent 只报告与建议，**不得自行判触发、不得删卡、
不得实现**（2026-09-24 真实越界事故：某会话把用户保留的 Obsidian 条目判成已触发、实现并删行——
行为评测 `reserved-item-restraint` 任务钉着这条纪律）。

## 卡片模板

```markdown
# 推敲：<标题>

> 立卡：YYYY-MM-DD ｜ 状态：推敲中｜毕业门判断 = <待定/该做/待触发/待用户判触发（🔒）/倾向放弃/…>｜下一步 = <动作或触发>

## 背景 / 触发
为什么推敲这个：问题、观察、出处（会话/Note/走查）。

## 已知与未决
已核实的事实（带出处）；四问各自的开放点（该不该 / 何时 / 次序 / 放弃）。
调研类卡补三字段：**待答问题 / 待跑实验** + **喂给谁**（结论将喂给哪个决定）。

## 候选与取舍
候选方向 × 各自代价；为什么 X 不是 Y（备选只记录、不编造）。

## 毕业门
四门各自的满足条件；缺什么证据才能判。
```

## 状态行规则

首部 12 行内必须有 `状态：` 行且写明毕业门判断——**每张卡自带户口**，防挂死稿。
（机械门禁暂不设：死稿卡第一次出现即加 `plans-liveness`，见 [`../README.md`](../README.md) 机械门禁节。）

## 调研卡形态规范（原 notes/research 规范并入，2026-09-28）

- **一手引证**：承重结论后跟来源 URL / 包名；二手转述不算数，跟到源头。
- **证据分级**：[affordance]（源码/接口可指认）/ [documented]（官方文档载明）/ [observed]（社区观察，注明出处）。
- **版本基线**：提到的每个包写明查证时的版本或 commit 日期。
- **承重结论内联自足**：只读本文即可成立。
- **普查底稿亲验**：进文前的承重主张由委托方复核（AI 检索结果不作最终证据）。
