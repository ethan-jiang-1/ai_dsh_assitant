# 推敲：它先开口——开屏播报、拍板感与周节律（行为层收口）

> 立卡：2026-10-07 ｜ 状态：推敲中 ｜ 可关闭：否

**问题与期望结果：** 返回产品时看到可操作的业务播报，拍板记录有本人口吻，并能按周对账。

**当前情况：** 开屏、拍板与周坐实现已有提交（`7fe774a` / `636a4a6` / `532c19d`），完整走查发生在 2026-10-07；[已归档 note](../../notes/archived/2026-10-07-opening-brief-and-rhythm.md)作历史引用。这不等于当前验收通过。

**未决问题：** #2 重载没有机械断言，#3 输入框可见性与 #6 排程依赖易失走查，#7 blank 渲染夹具阻断；#5/#6 及 R5 还待用户判断。不能概括为“6/7 通过、只剩用户终验”。

**下一步：** 点名接手时先按下方「补证据前的准备」明确环境、执行步骤和结果保存，再按原验收标准取证。技术缺口和用户待判断项分开报告；与 [总助体验卡](261006-chief-of-staff-experience.md)共用的验收结果记在本卡。

下面先列当前验收要求、补证据准备与关闭条件。文末「历史观察与实施记录」保留当时现场和走查结果，供追溯使用。

## 验收标准

标准于 2026-10-08 按 [验收设计](../methods/validation-design.md) 拆分。确定性逻辑、浏览器编排和模型行为分别取证；一次端到端演示不能替代全部检查。下表保留已有证据及其限制，不把历史走查升级为当前通过。

**本轮确认的承接：** 用户把“三行口语播报”定为待看具体界面的假设，不是不可更改的最终版式；首用从一件眼前的事开始，不必先完成公司画像/固定三问；桌面事项处理时允许留在对话，成功读回才返回。[总助卡 R1–R7/A1–A9](261006-chief-of-staff-experience.md#验收标准)拥有这些结果。下表 #1 的三行与 intake 断言只是当前实现变体的回归证据，#4 只证明通用回调，#5 的即时“已拍”只表示点击反馈，均不足以证明新目标已通过。其余原技术缺口与真人判断保留。

**R5 待本人判断（贯穿 #1、#5、#6）**：口语化、看得懂且可操作的业务内容是否适合本人，仍须真人判断。[中国 SME 调研](../research/positioning/261005-chinese-sme-boss.md)曾据此提出“三行口语题、不仪表盘化”；研究推论不能取代本人的选择。本轮已确认三行只是呈现假设，完整事项列表与宽/窄层级由总助卡承接；不再以“永远三行/永远不显示计数分区”卡死版式。机器证明的是当前分支/文案，不是产品价值通过。

**判定边界**：即使上表技术检查全部通过，#5、#6 与 R5 的用户判断也仍需单独记录。技术通过不能代替产品验收，见 [验收结果判断](../methods/validation-judgment.md)。

### 证据保存限制

2026-10-08 记录：上表 #3、#6 的走查证据住在
`/tmp/ux-shots/`（49 个文件，31 个 slice 证据）——**`/tmp` 重启即失**。`snapshots/` 按
[其契约](../../snapshots/AGENTS.md)只收 session 回放与 web 渲染期望两类，**走查截图不在任何已收编
owner 面**，故本卡不擅自把它们塞进 `snapshots/`（那是越界，也是
[validation-evidence](../methods/validation-evidence.md) 明禁的"把 snapshots 当通用证据桶"）。
两处 walkthrough 证据因此**只活在易失路径上**：

- 影响：#3、#6 的行在 `/tmp` 清空后**不可复核**——按
  [validation-judgment](../methods/validation-judgment.md) §1，证据不可复核 = **blocked，不是 pass**。
- 已做的缓解：本表把每行的**断言对象与判读要点**写全（不依赖图片本身也能理解判了什么），
  并把提交锚点（`7fe774a`/`636a4a6`/`532c19d`）列在开头的当前情况中。
- **可重取的方法线索**：保留断言对象、提交锚点与日志读法，供后续补证据使用。排程落盘日志读法见 [`usage-report`](../../dev/reports/usage-report.mjs) 的 `sessionLogs` / `readEvents`。这些线索和截图都不能替代一次可复核的执行结果。
- **触发条件**：同类"只有跑起来才看得出"的 model-visible/渲染证据**第二次**靠 `/tmp` 手工留存时，
  按 `snapshots/` 的升级触发精神立卡讨论第三类 admitted shape（或把走查协议固化进 probe 脚本），
  不提前预建。

## 关闭条件

1. 上方必要技术检查有可复核证据，阻断项得到处理；不能用“实现已落地”代替验收。
2. #5/#6/R5 的用户判断和 [总助体验卡](261006-chief-of-staff-experience.md)的共同体验判断均有结果，记录在本卡。
3. 总助体验卡中默认桌面未交付、回流缺证据的处理已明确，未通过项不能被这张卡的局部通过掩盖。
4. 条件满足后两卡一并归档；不通过则记录具体标准、环境和步骤，按现有流程修复或形成新的处理申请。

体验走查必须区分两种环境：无数据首次使用看引导，已有业务数据看播报；二者都可以使用隔离 home。不能要求无数据环境凭空播报业务内容。技术检查和用户判断分别记录，不用一句“好不好”代替。

## 历史观察与实施记录

以下是当时的观察、方案和执行记录。历史勾选只说明那次走查的结果，当前可判范围以上方验收及证据缺口为准。

### 背景 / 触发

[总助体验卡](261006-chief-of-staff-experience.md)前期实现后，2026-10-07 干净 home + 真模型九轮 DOM 逐帧走查发现：**当时观察到主区面板、拍板闭环和桌面回流走通，但体验弧线断在第一屏**。用户追问方向性：UX（不是 UI）靠谱不靠谱、设计预想还有多少距离、好不好修。本卡 = 距离的定位与消化次序。当时的“走通”记录不等于当前独立验收通过；对话回流仍需单独举证，见上方补证据准备。

### 修复前的观察（2026-10-07）

以下描述当时现场，原证据路径为 `/tmp/ux-shots/`；当前实现和可判范围见上方验收标准与结果。

**当时已走通的部分**：
- 拍板闭环端到端：dashboard 点「涨 5%+锁两年」→ 消息进会话 → 模型 40s/137K tok → 写长期记忆 + 改 state.json(+55/-12) + 撤旧决策 + 挂新决策 + 建到期任务 → 切回 dashboard 新决策已在。
- 主区面板机制（sidebar.panellist + main）：图标 → 独立页 → 数据态渲染全对。
- intake 开场质量好（fresh 时三问短弧线）。

**当时发现的断点**：
1. **auto-send 无去重**：判 fresh 读 `deskSlice(sid)`（新会话恒无数据 → 恒判 fresh）→ **每次页面重载重发「你好」**：10 分钟造 6 个会话、每条 ~44.6K tok 真模型调用。Day-2 打开 = 产品假装初次见面，直接击穿「它记得我」。
2. **composer 死亡**：FirstMileDock 卸载后隐藏 vendor composer 的 style 残留（`fallbackDisplay:none` 实锤；机制推断 = hooks 前条件 return 违反 React 规则致 cleanup 丢失）→ intake 问完**用户无处打字**，主线死锁。
3. **「有问题？」死按钮**：`dsh-navigate-to-session` 事件全仓（含 vendor）零监听者——dashboard 回对话的入口是断的。
4. **「它先开口」内容物错位**：开屏 = 「你好」+ intake 反问——**即使桌面上已躺着决策/行动/缺口**。实验实锤模型会猜错：第 5 次重载时桌面有 seed 数据，模型仍说「刚开的台面，还没有任何记录」（7 秒、未查任何工具）→ **第一句话必须由客户端拿桌面数据确定性合成，不能靠模型自猜状态**。
5. view preference 写入不生效（当轮主区仍落对话）——D7 未解，非本卡范围。

### 设计判断（考古结论）

- 「它先开口」的台词应是**播报**不是客套：Clay（首屏内容来自自动整合的既有数据）、VandeHei（真实 CEO 长期在用：夜间扫描→清晨送达）、Huper（"tells you what needs your attention before you have to ask"）三方外证一致；五谷渔粉案例（群里 99+ 没人提炼）是内证。
- **中国 SME 调研红线**：一把手是直觉型经营者不是仪表盘动物——播报 = 三行**口语化语文题**+每行可点，不是计数分区/图表。永远不做仪表盘化。
- 拍板产品句（定位卡 18 轮）：「拍板那一下，永远是你」——拍板记录必须读起来是**本人拍的话**，当时是英文机器腔以用户名义入账，违背账面价值主张。
- 输入边界诚实化：不接外部数据源拍板下，当时对「盯到闭环」的界定 = 「盯你喂进来的每件事到闭环，不丢不漏」。「世界的变化回流」叙事不做超额承诺。

### 输掉的方案

1. **auto-send 修去重后保留**——去重只治标；内容物（客套+反问）本身就不是设计要的「它先开口」。
2. **模型侧开屏**（让模型自己查桌面再开口）——实验证明它会 7 秒不查就猜错；第一句话必须确定性合成。
3. **消息版晨报做开屏**——每次打开烧一轮模型；确定性合成零 token 先行，真晨报留给 09:00 投递（B1 既有车道）。
4. **等 D7 再动开屏**——blank 相位是插件可占的（A1 已证明），把「第一眼」白等上游送掉不值。
5. **仪表盘化第一屏**——中国 SME 调研红线（直觉型经营者）。
6. **本卡内做输入边界**（坏消息通道/CSF/每周倒碎片）——真设计题，值得单独推敲卡，不搭车。
7. **修好 A1 的 composer 隐藏 CSS**（2026-10-07 实施期否决）——几何探针实锤它是自藏的：本 dock 挂在 vendor `ConversationContent.tsx` 的 composerStack（hero + input.dock + inputBar）内部，`[data-chain-overlay-fallback]` 一藏藏全家；A1 时代的「7/7 关键词命中」走的是 DOM 大纲匹配，隐藏元素也在大纲里——**可见性从未被证明**。退役优于修补。
