# 推敲：CEO 的持续助理——跟踪事情、适时提醒与建议、从结果中学习

> 立卡：2026-10-08 ｜ 状态：推敲中 ｜ 类型：未定 ｜ 可关闭：否

**问题与期望结果：** 用户再次反馈，项目开发已久仍“不痛不痒”，难以打动 CEO。用户明确强调提醒与主动建议、事物跟踪、经验沉淀和学习，并要求把调整思路组织到 issues、支持证据放 research。希望助手持续接住经营事项，在繁重日常中减少本人重新整理背景、判断该管什么和反复追进展的负担，并把结果与纠正用于下一次工作。

**外部结果三要素：** 触发＝本人交代一件需持续关注的事，或已有事项出现进展、新材料、到期、约束变化、纠正；用户得到＝可接续的事情记录，以及有依据、说明“为何现在需要你”的提醒或建议，反馈后记录和后续跟进同步，下一件类似工作能正确使用已经确认的经验；完成条件＝先形成能复述这一过程的需求与范围，通过有界情景比较得到机制/交互证据，确定可执行验收和后续处理申请。模拟可验证过程，不能据此宣布真人经营价值或长期学习已成立。

**当前情况：** 历史定位和调研已有这些诉求，现有载体包括决定、行动、缺口、记忆、知识、技能与排程；已有证据主要覆盖单轮分析、记录、局部交互和排程写入。跟踪、注意力筛选、主动判断与条件化学习尚未形成共同验证过的过程。

**未决问题：** 第一条代表性经营过程选哪一种；本人应付出的最少输入；哪些变化值得提醒/建议及何时应静默；什么证据表示进展或完成；经验适用/失效的条件；同材料下相对现有对话和普通聊天的增量。

**下一步：** 先按下方现状复验协议把现有版本实际走一遍，逐项记现在发生什么及未解决原因；再用同材料整理候选输出/交互，收敛范围、验收和需要本人判断的少量问题。本轮只承载推敲与研究，未确定新的实现方案。

## 用户确认与证据

### 本轮直接诉求

- 项目做了很久仍难以打动 CEO；需回看现存、已关闭 issue 和归档研究，检查解决深度与体验。
- “提醒或者是主动的建议”，放在 CEO 日常繁重工作的情境中思考。
- “还有事物跟踪”。
- “还有经验沉淀和学习”。
- 将调整思路组织进 issues，支持证据放 research。

四项均是用户明确提出；下文尚未确认的优先次序、提醒频次和经验规则仍是建议。桌面及账本的补充确认如下，不再作为待选问题重复询问。

### 统一经营账本与多会话输入（已确认）

**用户确认：** 一个权威经营账本可接收多个 Session 的输入，保留来源 Session 与原始记录追溯。桌面给完整事项列表、有依据的优先建议和下一步，CEO 保持自选权；证据不足时承认不能判断，不编造确定排序。一个账本不等于只许一个聊天会话，也不等于把不同工作区的所有文件自动混在一起。

**本卡拥有：** 事项身份与接续、何为最新已确认进展、提醒/建议依据、经验条件，以及多个会话输入如何成为经营账本的可信更新。[总助体验卡](261006-chief-of-staff-experience.md)拥有主区入口、信息层级、空间适配、事项对话交接和读回返回；它消费本卡的账本语义，不另建一份可写真相。

当前 `loadDesk` 从最近 Session 工作区寻找快照；`dataDir` 是跨会话承载，但四个房间与工作区桌面投影不是已经实现的统一事项账本。可用持久载体和会话/导航 API 的静态依据见 [本轮可行性附录](../research/positioning/261008-ceo-value-contract-review.md#八本轮主区入口与会话数据路径的静态可行性)，不据此宣布并入或冲突处理可用。

| 尚未定清的机制 | 需要形成的判断及反例 |
|---|---|
| 同一事项怎样跨 Session 认出 | 区分明确引用、改名、同名不同事与模糊相似；不能只按标题合并。至少检查甲/乙同一事项接续和相似不同事项并存；模糊输入是否需要本人确认仍待情景比较 |
| 权威状态与原始材料的关系 | 原记录、提议更新、已确认状态/修订、纠正与冲突如何区分；新材料不自动覆盖已确认决定，旧材料重投不把状态倒回。具体存储与写入接口未定 |
| 多写者和失败恢复 | 两个 Session 同时改同一事项、重复投递、写失败/读回失败怎样不丢更新、不重复认领；文件原子替换不能单独证明业务冲突被解决 |
| 来源 Session 与动作 Session | 点击事项是续原会话、使用另一处理会话还是明确选择，依据是什么；源会话归档/失效时如何保留追溯。不能默认发到最新 Session；不把来源与处理会话强行认作相同 |
| 提供给桌面的成功读回信号 | 能指出哪个事项、哪个已确认更新/修订、哪次处理及来源；区分模型回合结束、提交、写入成功与 UI 读回。具体字段/协议未定，不能仅用 `generatedAt` 判业务成功 |
| 优先建议的输入和诚实边界 | 使用截止时点内的期限、影响、依赖、本人偏好与出处；缺失或冲突时显示未知。权重、频次与“必须介入”的阈值未定，不由 UI 排序反推业务答案 |

上表是已确认结果必需的机制推敲，不是实施清单或暗定算法。验收材料至少包含两个 Session 同事项更新、同名不同事、日期冲突、无关 Session 成为最近项与重载读回；并入预期须先明确，未明确时 [总助卡 A2/A4/A6](261006-chief-of-staff-experience.md#逐项矩阵)相关证据保持 blocked。只解决列表/导航不算跟踪、提醒或学习已成立。

### 把“为什么改了仍不好”写成可核查原因

先区分以下情况，再选工作；不能把全部差距当成新需求：

- **已规定、未验证执行**：晨报的上下文读取、延期、静默和预算。先验证现有技能在反馈/新会话/重启后是否守约，再判断要改提示、数据流程还是确定性守卫。
- **实现结果比原诉求弱**：开屏第一条行动不等于注意力筛选；记录/排程不等于持续掌握进展。明确缺少的是选择规则、输入还是行为稳定性。
- **走过失败路径或受边界阻断**：默认桌面/自动开场的失败记录。保留原期待和失败原因，比较可落地替代，不因上游难做就删除用户结果。
- **研究只形成框架、验证没运行**：两个一手案例未核、条件变式未执行，学习与对照实验没有完整结果。补一个有界验证，不再增加泛调研篇数。
- **延后后承接不清**：阶段 4/5 等归档声称移交持续实践，阅读复核尚未核实细项承接。逐项查原去向与实际消费者；不根据档头认定已消化，也不因本轮没找到就断言不存在。

### 本卡下一轮的现状复验协议

1. 明确 repo commit、已构建版本、实际 profile/home/workspace 与使用的 preset；不能以本会话 GUI 自动等同这个仓库产品。
2. 固定一件事项和原始材料，先走**现有版本**：交代、反馈、新信息、延期/完成、再次打开或新会话；保留输入、桌面前后、工具/排程记录和可观察输出。
3. 每个差异写“预期用户结果 / 现在发生什么 / 证据与限制 / 断点原因 / 可落地补法或待核问题”。有技能规定但没有守约，也算当前差异；没有信息来源则先处理输入，不能让模型编进展。
4. 同一材料才做候选比较。定位到可修断点后改有界方案；受限制项保留或明确提出范围取舍，不把不可实现悄悄改写为不需要。
5. 记录机制已成立、技术失败、模型行为不稳定、证据不足、本人未判断分别有哪些，不重复此前“一次走通后整体已结”的读法。

本卡先留下这套有边界的检查动作；本轮没有启动运行环境或实施修复，不把“待复验”改写成现状通过。

## 要调整的思路

### 1. 用持续工作的过程连接四项诉求

建议围绕同一件事组织：**交代/发现 → 持续跟踪 → 判断是否需要本人关注 → 提醒或提出建议 → 反馈并更新 → 复盘结果与纠正 → 下次正确使用经验。**

工作对象不只限于已经拍板的待办：也包括待判断的问题、跨部门承诺、持续风险和待验证假设。应先按具体情景确定边界，不立即为全部对象建新数据模型。

| 本人需要什么 | 助手应交出的结果 | 现有证据不能替代的检查 |
|---|---|---|
| 事情交给它后不用反复重讲 | 保留目的、最新已知进展、责任人与下一信号，后续片段接回同一件事 | 新会话/改名/延期后仍能接续，不丢旧决定，不把相似事项误合并；没得到进展时标明未知与更新时间 |
| 忙的时候被及时提醒 | 提前量与影响相符；说清为何现在需要本人、可以怎样处置；不需介入的合并或静默 | 到期未完成与已完成、已延期、重复材料、无新信息分别处理；提醒是否实际送达与重启后是否重复需独立证明 |
| 得到有用的主动建议 | 发现影响判断的约束变化、事实冲突、跨事项依赖或失效信号；给建议、依据和需本人决定的部分 | 没有新变化时不凭空制造建议；有变化时建议能改变；支持/反对证据与未知分开 |
| 经验沉淀，下一次少费力 | 留住当时判断、适用条件、实际结果与纠正；下一件正确沿用标准，并指出从哪里学来 | 记忆/页/技能存在不算改善；条件改变、反例、旧标准撤回和未参与提炼的病例仍正确 |

这些是待收敛的结果要求，不是已确定的功能规格。第一版需选一条过程，而非同时实现表内所有可能形态。

### 2. 把注意力与输入负担写入需求

CEO 的繁忙使主动性同时有收益和成本。建议每次主动输出至少能回答：**什么变了；为什么现在值得你关注；建议怎么做或还缺什么；你是否必须介入。**

需比较一条即时提醒、一个批量简报和静默等待的取舍。紧急程度、提前量、频次、本人不回复时的处理尚未确认，不预设每天或每周一定要发。提醒不是凭空猜测外部经营变化；无进展材料不能把“没有收到”写成“没有发生”。

输入也不能只作为最后的通道选择：给出有用结果前本人要交代多少、补多少、维护多少，要与结果一起验证。现有“不接外部数据源、不做 IM、只在 DSH Web/Desktop”的边界继续作为约束依据，见 [输入边界卡](261007-input-boundary.md)。本卡不凭研究建议解除它，也不先决定接哪个系统。

### 3. 把学习写成行为变化

保留 [README 的 P2 判据](../../README.md#L18)：做过三件同类工作后，第四件不必重讲标准，而且能指出来源。补充条件变化、纠正和撤回的对照，防止把一次选择写成永久偏好。

分别看清记住事实、沿用判断标准、复用处理步骤三种改善。经营结果好坏不能直接证明当时判断正确或某条经验普适；需保留当时信息、外部变化与适用范围。

学习应当作为做事的副产品进入下一次工作，不以增加知识页、审批项、技能数或使用计数作为完成判据。哪些经验可以自动保留、哪些须确认，沿现行权限核对后再提出具体选择。

## 建议先验证什么

先选 **一件影响订单/回款或跨部门承诺的经营事项** 作候选。这样一件事可以同时检验公司层面的取舍、进展跟踪与本人注意力。选型仍需比较，不把历史案例的普遍痛点等同于本人的当前急事。

建议采用已标注的模拟或核实过的公开材料，按事件顺序给出：

1. 初始片段与目标，必要信息有缺口。
2. 本人拍板或委托跟踪，保留原判断依据。
3. 一段进展、一个延期或新约束，检查能否接回同一件事。
4. 一条普通更新与一条会改变决定的信号，比较静默、汇总和立即提醒/建议。
5. 完成证据或明确未完成，检查是否还错误催办或虚报闭环。
6. 一件类似事项，含一处改变经验适用性的条件，检验沿用与不照搬。

同材料比较 **现有 assistant 行为** 与 **拟议输出/交互**；其中关键回答再与相同模型、相同材料的普通聊天比较。尽量固定输入、截止时点与预算，不能用给候选更多信息证明其更好。第一轮可做纸面/离线输出比较，具体模型运行与产品验证另按范围确定。

读取结果时至少分开：事实与来源、接续正确性、建议随关键条件变化、漏报/误报/重复、本人所需输入/追问/处理动作、经验适用与撤回。实际耗时与计数运行后才填写。关注阈值、语气和本人是否愿意采用属于需要确认的判断；模拟读数不能证明真实采纳。

[公开案例研究](../_archive/research/positioning/261005-prototype-cases-and-interview-method.md) 原有两例一手正文尚未核齐，不能直接复用为“已验证案例”；可先用其明确标注的变式，并如实保留证据等级。

## 与现有卡片的分工

| 记录 | 继续承载什么 | 本卡如何使用 |
|---|---|---|
| [总助体验卡](261006-chief-of-staff-experience.md) | 默认全局主区入口、完整事项视图/空间层级、事项对话交接与成功读回返回、共同体验判断 | 消费本卡的权威事项/来源/更新语义；不把全部核心价值押在主区布局上 |
| [开屏与节律卡](261007-opening-brief-and-rhythm.md) | 原七项的窄证据及语气/周坐体验判断，三行版式按本轮确认降为假设 | 排程落盘不能代替本卡的主动建议、持续跟踪与注意力价值验证；原证据缺口仍保留 |
| [输入边界卡](261007-input-boundary.md) | 输入通道现在设计或先观察的选择，以及观察准备 | 多 Session 输入已确认，不解除 IM/外部数据限制；home、通道和 30 天选择仍按原卡，不另复制观察账 |
| 本卡 | 一个权威经营账本、多会话并入/来源、持续跟踪、提醒建议与经验迁移如何成为可信过程 | 拥有上述未决机制与后续申请；与总助卡共享的研究继续作为依据，不复制 UI 验收结果 |

旧卡的缺口值得补，但仅补成绿色不足以回答本卡。历史关闭可能是方向明确、切片交付、延后或不做，不一律重新开工；本卡只召回与四项诉求相关且仍未有充分结果证据的内容。

## 用现有方法推进

- [澄清需求](../methods/requirements-elicitation.md)：围绕一个具体事件问清委托、信息、现有做法与期望；只追问会改变范围/判断的缺口，不重做泛 CEO 画像访谈。
- [补充证据](../methods/requirements-probes.md)：同材料原型与条件变式，核实历史结论、反例和输入成本；模拟不冒充本人使用。
- [整理方案](../methods/requirements-synthesis.md)：按用户结果比较真实候选，把未知与延后留下，不先写 slot/工具配方；明确接手处，不能只称“以后持续实践”。
- [验收设计](../methods/validation-design.md) 与 [结果判断](../methods/validation-judgment.md)：分别判断记录/编排是否成立、模型行为是否守约，以及本人是否减少负担、愿意交付真事；不让局部技术绿替代后两层。

本轮先使用已有方法，不新增开发流程、评分体系或运行时技能。方法建议的具体执行还需按其要求加载相应完整技能。

## 方案取舍与当前建议

| 已考虑路线 | 能回答什么 | 主要不足与当前建议 |
|---|---|---|
| 先补现有开屏/周坐七项，再由本人整体终验 | 现有交付是否满足原要求 | 必要，但不能单独验证跟踪、主动判断与学习；作为旧卡收口保留 |
| 先观察 30 天输入习惯 | 本人是否、如何提供碎片 | 是输入卡的候选，不直接检验输出净收益；本卡可先做情景比较，不把 30 天当原型前置 |
| 先扩展数据接入与提醒通道 | 更多事实与触达可能性 | 涉及当前约束，且不能解决什么值得提醒/怎样跟踪/如何学习的未知；本轮不推荐先开此分支 |
| 先验证一条持续工作的完整情景 | 四项诉求能否连成可用过程，现有能力差在哪里 | **当前推荐**。真实采纳仍需以后观察，但可先自主识别机制/输出/输入成本问题，再形成有界方案 |

## 关闭条件

1. 一条代表性过程、目标结果、输入边界和当前未知得到确认，候选比较有依据。
2. 跟踪、提醒与建议、反馈和经验使用的范围与失败/恢复行为明确；本人不可替代的选择有记录。
3. 必要有界研究/原型结论回卡，区分事实、模拟、推断和真人判断；不足的证据不写通过。
4. 如决定做，按现有方法形成可执行验收与必要分步；如延后/不做，记录理由及可观察的重看条件。
5. 所需下游处理申请提交并记录去向后关闭；不等下游实施完成，也不把关闭称为 CEO 价值已验证。

当前未满足。本轮整理的方向与建议供进一步推敲，不授权产品实现。
