# 推敲：把桌面头条规则从渲染里提出来

> 立卡：2026-10-10 ｜ 状态：推敲中 ｜ 类型：Task ｜ 可关闭：否

**问题与期望结果：** `DeskPanel` 里「先办这件」的分拣和「这一行算不算已回答」写在渲染函数的立即执行体中（`src/client/panels.ts` 约 118–168 行）。这条规则已经错过两次：头条取了模型写在最前的内务（rank / kind），以及「看选项」的回执被当成已回答（R2）。期望：规则成为同文件里的具名函数，`DeskPanel` 只负责调用和画；屏幕上的字、按钮、折叠和会话范围与现在相同。

**当前情况：** 分拣是纯计算。经营事项按 `rank` 升序，头条取第一条经营事项；没有经营事项时，取第一条带 `options` 的非经营事项。其余经营事项进「等你决定」。非经营事项进「助手自己的事」，已当头条的那条除外。行 id 是 `id`，缺省用 `question`。已回答只认动作名「回答」：进行中的 pending 是「回答」，或没有进行中且 lastReceipt 是「回答」。`rank` 缺省按 0。现有面板测试已经把这些结果钉在渲染文本上，见下方验收标准。

**未决问题：** 无。范围已收死。不实施，直到用户点名本卡。

**下一步：** 用户点名本卡后，只改 `panels.ts` 里这一处，按「无副作用走法」做。不另写 note：这是局部搬家，没有新的产品取舍。

## 只动这一处

从该立即执行体提出两个函数，留在 `panels.ts`，仅 `DeskPanel` 调用：

1. 分拣：输入决策列表，输出 `lead` / `rest` / `upkeep`。
2. 已回答：输入行 id、当前 pending、lastReceipt，输出布尔。

折叠开关、选项按钮、行的 JSX、以及「在办的事」以下的各个区块留在渲染函数里。

## 不做

- 不把 `desk-io.ts` 的提示词函数收成表。每条已经是一次 `sendPrompt`，文案进会话，碰字符串就是模型可见面变化。
- 不与 `dashboard.ts`、`first-mile.ts` 共用过滤。那两处是「经营或带选项的平铺列表」，没有 rank、没有「头条离开折叠」。合成会改谁出现在首屏。
- 不把面板按区块拆文件，不改账本、工具、门禁，不搬注释，不去重内联样式。
- 不把新函数放进 `src/client/index.ts` 的工厂返回值。注册面由 `client-entry` 整包断言，多一个公开出口就是另一张脸。

## 无副作用走法

从现有断言倒推，不从「文件短一点」倒推。

1. 改代码前先跑验收命令。红了就停：神谕本身不干净，不能拿它当「重构后没变」的证明。
2. 抽出函数后，`DeskPanel` 用它们的返回值走原来的 JSX。文案、按钮标签、`onClick` 指向的函数、折叠文案都不改。
3. 再跑同一条命令。失败表示行为变了：回退这次抽出，不改测试去迁就新结构。
4. 不新增第二套直接单测。渲染文本已经是神谕；再写一套输入输出会和它各说各话。
5. `snapshots/web-face/` 里没有「先办这件」。`pnpm web-expected` 看不见这条规则，不能拿它当本片的通过证明。

## 方案与取舍

提出两个同文件函数，渲染继续拥有 JSX。比较过的做法：按区块拆成多个面板文件（状态仍是同一个 store，测试不会变短）；把提示词收成表（碰模型可见文案）；与主区、首用条共用过滤（合同不同）。三件都不做。
