# 推敲：章鱼管家 K4 收口——本人体验裁决与三处规格/实现差额

> 立卡：2026-10-10 ｜ 状态：推敲中 ｜ 可关闭：否（只剩本人裁决与三处二选一）

**问题与期望结果：** 桌面运营入口（[规格卡](../../notes/proposed/2026-10-06-desk-operating-entry.md)）的 K1–K3 链、K4 确定性面（浏览器端到端探针）与 K1/K2 八项限制补证都已落地或转正（索引见下）。「K3–K4 完整通过」只差四件：**一件必须本人做**（体验裁决），**三件各是二选一**（补切片 or 接受并改规格）。

## 还差什么（唯一清单）

### 1. 本人体验裁决：处理流的话术、层级、确认负担 ← 只有本人能判

走一遍 web 实例：桌面选一件事 → 「处理这件事」 → 在会话里说一句进展或改期 → 观察返回。判的是读起来累不累、层级对不对、要不要反复确认。

**复走时的预期状态（2026-10-11 之后已改，与旧走查记录不同）**：
- 处理会话首屏带**事项上下文**（标题/摘要/「只显示在界面上」提示），不再是新手 intake；
- **混合回合**（助手报告了进展 + 提出待确认的改期）**留在对话**，直到你显式确认/拒绝——不再自动返回；
- 只有「本次提交自己的回执」以不旧于观察修订读回、且事项仍在场，才自动返回，返回后仍选中原事项；
- 桌面只有一个（账本投影）；加事项走「＋ 交代新事项」。

### 2. 交代首事臂没有返回（规格 vs 实现，二选一）

规格 K3 行要求**两侧臂**（「本人交代首事 **或** 选择事项 → 读回 → 返回仍选原事项」），实现只绑了「处理这件事」臂：空桌面从对话交代第一件事时，没有处理路径、也没有返回。

- **补**：让交代流也建立处理路径并读回返回（触及 `processMatter` 的绑定入口与判定器路径，属新切片）。
- **接受**：把规格 K3 行改成单臂并写明理由——推荐倾向：交代是**对话行为**，说到一半被拉回桌面反而打断；「＋ 交代新事项」的回报是那件事出现在桌面上，不必抢焦点。

### 3. 第四种时间是空的（规格 vs 实现，二选一）

规格要求详情保留「**四种时间**」；实现只有三种——承诺（`promisedDeadline`）/预测（`forecastAt`）/核对点（`nextCheckpoint`），且 [`ledger.ts`](../../packages/dsh-smart-assistant/src/domain/operating/ledger.ts) 的注释同样写着「四种」却只列三种。缺的是**完成时间**（V3 里「完成强制随附依据材料」，但账本没有记录完成时刻的字段）。

- **补**：账本加完成时刻（随 completion 写入、可入投影与详情），投影与面板各一处渲染，配套 spec——规格已写明四种，这一侧不改变产品承诺。
- **接受**：把规格的「四种时间」改成三种，并修掉账本里那句不自洽的注释。

### 4. 窄视口「所选消失恢复」未单独取证（一处限制补证）

八项限制补证的第 ④ 项里，只有这个子项没有单独证据：窄视口下所选项从投影消失时的行为（面板已有「所选事项不在当前投影中」态，未在浏览器里单独验过）。补一次 CDP 取证即可（`dev/probes/web/projection-live-mechanics.mjs` 家族）。
