# 推敲：桌面历史视角——账本「做过的事」的呈现（传记/过滤/流水）

> 立卡：2026-10-12 ｜ 状态：推敲中 ｜ 类型：Feature ｜ 可关闭：否

**问题与期望结果：** 本人提出（2026-10-12）：桌面上只呈现「没做的事」（在办＋待认领，盯的视角），**做过的事情没有查回来的手段**，靠对话查既不确定也不免费。期望＝桌面上有确定性的历史呈现面：按事项看它怎么走到今天、按状态筛已了结的、按时间看我做过的所有事。

**当前情况（已核实，2026-10-12）：**
- 历史数据早已全量存在：账本 `operations` 是完整审计流水——每个动作带语义类型（交代/记录进展/确认改期/拒绝提案/认领/办结/放弃）、来源会话、原话引文、时间戳、结果回执；单 writer 权威、跨会话共享。
- 更进一步：这本流水**已经整本投影到客户端**（投影的平铺回执即读回单元），桌面只是没渲染；已办结/已放弃事项也已在列表里（K2 验过「7 在办＋1 完成」夹具），只是与在办混排、被「盯」的编排淹没。
- 结论：**缺的不是数据，是一个呈现视角**——查历史是渲染问题，不是模型问题。DSH 原生面已查：轨迹 panel 与 session-search 的语料是会话日志（聊天记录），跨会话的经营事实在单个会话里看不全——这正是账本存在的理由，账本流水才是「做过的事」的正身。

## 方案与取舍（三个视角，从锚点到全局，cheapest-first）

1. **详情页「流水」段（切片①，每件事的传记）**：详情页现在只显示材料（输入）不显示动作（决策）。加倒序操作流水——人类标签（认领/确认改期/拒绝提案/办结…）＋来源引文＋会话＋时间。数据面＝投影回执补 `kind` 字段（additive；客户端解析器本就透传多余字段，不 bump envelope）。
2. **列表状态过滤（切片②，纯客户端）**：在办 ⇄ 已了结（办结＋放弃）过滤 chips——做完的事不消失也不添乱，一眼切换。
3. **全局「流水」视角（切片③）**：桌面视角切换（在办看板 ⇄ 流水）——全部操作倒序、按天分组，点条目跳转并选中该事项。「查回来」的正身。

**输掉的方案：** ① 用会话轨迹/会话搜索查账本史——语料错位（聊天记录≠经营事实，单会话看不全正是账本存在的理由）；② 服务端全文检索（FTS）——投影已整本在手、量级未到，过度预建；③ 第二份「历史存储」——违反单 writer 原则，历史就是 operations 本身。

## 已知与未决

- 投影回执现无 `kind`（`flattenOutcome` 丢弃了操作语义）——切片①的域层改动点。
- 远期 concern：流水随时间增长会撞投影 byte cap——届时分页，现在不动（触发＝真的撞了）。
- 搜索框延后：客户端过滤在几十件量级足够；量级长大了再谈检索。

## 验收标准

| 切片 | 通过形态 | 会失败的行为 |
|---|---|---|
| ① 投影 kind＋详情流水段 | 投影 spec 断言回执带 kind（先红后绿）；panel spec 断言详情页流水段渲染人类标签＋来源引文＋时间；无模型可见面变更（不改工具/种子/组合行） | 回执无语义标签、流水与材料混排、丢来源引文 |
| ② 状态过滤 | panel spec 断言过滤行为：在办视图隐藏已办结/放弃，切回全部可见 | 已办结事项从桌面消失或无法找回 |
| ③ 全局流水视角 | 探针相位：流水按天倒序渲染、点击条目跳转并选中该事项 | 流水条目不可点、点了不选中 |
