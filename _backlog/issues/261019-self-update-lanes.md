# 推敲：助手怎么更新自己——面板维护面（显性/隐性/自动三条通道）

> 立卡：2026-10-19 ｜ 状态：等人拍板 ｜ 类型：Feature ｜ 可关闭：否 ｜ 毕业：做现在（P0 三片；范围待本人裁）

**问题与期望结果：** 本人问："我们有知识/记忆（这里进入的靠对话？能在 Panel 里面维护吗？）……智能体还需要 SKILL，我们现在还有 Viki……整体如何提高这个助手，显性更新（来自 Panel），隐形更新（来自对话）？" 期望：**面板能读到真值、点完当场生效、看得见最近变了什么**；对话里的隐性学习与 Viki 的自动捕获**看得见来源、管得住**。完成 = 面板三件事都成立，且退役掉造成"点完还要刷新"的那份拷贝。
**当前情况：** 面板除"知识批准"外**每个按钮都只是替人往会话里投一句话**，再由模型改文件、重写房间数据文件；面板读的是那份**拷贝**（`.desk/state.json`），所以连直调成功的批准也要等下一次重写才更新。知识正文在面板里不可见（只有草稿 200 字片段），技能只有一个计数，Viki 的抽取物**没有门也没有面**（旧公司 14 条今天仍在注入面）。事实表、逐动作取证与八条诊断 = 依据档 [261019-self-update-lanes](../research/self-update/261019-self-update-lanes.md)。
**未决问题：** Q1–Q5（下表），都是产品语义或合同变更，agent 不代判。
**下一步：** 本人裁 Q1–Q5 → 裁出 P0 范围后，按本卡「验收标准」立 proposed 卡实施（本卡不授予实施权限）。

## 方案与取舍

排序判据：**先修数据通路，再修门，最后修节拍**——按钮接在拷贝上，怎么改都是错觉。

**P0 = 面板读权威（S1）+ 面板直写（S2）+ 变更收据（S4）**：一次架构改动，模型可见面零变化，风险全在客户端与宿主服务。收益 = 陈旧类 bug 与"刷新"这个动词一起消失。
**P1 = Viki 层 2（S3）**：来源标记（`source: openviking:<id>`）+ 摘要计数行 + 旧数据清理 + 作用域；默认**事后可见**，不事先排队。
**P2 = 技能逐件可见（S5）**：P3 判据的直接欠账，复用 S2 车道。
**P3 = "记下来"（S6）**：消息级显式保存，提升隐性通道的自愿性。
**不做 = 会话收尾自动复盘（S7）**：触发条件未变（需要真实使用数据说明收益 > token 与同意成本）。

已考虑并输掉的：自由 Markdown 编辑器、面板直调模型 API、把 Viki 当唯一记忆、给房间做自动轮询、给 Viki 做逐条删除面、**每条写入事先排队等人批**（外部无人这么做，且与"默认静默"的既有裁决冲突）——逐条理由在依据档 §5.1。

## 验收标准

P0 三片，逐条可执行；下游做成什么样算合格：

| # | 判据 | 断言目标 |
|---|---|---|
| 1 | 面板数据源是房间真值，不是拷贝 | 面板 store 由宿主只读路由供给；`src/` 内对 `.desk/state.json` 的读写**零命中**；`desk-refresh` 技能删除、`docs/home.md` 的家手册节与 `_backlog/triggers.md` 对应行同 diff 退役 |
| 2 | 批准/纠错当场生效 | 组件级 spec：给定数据变更，面板在一轮轮询内换组（待审 → 已确立），**不出现"刷新"按钮**；空态与既有纪律不变 |
| 3 | 直写只做受限动作 | 每个直写方法有白名单校验（id 不存在 / 状态非法 → 拒绝并给可读原因）；负例 spec：尝试"新建"被拒 |
| 4 | 每次直写留痕 | `audit/approvals.jsonl` 追加密钥字段（`source: panel-direct`、动作、目标 id、前后状态）；spec 断言追加不覆盖 |
| 5 | 直调未挂载时降级可见 | 沿用 knowledge-approve 的降级语义：按钮回退指令通道且面板明示，空控制台契约不变 |
| 6 | 收据是纯核 | "自上次以来"由纯核从文件 mtime + 审批账算出（3 案：有新写入 / 无变化 / 只退役）；**不新增任何 `SessionEvent`**（grep 断言） |
| 7 | 收据零成本 | 真机探针（照 `proactive-idle-probe`）：35s 窗口内会话数不变、无模型回合 |
| 8 | 模型面零漂移 | `pnpm eval` 水位不降；家手册若改了房间数据节，`blank-first-open` 基线同 diff 重录并复验 |
| 9 | 收尾 | `pnpm typecheck && pnpm test && pnpm verify` 绿；改了 `src/client` 先 `pnpm build`；`pnpm build && pnpm release-smoke`（动发布物） |

本人的验收面（不代判）：**能不能在面板上看到那页的正文**、**点完是否立刻变**、**"最近变了什么"是否像一句人话**。

## 关闭条件

三片落地且上表 1–9 有真证据（spec 名与探针判决记在本卡或指向的提交说明）；`desk-refresh` 技能与房间数据文件合同同 diff 退役，不留下第二份契约；本人在真机上确认"读到正文、点完生效、看得见变化"三件事成立；结论与去向按 [关闭条件](../README.md#关闭条件) 交接后归档。
