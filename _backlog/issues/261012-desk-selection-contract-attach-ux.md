# 推敲：桌面选择契约——任何 item 选中即有相称动作；认领（Attach）动作的 UX

> 立卡：2026-10-12 ｜ 状态：推敲中 ｜ 类型：Feature ｜ 可关闭：否

**问题与期望结果：** 本人拍板（2026-10-12）：**桌面上的任何一个 item，选中之后必须有相称的处理动作**——按钮语义跟随 item（在办事项＝「处理这件事」，待认领片段＝「认领这件事」），不允许出现「显示了但不可操作」的死胡同项。这是桌面的**选择契约**，约束今后进入桌面的每一种 item。本人同时定性：认领（Attach）动作**完全是 UX 的考量，太重要**——它的会话形态、确认负担与「落在哪」的反馈需要显性推敲，不是实现细节。

**当前情况（已落地）：**
- 事项臂（既有）：选中 → 详情 → 「处理这件事」→ 绑定会话 → 回执读回自动返回仍选原事项。
- 待认领臂（本日落地，commit `5315e3b`）：片段卡可选中 → 详情（原文／来源／归户提示）→ 「认领这件事」→ 绑定认领会话（种子：先与本人确认归属、**未经本人确认不自行归户**）→ 片段离开待认领通道 + 本会话 committed 回执读回 → 自动返回并**选中归属事项**。判定语义：claim 的 committed 回执不携带片段 id，消费信号＝片段离开 unclaimed 通道，关联＝回执的来源会话（与交代首事臂同一可重建模式）。证据：纯核判定矩阵 10 条（包 32/32）、整包 564/564、desk-process-e2e 全链 PASS（事项／交代／双击各臂不受本日重构影响）、`dev/probes/web/projection-claim.mjs` affordance 探针 PASS；另有桌面版式修复 `b046910`（状态 chip 不再读作第二按钮、带时区时间戳本地化渲染、事实降纯文本 meta 行）。
- 输掉的方案（已否决，记录防重提）：① 桌面内联下拉选归属、自动代发指令——把桌面变成写入口、替本人偷发，且归属确认本来就可能需要一问一答，对话不该被跳过；② 只加提示文案教本人去会话说——死胡同依旧，负担没动。

## 已知与未决

- **认领全链浏览器 e2e 已落地（2026-10-12 本轮补齐）**：`desk-process-e2e.mjs --scenario claim` 按回放适配器的会话绑定模型独立成场景（认领臂总建新会话 = 场景里第一个调用会话，按位绑定主脚本）；种子账本增加片段 u-1，回放续段真调 claim。全绿 8 相位：片段选择/详情/按钮 → 认领会话（种子回合吃第一格）→ 指归属 → 真工具消费 u-1（回执 committed）→ 自动返回**选中归属事项**、原文与来源随附到归属事项依据里、待认领通道清空 → 单会话守卫（created:1）。prove-it-red：反转判定器消费检查重建后 `claim-auto-return` 独红，还原复绿。flow 场景 14 相位回归绿。
- **回放对齐的基建教训（记入 replay-adapter.patch.yml 头注）**：session-title-llm 的标题调用与 agent 回合走同一 llm 服务、同一 sessionId，会按位吃掉该会话脚本的下一格——flow 场景此前只是「粘贴快过标题调用」的竞速侥幸。patch 现已禁用该行（标题走 fallback），对齐成为确定性。
- **Attach UX 未推敲**：认领会话第一步该做什么（先 `assistant_operating desk` 列候选，还是直接问）；认领成功后桌面要不要比「返回后选中归属事项」更强的「落在哪」反馈（e2e 已证当前形态：返回即选中归属事项、原文在依据里可见）；多条片段的批量处理；「是噪音、不归户」在账本动作清单里没有出口（缺口归账本 owner，不混入本卡实现）。
- **派发/指派（本人 2026-10-12 提出后当场撤回）**：本产品里派发＝对助手下指令（都是自己给自己），不构成独立动作；账本 `responsible` 通道本来就在 entrust/revise 里，将来真出现「交办给他人」的场景再议。记录防重提。
- **未来 item 类型未受契约检验**：提案（等你确认）目前是事项详情内的属性、不可独立选中；提醒通道（V4/V5）落地时是否成为独立 item、各配什么动作——按选择契约逐类裁决。
