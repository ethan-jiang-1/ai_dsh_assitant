## 写一张卡

两轨的入场票只有一张，在 [入口](../README.md#入场票)：问题清楚 + 验收手段——本目录的半张是 `## 验收标准`，缺了就不算立起来。

文件名为 `YYMMDD-<slug>.md`。开头先让下一位读者知道：解决什么、现在什么情况、还缺什么、下一步是什么。讨论中的事实、假设和建议分别写清，历史推演放在当前情况之后。

新卡参考下面的骨架；简单问题可以简写。`Feature` 表示可观察行为会变，`Task` 表示要交出代码、文档、配置或结论；还分不清就写 `未定`，旧卡不回填类型。

```markdown
---
status: 推敲中
opened: YYYY-MM-DD
---

# 推敲：<标题>

> 立卡：YYYY-MM-DD ｜ 状态：推敲中 ｜ 类型：未定 ｜ 可关闭：否 ｜ 毕业：未定

**问题与期望结果：** 什么情况引出问题，用户应得到什么，怎么算完成。
**当前情况：** 已经确定什么。
**未决问题：** 还缺什么事实或选择。
**下一步：** 谁来做什么，或等待什么具体条件。

## 已知与未决

## 方案与取舍

## 关闭条件
```

决定做的事项，按 [验收设计](../methods/validation-design.md) 在同卡加 `## 验收标准`，可以是短清单或表格。它描述下游做成什么样算合格；backlog 关闭不要求这些未来检查已执行，但 `待落地` 前必须非空。

`待落地` 的头部形状（`去向` 值见 [AGENTS](../AGENTS.md)，note 写入时机见 [`notes/AGENTS.md`](../../notes/AGENTS.md)）：

```markdown
> 立卡：YYYY-MM-DD ｜ 状态：待落地 ｜ 毕业：做现在 ｜ 去向：implemented ｜ 可关闭：否
```

## 收口卡

问题卡的一种**用途**，不是新卡型：**`待落地` 卡的 work 台账**。授权后，切片推进、停点、证据缺口、开放验收和未取的人判断都住这里（授权事实记在 proposed 卡状态行；本轮点名时在卡上记一句来源；proposed 卡只指针到本卡，不复制台账）。`## 验收标准` 按入场票写全，各片真证据记在卡上或其链接的提交说明，验收与 `审查：` 完成后按[关闭条件](../README.md#关闭条件)归档。`审查：` 与 `去向：` 的字段形状自 2026-11-02 起生效；更早归档的卡按其时规则，不回填。`待落地` 覆盖整个落地期；`## 切片台账` 是证据表，不是第二状态——不要为它新增 `落地中`/`待复核`。规格卡（部署/运行态/检索等）是**规格**，不单独授权、不持有台账；它们指向本卡。先例：[261102 首屏收口卡](../_archive/settled_issues/261102-first-screen.md)（外部结果三要素 / 验收标准 / 切片台账 / 仍未取 / 审查三层齐全）。**落笔形状**：外部结果三要素（触发 / 用户得到 / 完成条件）打头，节名 `## 外部结果三要素`；切片推进与证据住 `## 切片台账`（片 × 状态 × 证据表）；开放项住 `## 仍未取`（人判断/延后验收；note 只留指针）。

## 评审卡

问题卡的另一种**用途**，不是新卡型：**重大路线裁决前的分角色评审台**。要决定什么、主张与证据强度、请谁攻击哪几条住卡上；评审意见的家是卡内「评审记录」节（按角色小节追加），K 表「现状」列随结论翻 `已证 / 证伪 / 维持`；评审卡不承载实施（实施住 proposed 卡或收口卡），其验收＝评审收敛 + 一次路线裁决。先例：[主动性方向评审卡](../_archive/settled_issues/261018-proactive-direction.md)。

## 关闭或叫停

按 [入口的关闭条件](../README.md#关闭条件) 检查。需要后续处理的，按结论路由到 work（proposed/收口卡）或 memory（note/trigger）；卡上记录结论、`毕业`、`去向` 与审查/跳过。满足条件后，头部写 `可关闭：是` 并在同次改动中归档，不留在活跃清单；卡与去向载体同变更。

- 有结论：用 `git mv` 进 [settled_issues](../_archive/settled_issues/README.md)，`status` 改为 `已结`，状态行补结论、审查与去向。
- 被用户明确叫停、尚无结论：进 [suspended_issues](../_archive/suspended_issues/README.md)，`status` 改为 `叫停`。重新讨论需要用户明确的新决定。

搬迁保留文件名和讨论正文，修相对链接，更新两边清单。`pnpm verify` 检查清单、frontmatter，以及已声明可以关闭却仍留在活跃区的卡；旧字段保持兼容。

## 状态怎么翻

frontmatter `status` 是当前阶段的唯一家；状态行镜像它（引导词 `状态：`）并拥有历史——结论追加、出口补结论与去向。翻转表：

| From | 守卫 | To | 谁 |
|---|---|---|---|
| （开卡） | 分诊后——确认是问题、选对目录 | 推敲中 | agent |
| 推敲中 | 下一步是本人的选择 | 等人拍板 | agent（`下一步` 点名确切问题；仅本人可判时 🔒） |
| 等人拍板 | 本人明确答复 | 回等待前状态，或出口 | 仅本人 |
| 推敲中 | 结论=做现在：`毕业：做现在` + 非空 `## 验收标准` + `去向` + 方案与取舍；**不是授权** | 待落地 | agent |
| 推敲中 | 结论=以后做/不做/已在别处：`去向` 已记 | 已结（同改动归档） | agent |
| 待落地 | 方案/前提被证伪 | 推敲中（把证据留在卡上） | agent |
| 待落地 | 审查/跳过已记 + 业务验收（如需）+ 去向载体成立 + `可关闭：是` | 已结（同改动归档） | agent |
| 待落地 | 下一步是本人的选择 | 等人拍板 | agent（🔒 仅本人可判时） |
| 任意活跃值 | 本人叫停、无结论 | 叫停（归档） | 仅本人 |
| 叫停 | 本人明确复活 | 推敲中 | 仅本人 |
| 已结 | 永不重开——复发＝引用旧卡开新卡 | — | — |

沉默不翻转；出口值只在归档的那次改动里翻；「可关闭：是」与搬迁同落（见[关闭或叫停](#关闭或叫停)）。共享翻转法在[入口 README](../README.md#卡的生命周期)。

状态行可带「毕业：」倾向字段——头必须是闭集 `未定 | 做现在 | 以后做 | 不做 | 已在别处`（四门即[关闭表](../README.md#关闭条件)那四行），自由文字跟在头后。它是倾向不是阶段：不写不算错，写了头就不许跑出闭集；历史卡上的 `毕业门判断` 旧字段保持兼容，不回填。`去向：` 在 `待落地` 写值；`审查：agent / user / 跳过` 在出口前记；三者都住状态行，不另开字段。

## frontmatter

新卡第一行是 `---`，字段按下面顺序：

```yaml
---
status: 推敲中
opened: YYYY-MM-DD
---
```

| 字段 | 内容 |
|---|---|
| `status` | 活跃值：`推敲中` / `待落地` / `等人拍板`。`待落地` 只用于 `毕业：做现在`，表示准备进开发，不授权；旧卡已实施但验收未完成的按 `待落地` 处理，不新增 `落地中`/`待复核`。翻转守卫见[状态怎么翻](#状态怎么翻) |
| `opened` | 立卡日，与正文一致 |

离开目录时只改 frontmatter 的 `status`，其他字段保留。不把正文长说明复制进 frontmatter。

## 🔒 只有用户能判定触发

状态行带 🔒 的卡，agent 只报告和建议，不自行判定触发、删卡或实施。
